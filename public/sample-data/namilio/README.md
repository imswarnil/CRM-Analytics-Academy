# The Namilio warehouse

A fictional company's GTM data, built for the CRM Analytics Academy GTM modules.
Everything here is generated by `scripts/gen-namilio-dataset.mjs` from one seed,
so the relationships between files hold exactly. Regenerate with:

```bash
node scripts/gen-namilio-dataset.mjs            # same bytes every time
node scripts/gen-namilio-dataset.mjs --scale=3  # a bigger warehouse
```

## The company

**Namilio** sells AI infrastructure: voice agents, a messaging API, an LLM
copilot endpoint, phone verification, and a seat-priced studio. It is shaped
like the companies a GTM engineer actually supports — Twilio's usage billing,
Stripe's self-serve-to-enterprise ladder, Anthropic's metered API — because the
analytics problems that shape creates are the point of the curriculum.

Three revenue models sit side by side, and that is deliberate:

| Model | Products | Why it complicates analytics |
| --- | --- | --- |
| **Usage** | Voice Agents, Messaging, Copilot, Verify | Revenue is re-earned daily. A customer can grow or shrink 40% with no sales involvement. |
| **Seat** | Studio | Renews on a date. Classic ARR. |
| **Platform** | Connect Enterprise | A flat fee that is neither, and breaks any "per unit" metric. |

Five segments — Self-Serve, SMB, Mid-Market, Enterprise, Strategic — drive ARR
band, sales cycle, and whether a human is ever involved.

## The files

**Dimensions** — small, stable, joined to by everything else.

| File | Grain | Notes |
| --- | --- | --- |
| `accounts.csv` | one row per account | Segment, Motion, Region, ARR, HealthScore, SupportTier |
| `contacts.csv` | one row per contact | Persona, `IsEconomicBuyer`, `IsChampion` |
| `products.csv` | one row per product | PricingModel, Unit, list price, margin |
| `reps.csv` | one row per rep | Role (AE/SDR/BDR/SE/CSM), quota, `RampStatus` |

**Marketing and demand.**

| File | Grain | Notes |
| --- | --- | --- |
| `campaigns.csv` | one row per campaign | Spend + aggregates **computed from** the lead and opp rows |
| `marketing_spend.csv` | month × channel × region | Finance's grain, deliberately different from campaigns |
| `web_sessions.csv` | day × channel × landing page | GA4 vocabulary. `AI Assistant` is a first-class channel |
| `seo_keywords.csv` | week × keyword | Position, CTR, and `InAIOverview` |
| `llm_visibility.csv` | month × engine × prompt × run | GEO. 5 runs per prompt, so Share of Voice has a denominator |

**Pipeline.**

| File | Grain | Notes |
| --- | --- | --- |
| `leads.csv` | one row per lead | Separate `MQLDate`/`SQLDate`/`ConvertedDate` — stage history, not just status |
| `opportunities.csv` | one row per opportunity | Type (New/Expansion/Upsell/Renewal), `POCCompleted`, `SecurityReviewDays` |
| `opportunity_products.csv` | opportunity × product | ARR **sums exactly** to the opportunity's ARR |
| `quotes.csv` | opportunity × version | CPQ. Superseded versions kept, approval chain and days recorded |

**Post-sale.**

| File | Grain | Notes |
| --- | --- | --- |
| `usage_monthly.csv` | month × account × product | Committed vs used, overage, `CommitState` |
| `platform_health_daily.csv` | day × product | Errors, p95 latency, incidents — the "was it us?" table |
| `cases.csv` | one row per case | SLA target vs actual, `DeflectedByAI`, root cause |
| `csat_surveys.csv` | one row per response | CSAT 1–5 and NPS 0–10, kept separate on purpose |
| `arr_snapshots.csv` | month × account | The revenue waterfall: New / Expansion / Contraction / Churn |

## What reconciles

These hold by construction. The generator prints a check for each one, and the
recipes in the curriculum rebuild them by hand:

- a campaign's `Leads` equals the rows in `leads.csv` naming that campaign
- an opportunity's `ARR` equals the sum of its `opportunity_products` rows
- `usage_monthly` only bills a product the account has a closed-won line for
- `arr_snapshots` movements line up with opportunity close dates

`manifest.json` carries exact row and column counts plus the seed.
