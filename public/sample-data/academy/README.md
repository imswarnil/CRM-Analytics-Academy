# The CRM Analytics Academy warehouse

The Academy's own business data, built as the worked example for every build in
the course. Everything here is generated by `scripts/gen-academy-dataset.mjs`
from one seed, so the relationships between files hold exactly. Regenerate with:

```bash
node scripts/gen-academy-dataset.mjs            # same bytes every time
node scripts/gen-academy-dataset.mjs --scale=3  # a bigger warehouse
```

## The company

**CRM Analytics Academy** teaches Salesforce CRM Analytics. It sells to
individual learners (Academy Pro), to company teams upskilling their admins and
analysts (Team Plan, Enterprise Programmes), runs classroom batches at six
training centers, sells certification vouchers, and takes on implementation
projects. The data is synthetic; the shape is the shape of a real training
business.

Three revenue models sit side by side, and that is deliberate:

| Model | Offerings | Why it complicates analytics |
| --- | --- | --- |
| **Seat** | Academy Pro, Team Plan | Renews on a date. Classic ARR — but only if the seats are actually used. |
| **Prepaid pool** | Classroom Seat-Days, Certification Vouchers, Implementation Services | Bought up front, drawn down over the year. Unused pools do not renew. |
| **Platform** | Enterprise Programme | A flat annual fee that breaks any "per seat" metric. |

And one that is not recurring at all: **classroom batches** (`batches.csv`,
`enrollments.csv`) are one-off revenue with a fixed-cost room behind them. None of
it appears in `arr_snapshots.csv`, which is the point.

Five segments — Self-Serve, SMB, Mid-Market, Enterprise, Strategic — drive ARR
band, sales cycle, and whether a human is ever involved.

## The files

**Dimensions** — small, stable, joined to by everything else.

| File | Grain | Notes |
| --- | --- | --- |
| `accounts.csv` | one row per account | Segment, Motion, Region, ARR, HealthScore, SupportTier |
| `contacts.csv` | one row per contact | Persona (Individual Learner … L&D Manager), `IsEconomicBuyer` |
| `products.csv` | one row per offering | PricingModel, Unit, list price, margin |
| `reps.csv` | one row per rep | Role (AE/SDR/BDR/SC/CSM), quota, `RampStatus` |
| `centers.csv` | one row per training center | Seats, monthly fixed cost, region |

**Marketing and demand.**

| File | Grain | Notes |
| --- | --- | --- |
| `campaigns.csv` | one row per campaign | Spend + aggregates **computed from** the lead and opp rows |
| `marketing_spend.csv` | month × channel × region | Finance's grain, deliberately different from campaigns |
| `web_sessions.csv` | day × channel × landing page | GA4 vocabulary. `AI Assistant` is a first-class channel |
| `seo_keywords.csv` | week × keyword | Position, CTR, and `InAIOverview` |
| `llm_visibility.csv` | month × engine × prompt × run | 5 runs per prompt, so Share of Voice has a denominator |

**Pipeline.**

| File | Grain | Notes |
| --- | --- | --- |
| `leads.csv` | one row per lead | Separate `MQLDate`/`SQLDate`/`ConvertedDate`; `StartedFreeCourse` |
| `opportunities.csv` | one row per opportunity | Type (New/Expansion/Upsell/Renewal), `PilotCompleted`, `SecurityReviewDays` |
| `opportunity_products.csv` | opportunity × offering | ARR **sums exactly** to the opportunity's ARR |
| `quotes.csv` | opportunity × version | CPQ. Superseded versions kept, approval chain and days recorded |

**Post-sale.**

| File | Grain | Notes |
| --- | --- | --- |
| `usage_monthly.csv` | month × account × offering | Seats or pool bought vs used, `UtilizationPct`, `CommitState` |
| `platform_health_daily.csv` | day × offering | Errors, p95 latency, incidents — the "was it us?" table |
| `cases.csv` | one row per case | SLA target vs actual, `DeflectedByAI` (the Ask AI tutor), root cause |
| `csat_surveys.csv` | one row per response | CSAT 1–5 and NPS 0–10, kept separate on purpose |
| `arr_snapshots.csv` | month × account | The revenue waterfall: New / Expansion / Contraction / Churn |

**Classroom.**

| File | Grain | Notes |
| --- | --- | --- |
| `batches.csv` | one row per batch | Center, programme, capacity, seats sold, `UtilizationPct`, revenue |
| `enrollments.csv` | one row per seat | Individual or corporate, price paid, attended, completed, certified |

## What reconciles

These hold by construction. The generator prints a check for each one:

- a campaign's `Leads` equals the rows in `leads.csv` naming that campaign
- an opportunity's `ARR` equals the sum of its `opportunity_products` rows
- a batch's `SeatsSold` equals its rows in `enrollments.csv`
- `usage_monthly` only draws down an offering the account has a closed-won line for
- `arr_snapshots` movements line up with opportunity close dates

`manifest.json` carries exact row and column counts plus the seed.
