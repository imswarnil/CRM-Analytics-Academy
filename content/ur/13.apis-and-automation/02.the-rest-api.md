## ورژن

فارغین راستے میں ایک ورژن لے جاتے ہیں۔ پینین.

::note{icon="i-lucide-pin"}
**ایک قلمی نسخہ ہے جو پلیٹ فارم اپ ڈیٹ کرنے کے دوران کام کرتا رہتا ہے اور ایک غیر معلوم شدہ تحریر ہے جو کسی اور شخص کو منتخب کیا جاتا ہے** دوبارہ تجدید: نسخے کو تبدیل کرنا، ریتلے بکس کے خلاف چلانا، جواب کی شکل کی تصدیق کرنا کہ آپ کیا توقع کرتے ہیں، پھر جہاز میں۔ یہ دو منٹ کی ایک ایسی عادت ہے جس میں ناکامی کی کلاس کو روکا جاتا ہے جہاں آپ کی خانقاہ میں کوئی تبدیلی نہیں آئی اور یہ کام بہرحال ٹوٹ گیا۔
::

## چاروں طرف ڈیزائن کرنا

ہر پلیٹ فارم کے پاس ان کے اور مخصوص اعداد و شمار متحرک ہوتے ہیں، لہٰذا غیر مستحکم مشورے اعداد کی بجائے شکل کے بارے میں ہیں:

::compare-cols
---
items:
  - title: "وہ انداز"
    subtitle: "Work with the limits"
    icon: "i-lucide-check"
    pros:
      - "Batch — one call with many rows rather than many calls with one"
      - "Incremental — send what changed, not everything, every night"
      - "Back off and retry on a rate-limit response rather than hammering"
      - "Check the current limits for your edition before sizing anything"
    cons:
      - "More code than the naive version"
    verdict: "Write it this way from the start."
  - title: "ایسے شاپ جو پیمانے پر ناکام ہو جاتے ہیں۔"
    subtitle: "Fine in a test, not in production"
    icon: "i-lucide-x"
    pros:
      - "Simple, and works beautifully against 100 rows"
    cons:
      - "A call per row exhausts the daily allowance and starves everything else in the org"
      - "A full reload every night when 2% of rows changed"
      - "No retry, so one transient error loses the whole run"
    verdict: "This is how an analytics job takes down an org's API budget."
---
::

::warning{icon="i-lucide-gauge"}
**API حدیثیں یاگ کثرت سے ہیں۔** لالچی اناطولیہ ملازمت نہ صرف اپنے آپ کو سستا بنا لیتا ہے بلکہ اس سے یہ نتیجہ اخذ کر لیتا ہے کہ موبائل کمشنروں اور دیگر ٹیموں کو بھی متاثر کر رہی ہے ۔ اِس کی وجہ یہ ہے کہ اُن لوگوں کے لیے جو آپ کے ہم‌عمروں کی بات نہیں سنتے تھے ۔
::
