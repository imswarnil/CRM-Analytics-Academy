# Joins in Depth

Most wrong numbers in CRM Analytics come from one node.

## The six join types

| Type | Keeps | Rows change? | Use it for |
|---|---|---|---|
| **Lookup** | All left; one match | Never | Adding parent attributes (Account → Opportunity) |
| **Left** | All left; every match | Yes, per match | Moving to the child grain |
| **Right** | All right | Yes | Rare: swap the inputs instead |
| **Inner** | Matches only | Yes | Keeping only rows that match |
| **Outer** | Everything | Yes | Finding what doesn't match |
| **Cross** | Every pair | Multiplies | Small scaffolds (months × regions) |

## Fan-out

```text
OPP-1  Amount 30,000  ⟶  OPP-1 · Vouchers   30,000
                          OPP-1 · Classroom  30,000   ← same amount, three times
                          OPP-1 · Seats      30,000
```

**Fix 1:** sum the measure that belongs to the grain (line `ARR`, not `Amount`).
**Fix 2:** aggregate the many-side to one row per key, *then* join.

## Key rules

- Join on **Ids**, never names
- Same **type and length** on both sides (15 vs 18-character Ids don't match)
- Check the "one" side really is **unique**

::warning
Write down the row count and the total of your main measure before and after every join. A change you didn't expect is a bug.
::
