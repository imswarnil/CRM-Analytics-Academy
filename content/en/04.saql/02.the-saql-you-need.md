interview:
  - q: "How does SAQL differ from SQL?"
    a: "SAQL is a sequence of statements, each transforming a named stream (q = load; q = filter q; …), rather than one declarative SELECT. Grouping and projection are separate steps (group, then foreach generate). Joins are done with cogroup, and it runs against indexed datasets, not tables."
  - q: "When do you write SAQL by hand rather than clicking?"
    a: "For windowing, cogroup across datasets, case logic, time series, and anything the builder can't express. I start from a clicked query in SAQL mode and edit it."

# The SAQL You Need

Six keywords, one idea: statements flow top to bottom.

::lesson-hero{figure="dashboard"}
---
points:
  - "Open any query in SAQL mode"
  - "Read a query statement by statement"
  - "Write load, filter, group, foreach, order, limit"
  - "Filter by date ranges"
---
::

```sql
q = load "academy_opportunities";
q = filter q by 'IsWon' == "true";
q = group q by 'Region';
q = foreach q generate 'Region' as 'Region', sum('Amount') as 'Won';
q = order q by 'Won' desc;
q = limit q 10;
```

| Keyword | Does |
|---|---|
| `load` | Reads a dataset |
| `filter` | Keeps matching rows |
| `group` | Bundles rows (no maths yet) |
| `foreach … generate` | Builds the output columns |
| `order` / `limit` | Sorts, keeps the top N |

**Quotes:** `'Field'` single, `"value"` double.

```sql
q = filter q by date('CloseDate_Year', 'CloseDate_Month', 'CloseDate_Day')
    in ["current fiscal_quarter".."current fiscal_quarter"];
```
