# The Vocabulary

Precise definitions. Most early confusion in CRM Analytics is a vocabulary problem wearing a concept problem's clothes — and in an interview, using these words loosely is the fastest way to sound like you have only read about the product.

## The data things

**Connection** — credentials plus an endpoint. Where external data comes from.

**Data sync** (older material says *replication*) — the scheduled pull of selected objects and fields into CRM Analytics' own store, so recipes read a local copy.

**Recipe** — the visual transformation pipeline. Input nodes, then joins, filters, formulas, aggregates, and an output. The current tool for building datasets.

**Dataflow** — the predecessor to recipes, defined in JSON. Legacy, still running in older orgs, worth being able to read.

**Dataset** — the materialised, columnar result. What lenses and dashboards read.

::note{icon="i-lucide-git-compare"}
**Recipe vs dataset, since they are constantly confused.** The recipe is the *instructions*; the dataset is the *output*. Editing a recipe changes nothing until it runs. Deleting a dataset does not delete the recipe that built it. A dataset with no recipe behind it was loaded from a CSV and will never update itself.
::

## The design things

**Lens** — one exploration of one dataset: a grouping, a measure, a chart. Disposable by default, saveable if it is worth keeping. This is your workspace, meant to be thrown away twenty times an hour.

**Dashboard** — an assembled screen: many widgets, fed by named queries, faceted together, built for other people to use.

**Widget** — one element on a dashboard. A chart, a number, a table, a filter, an image, a block of text.

**Query** — the actual request behind a widget. Several widgets can share one query, which is the main lever on dashboard performance.

**Faceting** — the behaviour where interacting with one widget filters the others. On by default between widgets sharing a dataset, and controllable per widget. Section 5 treats it as a design decision rather than a setting, because a dashboard where everything facets everything is unusable in a different way than one where nothing does.

**Binding** — one widget's state feeding another's query. The mechanism behind dynamic titles, dependent filters and dashboards that reconfigure themselves. Powerful, and the place dashboards become unmaintainable if you are not disciplined.

**Explorer** — the mode you are in when working inside a lens. Chart, Table and SAQL are its three views of the same exploration.

**SAQL** — Salesforce Analytics Query Language, the stream-transformation language your clicks generate. Not SQL: statement order is the query plan, and that difference catches out people who know SQL well.

## The intelligence things

items:
  - title: "Story"
    subtitle: "The analysis"
    icon: "i-lucide-search"
    pros:
      - "What correlates with an outcome, and how strongly"
      - "Directional, explanatory, readable"
      - "Produces no scores by itself"
    cons:
      - "Correlation, not causation — it will say so, and people will forget"
    verdict: "Run one to understand. It is an investigation."
  - title: "Model"
    subtitle: "The deployment"
    icon: "i-lucide-cpu"
    pros:
      - "Scores records and writes back to Salesforce"
      - "Carries prediction plus top factors"
      - "Shows up where the work happens"
    cons:
      - "Needs monitoring — accuracy decays as the business changes"
      - "A score without its factors gets ignored within a month"
    verdict: "Deploy one to act. It is a commitment."
