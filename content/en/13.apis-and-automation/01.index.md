# Analytics You Can Automate

Datasets, queries, dashboards and metadata are all reachable programmatically. That turns a set of manual chores into scheduled jobs, and it turns dashboards into something that can be generated rather than hand-built.

::note{icon="i-lucide-shield-check"}
**The API is not a way around the security model.** Requests authenticate as a user, and that user's permission sets, sharing and row-level security apply exactly as they do in the interface. A script run as an integration account sees what that account can see — which is the correct behaviour and worth stating plainly, because "just use the API" is occasionally offered as a workaround for an access problem. It is not one.
::

## What should stay manual

::warning{icon="i-lucide-hand"}
**Automating a thing you do twice a year is a liability.** The script rots, its credentials expire, and the person who wrote it has forgotten it by the time it next runs — so the annual task becomes "debug a script nobody has looked at in twelve months" instead of "spend an hour clicking". Automate what happens weekly or more often, or what must be identical every time. Everything else is cheaper by hand.
::

Design work is the other category. A dashboard's layout, its refusals and its titles are judgement, and generating them from a template produces forty screens that are consistently mediocre rather than one that is right.

::tip{icon="i-lucide-shield"}
**Before the first script: a dedicated integration user, with narrow permissions, and credentials in a secret store.** Not a person's account, not a token pasted in a notebook. Every automation section in every product says this and it is ignored often enough to be worth repeating — the cost lands when somebody leaves and their account is deactivated.
::
