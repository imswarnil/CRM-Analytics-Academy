# Embedding

The cheapest way to make analytics used is to remove the decision to go and look at them.

## The Analytics tab

The same content inside Lightning Experience, beside the tabs people already use. Same data, same permissions, different door — and for an audience that consumes rather than builds, it is the correct door.

::note{icon="i-lucide-door-open"}
**Design for the tab, not for Studio.** You will build in Analytics Studio, which is full-screen and spacious. Your audience will open the same dashboard in the Analytics tab, inside the Lightning shell, with less room and a navigation bar above it. Check it there before shipping — a layout that is comfortable in Studio can be cramped in the place it will actually be used.
::

## On a record page

A dashboard component on an account or opportunity page, filtered to that record. This is the strongest placement available, because the person is already there for another reason.

## Filter it to the record

An embedded dashboard that shows company-wide numbers on an account page is worse than no dashboard: it looks like it is about this account and it is not. Pass the record's id into the dashboard so it scopes itself, and put the scope in the title — the same screenshot discipline from the collaboration section, for the same reason.

## The discipline embedding needs

::lesson-steps
---
items:
  - title: "Keep it to two or three widgets"
    description: "A component is glanced at, not explored. The headline, one trend, and at most one short list — anything more competes with the record page itself."
  - title: "Watch the load budget"
    description: "The record page has its own performance ceiling and users blame the page, not the component. An embedded dashboard that adds three seconds to every account page will be removed by someone who never tells you why."
  - title: "Respect the security model"
    description: "Row-level security still applies, so a user may see a component with no data. Give it an empty state — on a record page, a blank panel reads as a broken page rather than as an honest absence."
  - title: "Decide who owns the page"
    description: "The record page belongs to whoever administers Lightning, and the dashboard belongs to you. Agree before shipping, or the component quietly disappears in someone else's page redesign."
---
::

::tip{icon="i-lucide-target"}
**Embedding is where adoption actually comes from.** A standalone dashboard competes with every other thing in someone's day and loses most days. A component on a page they open anyway costs them nothing — and it is the reason CRM Analytics' position inside the CRM is a real advantage rather than a marketing line.
::
