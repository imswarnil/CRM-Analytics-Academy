interview:
  - q: "What is a lens in CRM Analytics, and how is it different from a dashboard?"
    a: "A lens is a single query against a single dataset, plus the visualization of its result. It's the exploration surface — you click to change measures, groupings, and filters, and every click rewrites the underlying SAQL. A dashboard is a composed page of multiple widgets that can span several datasets, with bindings and interactivity between them. Practically, I use a lens to explore and validate, then clip the result onto a dashboard once the query is right."
  - q: "A sales team says they can't find Analytics. What do you do?"
    a: "Two separate things to check. First, access: do they have the CRM Analytics permission set license, and has the app containing the assets been shared with them? Second, navigation: by default the only route in is the App Launcher, which drops them out of the Sales app. I'd add the Analytics navigation item to their Lightning app and reorder it high enough to be visible, so Analytics Studio loads inside the app they already use. Adding the tab is navigation only — it doesn't grant any access on its own."
  - q: "How does sharing work in CRM Analytics? Walk me through the model."
    a: "You share the app, not individual assets. An app is a container for dashboards, lenses, datasets, and stories, and the grant flows down to everything inside it. From the app's Share button you grant access to users, public groups, or Salesforce roles, at Viewer, Editor, or Manager level. Groups are usually the right default because membership is managed once in Setup. Crucially, this is asset-level access — it controls what a user can open, not which rows they see. Row-level visibility is a separate concern handled by sharing inheritance or a security predicate on the dataset."
  - q: "Why does work often end up stuck in My Private App, and how do you avoid it?"
    a: "Because it's the default save location, and it's genuinely private — nobody else can see it, including admins. People prototype there, then discover nobody can access their dashboard. The habit that fixes it is creating the destination app before you start building, so assets are saved into the right place from the first save. Moving a pile of assets afterwards and re-pointing everything is far more work than it sounds."
  - q: "Someone asks for the top ten accounts by revenue in a lens. What do you actually configure?"
    a: "Three things, and people often forget one. Set the measure to sum of amount, group by account name, then set the sort to descending on that measure and set the query limit to ten. The limit alone gives you ten arbitrary groups — it's the sort that makes them the top ten. Ascending sort with the same limit gives you the bottom ten. I'd also add a relative date filter, like current fiscal year, rather than a fixed range, so the lens stays correct next quarter."
  - q: "When would you use a trellis instead of a stacked bar chart?"
    a: "When I'm comparing patterns rather than totals. A stacked bar tells you which region is biggest and roughly how the stages split. A trellis gives you one small chart per region, so you can see whether each region's stage distribution has the same shape. That's a different question, and trellis answers it far better because each small chart has its own consistent layout instead of segments of different sizes competing on one axis."
  - q: "Explain the difference between a values table, a compare table, and a pivot table."
    a: "A values table shows raw, unaggregated rows — it's my main debugging tool, because if a total looks doubled I can filter to one account and count the rows to spot a fan-out join. A compare table is the aggregated spreadsheet view with groupings down the left and measures across the top, and its key feature is the formula editor for derived columns like win rate, variance to target, or percent of total. A pivot table crosses two dimensions with a measure in the cells — the classic cross-tab you reach for when someone says they want it like Excel."
  - q: "When do you drop into SAQL, and what's the catch?"
    a: "I click as far as the UI will take me first, then go to advanced mode for the last mile — multi-step queries, cogroup, windowing for running totals and rank, case statements for custom bucketing, or computed measures inside the foreach. The catch is that hand-editing is effectively a one-way door for that lens: the visual explorer can't round-trip the edited query, so you stay in SAQL from then on. That's why I do all the point-and-click work before touching the editor."
  - q: "What does the Fields panel in a lens actually change, and why is that a big deal?"
    a: "It edits the dataset's metadata, not the lens. Anything you save there applies to the dataset everywhere — every existing lens, dashboard, and story, for every user. You use it to set the default columns for the values table, relabel dimensions from things like AccountId.Name to Account Name, assign fixed colors to dimension values, and format measures with a currency symbol and sensible decimal places. It's a big deal because one curation pass makes every downstream dashboard look finished, and because a careless edit propagates just as widely. It requires Manage Analytics or Edit Dataflows."
  - q: "A colleague renamed a dimension value in the Fields panel and now a SAQL filter returns nothing. What happened?"
    a: "Renaming in the Fields panel changes the display label only — the stored value is untouched. So a chart may read 'Enterprise' while the underlying value is still 'ENT', and a SAQL filter written against the label matches nothing. The same applies to relabelled fields: the API name is unchanged, so SAQL and advanced mode still use the original. The rule I follow is to change labels in the Fields panel but change actual values at the data layer, with a bucket or transformation in the recipe or dataflow, so stored and displayed values agree."
  - q: "Why does assigning colors at the dataset level matter more than styling each chart?"
    a: "Consistency and cost. Set Closed Won to green and Closed Lost to red once against the Stage dimension, and every chart grouped by Stage in every dashboard inherits it — including charts generated by Conversational Analytics. Styling per chart means re-picking colors every time and inevitably ending up with the same value in different colors on different pages, which quietly erodes trust in the dashboards."
  - q: "What is Conversational Analytics and where does it fit in your workflow?"
    a: "It's natural-language querying, enabled in Setup under Analytics Settings. You type something like 'amount by industry' — measure first, then by and the dimension — and it builds the lens for you, including a second dimension if you layer one on. It respects the dataset metadata, so your labels, currency formats, and value colors carry through. I use it as an accelerator for quick questions and as an on-ramp for non-technical users, then take over in Explorer mode for anything needing precise filters, derived formulas, or multi-step logic. It's notably better when fields have been relabelled, because people ask for 'Account Name', not AccountId.Name."
