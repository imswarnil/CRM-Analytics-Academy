# Widgets and Layouts

A widget is *what* is drawn. A layout is *where it sits*. Keeping them apart is what lets one widget be positioned differently on a wide screen and a phone — and it is why a positioning problem is never in the widget.

## Widgets

Each widget entry names its type, the step feeding it, and its display parameters. The properties worth knowing as text:

::field-table
---
dataset: widget properties
grain: one row per property group
fields:
  - name: "type and step"
    type: "what and from where"
    role: "key"
    note: "chart, table, number, text, filter, image, container. Plus the step name. Changing which step a widget reads is a one-word edit here and several clicks in the builder."
  - name: "title and subtitle"
    type: "the text"
    role: "dimension"
    note: "Including any binding expression that makes the title dynamic. Searching titles is the fastest way to find a widget you can see on screen."
  - name: "formatting"
    type: "number format, colours"
    role: "measure"
    note: "Decimal places, currency, abbreviation, conditional formatting rules and their thresholds. The most common thing to bulk-edit, because a formatting decision usually applies to a dozen widgets at once."
  - name: "faceting behaviour"
    type: "does it respond"
    role: "dimension"
    note: "Whether this widget reacts to selections elsewhere. The reference widget that must not move is a property here -- and in the JSON you can confirm it across every widget at a glance rather than opening each panel."
---
::

::tip{icon="i-lucide-replace"}
**Bulk formatting is the best everyday use of the JSON.** Somebody decides currency should be abbreviated without decimals across a whole dashboard. In the builder that is twelve panels and a decent chance of missing one; as text it is one find-and-replace that cannot miss any. The same is true of a threshold change to every conditional format on the screen.
::

## Layouts, and why they surprise people

Layouts are the part that catches you out, because there is usually **more than one** — a set of breakpoints, each with its own positions and sizes.

::warning{icon="i-lucide-smartphone"}
**A widget can exist in one layout and not another.** Add a widget in the builder while previewing desktop, and a phone layout may not receive it — so the widget is simply absent for anyone on a small screen, with nothing to indicate it. Equally, deleting a widget and leaving an orphaned reference in another layout produces an empty slot. If a dashboard looks wrong on one device and right on another, the layouts are where to look, and the widget is almost certainly fine.
::

::lesson-steps
---
items:
  - title: "Check every breakpoint after a structural change"
    description: "Adding, removing or resizing a widget affects one layout by default. Preview at desktop, tablet and phone widths before shipping — the Analytics tab is narrower than Studio, which is where many viewers actually are."
  - title: "Keep the mobile layout deliberately smaller"
    description: "Not every widget belongs on a phone. A layout that omits the wide table and the dense pivot reads far better than one that shrinks everything to illegibility."
  - title: "Watch for orphans"
    description: "A layout entry referencing a widget that no longer exists leaves a gap. The JSON makes this findable; the builder mostly does not."
---
::

## Containers and grouping

Containers group widgets so a set can be positioned, shown or hidden together. Used well, they keep related widgets together across breakpoints. Used heavily, they nest several levels deep and become as hard to reason about as chained bindings — the same maintainability rule applies.

## The round-trip test

::note{icon="i-lucide-refresh-cw"}
**After any hand edit: save, reload the dashboard in the builder, and confirm it still opens and still edits.** Some hand-written structures are valid JSON that the builder cannot reconstruct into its visual form, and you want to discover that immediately rather than three weeks later when a colleague tries to change a title. If the round trip fails, revert to the copy you exported before you started.
::
