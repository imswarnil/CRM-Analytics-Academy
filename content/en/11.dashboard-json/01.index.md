# When to Open the JSON

A CRM Analytics dashboard is a JSON document: widgets, layouts, queries and bindings, all as text. The builder writes it for you, and occasionally the text is the better tool.

::note{icon="i-lucide-file-json"}
**This is not the advanced tier of dashboard building.** Most dashboards should never have their JSON opened, and reaching for it to do something the builder does perfectly well is a way to produce a dashboard nobody else can maintain. It earns its place for bulk work, for review, and for the handful of things the interface does not expose.
::

## The four good reasons

::field-table
---
dataset: when JSON wins
grain: one row per case
fields:
  - name: "Bulk edits"
    type: "the main one"
    role: "key"
    note: "Rename a field across thirty widgets, change every query pointing at an old dataset, apply a filter to every widget on the screen. Find and replace in a text file beats thirty configuration panels, and it cannot miss one."
  - name: "Review and diff"
    type: "underrated"
    role: "dimension"
    note: "JSON is text, so a change diffs. That converts 'I adjusted the dashboard' into a reviewable list of exactly what moved -- the only realistic change control available for dashboards."
  - name: "Reuse and templating"
    type: "scaling"
    role: "measure"
    note: "Four regional dashboards that differ only in a filter value. Build one, copy the JSON, change the value. Better still, generate them -- which is the APIs section."
  - name: "Reaching something the UI does not expose"
    type: "occasional"
    role: "measure"
    note: "Properties that exist in the format but have no control in the builder. Genuine, uncommon, and the reason people first open the file -- then they discover the other three and stay."
---
::

## The two bad reasons

::warning{icon="i-lucide-hand"}
**Do not use JSON to do ordinary work faster, and do not use it to be clever.** A dashboard hand-edited into a configuration that the builder cannot round-trip is a dashboard only you can change, which is the same failure as an over-bound one. If the builder can express it, let the builder express it — the JSON is for what the builder cannot do, and for seeing what it did.
::
