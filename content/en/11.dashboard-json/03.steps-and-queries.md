# Steps and Queries

A step is a query definition with a name. Everything a widget displays comes from one.

## What a step carries

- **Its dataset** — which one it reads.
- **Its shape** — groupings, measures and filters, either as structured properties the builder can edit or as raw SAQL.
- **Its name** — how widgets and bindings refer to it.
- **Its selection behaviour** — what happens when a viewer clicks something driven by this step, including whether it facets others and its initial selection.

## Clicked queries versus raw SAQL

::warning{icon="i-lucide-lock"}
**Converting a step to raw SAQL can be one-way in practice.** Once a step carries a hand-written query, the visual editor may not be able to reconstruct the structured form, so the next person edits text or rebuilds the widget. That is an acceptable trade for something the builder genuinely cannot express, and a poor one for a query you wrote by hand out of preference.
::

## Static steps

Not every step queries data. A **static step** holds a fixed list of values — the options in a toggle, a set of thresholds, a list of labels. They are how a measure toggle gets its choices, and they are cheap: no query, no round trip.

::tip{icon="i-lucide-list"}
**If a static step's values are business rules, they are in the wrong place.** Thresholds typed into a dashboard's static step go stale invisibly — nobody reviews a dashboard's JSON when the business changes its definition of "at risk". Bands and thresholds belong in the recipe, where the bucketing lesson put them; a static step is for interface options like "ARR / Deal count".
::

## Consolidating queries

The number of distinct steps is the main performance lever on a dashboard, and the JSON makes it countable.

  - title: "Find steps that differ only in presentation"

    description: "Widgets sharing a step now share its selection behaviour too. That is usually what you wanted, and it is worth confirming rather than assuming — especially for a reference widget that was deliberately not faceting."

## Filters live in more than one place

A widget can be narrowed by the step's own filter, by a dashboard filter, by faceted selection, and by the security predicate. When a widget shows fewer rows than expected, the JSON tells you about the first of those directly — and that is often the one nobody remembered was there.
