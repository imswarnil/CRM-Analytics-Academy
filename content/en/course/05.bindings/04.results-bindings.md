interview:
  - q: "What is the risk with heavy binding use?"
    a: "Results bindings force sequential execution and make dashboards hard to maintain: a renamed column breaks a chain silently. I keep chains short, document them, and prefer faceting or recipe logic when it does the job."
  - q: "When would you not use a binding at all?"
    a: "When faceting already does it, or the value is static enough to compute in the recipe. Bindings are for behaviour that must change at runtime."

```text
{{ cell(top_rep.result, 0, "OwnerName").asString() }}
```

| Use | Source step returns |
|---|---|
| Dynamic title | Top rep (ordered, limit 1) |
| Reference line / threshold | This quarter's target |
| Filter by computed value | Average deal size |
| Default selection | Best region |

::warning
Results bindings run in order: source first, then target. Long chains are slow, and two steps bound to each other never finish.
::
