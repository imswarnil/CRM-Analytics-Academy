# Reading a Story Honestly

The output is confident, well-presented and easy to over-trust. Five questions deflate most of the over-trust.

## 1. What would a trivial baseline score?

::warning{icon="i-lucide-equal"}
**Always compare against always-predict-the-majority.** If 3% of leads convert, a model that predicts "no" every time is 97% accurate and completely worthless. Accuracy on a rare outcome is nearly meaningless on its own, and it is the figure that gets quoted in the meeting. Ask what the model gets right *that guessing would not*.
::

## 2. Is there leakage?

An accuracy figure that feels too good almost always is. Re-read the top factors and check each one would have been populated, with that value, at the moment you want the prediction.

## 3. How many rows sit behind each claim?

A factor built on nine deals is a coincidence presented in the same typeface as one built on four hundred. Check segment sizes before quoting anything about a narrow slice.

## 4. Which factors can anybody act on?

::field-table
---
dataset: turning a story into action
grain: one row per question
fields:
  - name: "Is it actionable?"
    type: "the deciding question"
    role: "key"
    note: "Days since last activity — yes. Industry — no. A model whose top five factors are all descriptive is informative and cannot be deployed as advice, because there is no next action attached to any of them."
  - name: "Is it already known?"
    type: "value check"
    role: "dimension"
    note: "'Enterprise deals close more often' is true and adds nothing. The value of a story is in what somebody did NOT already believe."
  - name: "Would acting on it change the data?"
    type: "the feedback trap"
    role: "measure"
    note: "If reps start filling in the economic buyer field because the model rewards it, the field stops measuring engagement and starts measuring compliance with the model. The signal degrades precisely because you used it."
  - name: "Does it hold in every segment?"
    type: "robustness"
    role: "dimension"
    note: "A factor that reverses direction in one segment is either an interaction worth understanding or noise. Either way, a single company-wide model may be the wrong shape."
---
::

## 5. Would it still be true next quarter?

::note{icon="i-lucide-calendar-clock"}
**Models decay because the business moves.** The Academy launched Implementation Services in May 2025; a model trained before that has no idea the offering exists, and its view of what a good deal looks like is a view of the old portfolio. Decay is not a defect, it is the normal condition — which is why monitoring is part of deploying rather than an optional extra.
::

## Accurate and useless

The failure worth naming, because it survives review: a model can be accurate, honest, free of leakage, and still change nothing. If its top factors are all descriptive, if its predictions arrive too late to act on, or if it tells people what they already believed, it is a well-built artefact with no consequence.

::tip{icon="i-lucide-target"}
**Before deploying, write the sentence: "when this score is low, [person] will [do something] differently."** If you cannot fill it in with a real person and a real action, the story is worth reading and the model is not worth deploying. That sentence is the same test as the decision behind a dashboard, applied to prediction.
::
