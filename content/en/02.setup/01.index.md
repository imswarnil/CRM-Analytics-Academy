## Planned lessons

- **Why access first** — Licences, permission sets, two special users and a row-level security model — the least glamorous section in this course, and the one that decides whether anything else ships.
- **Licences & permission sets** — Growth versus Plus, the permission sets that actually grant access, why System Administrator grants none of it, and how to work out what a user is missing in under two minutes.
- **The integration user** — Data sync runs as a specific user, so whatever that user cannot see simply never arrives — no error, no warning, and a dashboard that looks entirely plausible while being wrong.
- **Row-level security** — The security user, the security predicate, and the role-hierarchy flatten — how a dataset decides which rows each individual viewer is allowed to see, and how to write a rule you can still explain in six months.
- **Sharing inheritance** — Letting Salesforce's own sharing decide who sees which analytics rows — what it covers, where it stops, and why it always needs a fallback predicate behind it.
- **Settings & rollout** — The Analytics settings page, how to adopt a new feature without breaking a live dashboard, and the rollout sequence that avoids a bad first week with a real team.
- **Hands-on: lock it down** — Add a security predicate to the accounts dataset so a regional rep sees only their own region — then prove it by checking as that rep rather than as yourself.
- **Interview questions** — The access questions asked in every CRM Analytics interview — licences, the two special users, predicates versus inheritance, and how you would debug an empty dashboard.
