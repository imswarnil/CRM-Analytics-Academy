## 応答を読む

結果が戻ってくる JSON: レコードのセット、列名の各マップは値です。 想定するよりも、処理する2つのこと:

- **クエリの列名から列名が来る `generate` エイリアス**つまり、エイリアスの名前を変更すると、応答のキーの名前を変更し、消費するものを破ります。 名前を意図的にピンにし、それらを安定した保つ。
- **型は、データセットが何を言っているかです。** 日付は、言語の日付オブジェクトではなく、データセットの表現に着きます。そして、クライアントに応じて数字が文字列として到着することがあります。 形状を信頼する代わりに明示的に解析します。

## ダッシュボードの数値が異なる理由

4つの理由、すべての正当な、およびこの順序でチェックする価値:

dataset: "discrepancy causes"

fields:
  - name: "A different user"
    type: "most common"
    role: "key"
    note: "行レベルのセキュリティが適用されます API インターフェイスにそのまま。 広範囲のアクセスを持つインテグレーションユーザーとして実行されるスクリプトは、地域のビューアよりも合法的に参照します。 それぞれの番号が間違っています。彼らは異なる人々のための質問に答えます。"
  - name: "A relative date range"
    type: "time moved"
    role: "date"
    note: "'Last 90 days' は、 23:00 で 01:00 より異なり、明日は異なることを意味します。 ライブダッシュボードの修正と、再コンパイル時のトラップ - そのためには、ピンの絶対日付。"
  - name: "The dataset refreshed between the two reads"
    type: "materialisation"
    role: "date"
    note: "夜に走る前にダッシュボードが開き、その後スクリプトが走った。 最後の実行時に、間違った番号に関する最初の質問はまだあります。"
  - name: "The query is not the same query"
    type: "the honest answer"
    role: "measure"
    note: "ダッシュボードのウィジェットは、ステップ、ダッシュボードフィルタ、および現在の選択からフィルタを運びます。 「同じ」メトリックを頻繁に生成する手書きのクエリは、通常、選択を省略します。 JSONお問い合わせ"
---
::

::tip{icon="i-lucide-copy"}
**ダッシュボードのクエリから最初はスクラッチから1つを書くのではなく。** コピーする SAQL それから選択が適用されたフィルターを加えて下さい。 2つの独立した書き込みクエリを交換することは、一つを適応させるよりもはるかに難しい問題であり、ほとんどの不透明度は誰も覚えていないフィルタであることが判明します。
::

## 調整のための決定主義

::warning{icon="i-lucide-calendar-clock"}
**調整ジョブは、その日付をピン留めする必要があります。** ソースシステムに対するロールウィンドウを比較すると、クロックが移動するたびに違いが生成され、2つのクエリが実行されたときの完全アーティファクトである午後を調査します。 絶対開始と終了, ジョブの上部に一度計算し、両側に使用する.
::

## リポジトリにクエリを保管する

スケジュール上で実行するクエリはコードです。 リポジトリをジョブで保持し、スケジューラのテキストボックスに貼り付けられず、レビューしたり、変更したり説明したりできません。また、生成された番号が疑われると、誰も見つけられない場所に保管してください。
