# オートメーションと展開

スクリプトは簡単です。 それらを確実に実行し、見直し可能な変更を作ることは、それが生き残るかどうかを決定する半分です。

## スケジュールと注文

データ準備セクションからの依存性トラップは、スクリプトがプラットフォームの独自のモニターに表示されないため、スクリプトで悪くなります。

::warning{icon="i-lucide-clock-alert"}
**それが消費するレシピの後に実行する負荷は、常に1日の背後にあるダッシュボードを生成します, 成功裏に, 永遠に.** すべてが緑を報告する。 チェーンを明示的に注文する — ロード, その後、同期, その後のレシピ — 実際のヘッドルームではなく、楽観的なギャップ, ジョブを好む *チェックイン* その依存性は、後から始まり、希望するだけに完了しました。
::

## 資格情報

例外なく適用される1つの規則: **スクリプトには秘密が含まれていることはありません。** 環境変数は、秘密ストアやCIプロバイダーの秘密ストレージ、専用の統合ユーザー、そして、誰かが所有する回転から供給されます。 パブリックリポジトリのクレデンシャルは恥ずかしいことではありません。

## 生産へのサンドボックス

orgs間での分析作業は、本物的にawkwardです。データセットは、org-local、idsは異なります。そして、一つのorgの参照からエクスポートされたダッシュボードは、他に存在しない可能性があることを言及しています。

::tip{icon="i-lucide-map"}
**繰り返し可能な部分を自動化し、書き込みチェックリストを残りの部分に保ちます。** ダッシュボード JSON テンプレート化とプッシュすることができます。データセットのID、セキュリティ述語、スケジュールは通常、orgごとの注意が必要です。 どのステップが手動であるかについて正直なチェックリストは、それらが存在しないとサイレントに存在しないデータセットで指すダッシュボードを展開するスクリプトを打ち負かす。
::
