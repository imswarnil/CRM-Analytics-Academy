# データの読み込み

外部データ API コネクタが入らないもの CRM Analytics: 倉庫の抽出物、ベンダーファイル、NamilioのWebセッションと支出。

## 順序で3つのステップ、

::lesson-steps
---
items:
  - title: "ジョブの宣言"
    description: "ロードしようとしているものを記述するレコードを作成します。データセット名、操作 — オーバーライト、追加、アップサート、削除 — フィールドを記述するメタデータ。 未発表の未発表です。"
  - title: "部品内のデータをアップロードする"
    description: "行は、1つのペイロードではなく、ナンバーされた部分として上ります。 各部分はファイルのチャンクであり、番号付けはプラットフォームがそれらを再構築する方法です。 大きい負荷は多くの部品です;小さいものは1です。"
  - title: "信号の完了"
    description: "ジョブのステータスを設定して、全ての部品が送信されるようにします。 処理が始まります。 これをスキップすると、誰もが一度にヒットし、エラーが発生しません。その部分は単にそこに座ってデータセットが現れません。"
---
::

::warning{icon="i-lucide-flag"}
**サイレント障害は、ステップ3を忘れています。** 宣言は成功しました。すべての部分が正常にアップロードされ、エラーが発生しません。データセットはありません。 残っているジョブは、ジョブがまだ進行中から消える。 負荷が「仕事がではなく、何も作り出さない」場合、ジョブのステータスをチェックしてください。
::

## メタデータファイルがフィールドタイプを決める

宣言で送信されたメタデータは、各フィールドが何をしているかをプラットフォームに伝えます。その名前、ラベル、およびテキスト、数値、日付であるかどうか、フォーマットと精度。

::note{icon="i-lucide-type"}
**これは、コード内のデータ準備セクションからCSV-uploadレッスンです。** 同じ3つの間違いは、同じ費用で、そして今、あなたがクリックしたダイアログではなく、あなたが制御するファイルです:テキストとして宣言された日付は、決してトレンドすることができず、測定として宣言された数字の見栄えのIDは、最終的に誰かによって要約され、間違ったスケールを持つ通貨は、それをフラグするものではありません。 ここで行う利点は、メタデータがコードであるということです。それは、レビュー可能で、互換性があり、すべての実行で同じです。
::

## インクレメンタルは自動的に改善されません

::compare-cols
---
items:
  - title: "完全な上書き"
    subtitle: "Send everything"
    icon: "i-lucide-refresh-cw"
    pros:
      - "Self-correcting — a bad run is fixed by the next good one"
      - "No key required, no drift possible"
      - "Far easier to reason about at 2am"
    cons:
      - "Wasteful as the dataset grows"
      - "Longer run, larger API footprint"
    verdict: "Right until volume makes it wrong. Start here."
  - title: "インプレメンタルアップサート"
    subtitle: "Send what changed"
    icon: "i-lucide-git-pull-request"
    pros:
      - "Fast, small, cheap on API allowance"
      - "Necessary at large volumes"
    cons:
      - "Needs a reliable change marker and a genuinely unique key"
      - "Drifts silently when a change is missed — nothing errors, the dataset is just slightly wrong, forever"
      - "Needs periodic full reconciliation to catch that"
    verdict: "Adopt when volume demands it, with a reconciliation job."
---
::

::tip{icon="i-lucide-check-check"}
**どちらを選択するか、ロード後の行数を確認します。** データセットのメタデータを読み、送信したものと比較します。 コードの行数が少ないため、毎晩実行され、そうしないと1週間後にダッシュボードを見ている人によって発見される部分的な負荷をキャッチします。
::
