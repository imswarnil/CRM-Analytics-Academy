# レシピで同じデータセットを作成する

ビルドしてみましょう **厳密な同じ** 機会データセット — 意見 + アカウント + ユーザー — と **レシピ** お問い合わせ レシピは、最新のデータ準備エンジンです。ドラッグアンドドロップ、ビジュアル、データフローよりもはるかに柔軟です。 トレードオフは、 *お問い合わせ* 関係を所有する。 Dataset Builder 次のオブジェクトとあなたのための参加キーを把握しました。 レシピでは、参加するものと方法を決定します。

## 新しいレシピを始める

詳しくはこちら Analytics Studio, **作成 → データセット** データセットやオブジェクトの同期から選択します。 **レシピ** お問い合わせ Data Manager (データフロー) & レシピ → **レシピ** →新しいレシピ)。

レシピで, **データの選択** 作成したデータセット、外部ソース、コネクティッド/同期オブジェクトがすべて表示されます。 Salesforceお問い合わせ 同じ3つをつかむ — **コミュニティ**, **パスワード**, **ユーザー**お問い合わせ

::tip{icon="i-lucide-list-checks"}
最初から実際の違い Dataset Builder: できます **すべてを選択** オブジェクトごとのフィールドをワンクリックではなく、広いオブジェクトの巨大なタイムセーバーです。 しかし、そうではありません。 オブジェクトに150以上のフィールドがある場合、それらはすべてを必要としません。 あまりにも広いデータセットは、スクロールしてクエリを遅くすることができません。 ダッシュボードのニーズだけを引き出します。
::

クリック **次へ** そして、あなたはレシピキャンバスに上陸 — そこに座るあなたの3つのオブジェクト、 **接続しない**お問い合わせ それはコアの違いです: レシピで、それらを接続することはあなたの仕事です。

## 列の制御

レシピは、出力列をリアルタイムに制御します。

- **参加型** — 結合ノードを拡大して選択します **ラインナップ** 完全参加対。 (グレインレッスンで重要な理由は、こちらをご覧ください。)
- **プレフィックス** — アカウントのフィールドは、 `Account.Name`, `Account.Industry`など。 これらのプレフィックスの名前を変更して、最終的な列は必要な方法を読みます。
- **保存またはドロップ** — 着信列をプレビューし、 **ログイン** 出力に到達しないので、必要ないもの。 トリム `User.` たとえば、所有者名と写真だけにフィールドダウンします。

## 出力ノードを追加する

ここでは、ステップの人々を忘れています: **出力(登録)ノードを追加するまで、使用可能なデータセットとして存在しません。** 参加は、ダッシュボードに置くことができるものだけを生成します。
