# 実行とトラブルシューティング Dataflow

クリックしてデータセットを作成します。 **データフローを実行する**お問い合わせ それでは、実際に何をやっているのかを理解して、ほぼ全員を初めてキャッチするエラーを修正してみましょう。

## 本当に「データフローを実行する」とは

いつか Dataset Builder への書き込み **デフォルトデータフロー**ビルドするだけではありません *お問い合わせ* データセット — 実行 **すべて** そのデータフローに。 空でないトレーニング org で: 他のデータセットと指示を事前にパッケージ化します。 そのため、デフォルトデータフローを実行すると、すべての機能が実行されます。また、単に設計した機会のデータセットだけではありません。

::tip{icon="i-lucide-git-branch"}
これは、経験豊富なビルダーが最終的に作成する理由です **シェア** データフロー 単一の共有デフォルトデータフローは、すべてのビルドがすべてを再実行することを意味します。 成長するにつれて、名前付きデータフロー(またはレシピ)に作業を分割して、それぞれが独自のスケジュールでデータセットの既知のセットを更新します。
::

ヘッド **Data Manager → モニター** デフォルトのデータフローの実行が表示されます。

## 古典的な最初の実行エラー

新規の org — またはこの実行の初めて — データフローは、 **エラーで失敗**お問い合わせ 慌てないでください。 原因はほぼ常に単純です。データフローはオブジェクトを要求しています **まだ同期レイヤーに引き込まれていない**お問い合わせ

チェーンを記憶:データフローが読み込まれる **接続/同期**からではなく Salesforce 直接。 Connect がアカウント、Opportunity、および User を改ざんしていない場合は、データフローは読み込まれずエラーが発生します。

## フィールドを忘れた場合 ダイジェストノードの編集

再開できないため Dataset Builder フィールドピッカー、編集フィールドは後で起こります **dataflowのダイジェストノード**お問い合わせ

- データフローを開き、関連するダイジェストノード(say)をクリックします。 **パスワード**)フィールドを経由して再追加 **フィールドの選択**お問い合わせ
- 保存し、プロンプトが表示されたら、選択します **プロパゲート** フィールドは、最後のレジスタノードまで下がるすべての方法です。そうしないと、そのサブウェイを停止し、データセットに到達しません。
- 更新と更新 **データフローを再び実行する** 従って新しい分野は材料化されます。

ダイジェストノード、フィールド属性、およびデータフロー編集を適切にカバーします。 Data Manager レッスン — 気に入らないだけ。

## 最初のデータセットを作成しました

データフローが緑色に仕上げたら、戻って Analytics Studio そこには、あなたの機会データセット、あなたのプライベートアプリに座って、探索する準備ができています。 ランドスケープダイアグラムでは、今では生きています **データセットレイヤー**, 同期から読み込むデータフローによって構築されます。

::tip{icon="i-lucide-check-check"}
データフローが失敗したときにメンタルチェックリスト: **(1) (1) (1)** ソースオブジェクトは同期されますか? **(2)** データフローが走る前に、実際に接続してみませんか? **(3)** レジスタノードにプロパゲートが必要なフィールドは? 初めての不具合が10件のうち、これらの3つの質問に回答されます。
::

Dataset Builder フレンドリーですが、ルックアップとデータフローにあなたをロックします。 次に構築します **同じデータセット** お問い合わせ **レシピ** - プラットフォームが見出している方向、前面、はるかに制御、および方向をもっとクリックします。
