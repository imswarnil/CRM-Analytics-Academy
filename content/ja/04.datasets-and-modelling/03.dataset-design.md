# データセットの設計

テーブルからではなく、質問から始めましょう。 テーブルは何ができるかを教えてくれます。質問は何をビルドするかを教えてくれます。

## 4つの要求設計

::lesson-steps
---
items:
  - title: "答えなければならない質問を書き留める"
    description: "5、6、プレーン語 'Which セグメントは ARR を保持します。' 「取引が最長に立ち往生している」 それらをリストできない場合は、データセットではなくソーステーブルのコピーを作成しています。"
  - title: "最高級の質問から穀物を育てる"
    description: "質問が個々の取引に関してあれば、穀物は1列あたりの取引です。 セグメントごとに月単位の合計がすべてある場合、月単位で1列の列が1列になる場合があります。"
  - title: "各質問が必要とする列のリスト"
    description: "大きさをグループ別に、集計、傾向への日付を測定します。 リストされた質問に役立たないものは、退去する候補です。追加の列は時間を実行し、次の人のためにフィールドリストを難しくなります。"
  - title: "永続的に除外されるものを決定する"
    description: "レコードのテスト、内部アカウント、製品ラインの誰もレポートしません。 行がこのデータセットに応答しない場合には、すべてのダッシュボードに覚えておくのではなく、ここでフィルタリングしてください。"
---
::

::warning{icon="i-lucide-filter-x"}
**データセット内のフィルタは、すべての下流に見えない。** つまり、その価値とそのリスク: ソースに対するデータセットを分析することは、違いを見つけ、理由を見ない方法はありません。 データセットの記述にすべてのデータセットレベルのフィルタを入れる — 'テストアカウントと内部のサンドボックス org' を除外する - または、あなたは慎重に尋ねられます。
::

## 1つのデータセットか2つか。

テンプテーションは、常に既存のものを広げることです。 代わりに分割すべき2つの信号:

::compare-cols
---
items:
  - title: "スプリート"
    subtitle: "Different grain, or different purpose"
    icon: "i-lucide-split"
    pros:
      - "Each is simple enough to reason about"
      - "The daily dashboard gets a fast pre-aggregated dataset while exploration keeps the detail"
      - "One recipe can produce both outputs, so the logic is still defined once"
    cons:
      - "Two things to schedule and monitor"
    verdict: "Usually right when the grains genuinely differ."
  - title: "ワイド"
    subtitle: "Add columns to the existing one"
    icon: "i-lucide-move-horizontal"
    pros:
      - "One thing to maintain"
      - "Fine when the new questions live at the same grain"
    cons:
      - "A dataset serving everybody eventually serves nobody well"
      - "Sixty columns of which fifteen matter is hostile to self-service"
    verdict: "Right only while the grain and purpose still match."
---
::

::tip{icon="i-lucide-git-branch"}
**1つのレシピから2つの出力は、未使用のオプションです。** 参加、清掃、定義は一度行われます。 レシピは、詳細なデータセットと集計されたものを書きます。 論理の漂流の2つのコピーなしで、必要な場所が重要で細部である速度を得ます。
::

## 説明の穀物を書く

すべてのデータセット、1つの文: *製品ごとの機会ごとの1列*お問い合わせ それは仕事の5秒であり、誰も下流を読むのに最も有用なものの1つです。同僚と正しい列をまとめ、かつて知らずに重複したものをまとめることの違い。
