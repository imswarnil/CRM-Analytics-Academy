# ダッシュボードの解剖学

## 互いに参照する方法

ウィジェットにはクエリが含まれていません。 **ステップの名前**お問い合わせ 複数のウィジェットは、見出し番号、バーチャート、テーブルが3つを発行するのではなく、1つのクエリを共有できるかを正確に示します。

::tip{icon="i-lucide-merge"}
**読書 JSON ダッシュボードのパフォーマンスを監査するための最速の方法です。** ウィジェットをカウントし、ウィジェットをカウントします。 十二のステップに対するウィジェットは、ほとんど何も共有されていないことを意味し、画面は11ラウンドトリップを作ることです。 4つのステップに対する12個のウィジェットは、誰かが考えていたダッシュボードです。 この監査は、テキストエディタで30秒かかりますし、すべてのビルダーで実行するためにawkwardです。
::

## 名前は読みやすい層です

ウィジェットが参照し、バインディングが参照し、何かをトレースするときに読み込まれるステップ名は、どこにでも伝播します。

`step_7` 何も言わない。 `closed_won_by_segment` クエリがその行を読んでいる前に、次の人物に伝えます。バインディングは、名前による参照ステップを記述するため、良い名前は、正当な配置とパズルの違いです。
