# ウィジェットとレイアウト

ウィジェット *お問い合わせ* 描画されます。 レイアウトは *座る場所*お問い合わせ それらを離れて保つことは、ウィジェットが広い画面と携帯電話で異なる配置できるものです。そのため、位置の問題はウィジェットに決してありません。

## ウィジェット

各ウィジェットは、そのタイプ、それを供給するステップ、およびその表示パラメータの名前を入力します。 テキストとして知る価値のあるプロパティ:

::field-table
---
dataset: "widget properties"
grain: "one row per property group"
fields:
  - name: "type and step"
    type: "what and from where"
    role: "key"
    note: "チャート、テーブル、番号、テキスト、フィルタ、イメージ、コンテナ。 ステップ名をプラスします。 ウィジェットが読み込まれるステップは、ここで1つの単語の編集とビルダーの複数のクリックです。"
  - name: "title and subtitle"
    type: "the text"
    role: "dimension"
    note: "タイトルを動的にさせる任意の結合式を含みます。 タイトルを検索するのは、画面上で見ることができるウィジェットを見つけるための最速の方法です。"
  - name: "formatting"
    type: "number format, colours"
    role: "measure"
    note: "所定の場所、通貨、略語、条件付き書式規則およびそのしきい値。 フォーマットの決定は通常一度にダースウィジェットに適用されますので、バルクeditに最も一般的なもの。"
  - name: "faceting behaviour"
    type: "does it respond"
    role: "dimension"
    note: "このウィジェットが他の場所で選択に反応するかどうか。 動く必要のない参照ウィジェットはここにプロパティです。 JSON 各パネルを開くのではなく、すべてのウィジェットを一目で確認することができます。"
---
::

::tip{icon="i-lucide-replace"}
**バルクフォーマットは、日常的に使うのがベストです。 JSONお問い合わせ** 一部の人は、ダッシュボード全体で小数なしで通貨を省略する必要があります。 12つのパネルと欠落のチャンスであるビルダーでは、テキストとして、それは見逃せない1つの発見と置換です。 同じことは画面上のすべての条件形式にしきい値の変更の真です。
::

## レイアウト、そしてなぜ彼らは人々を驚かせているのか

レイアウトは、通常はあるので、あなたを引き出す部分です **1 つ以上** — 1セットのブレークポイント、それぞれ独自のポジションとサイズ。

::warning{icon="i-lucide-smartphone"}
**ウィジェットは1つのレイアウトではなく別のレイアウトに存在できます。** デスクトップをプレビューしながら、ビルダーにウィジェットを追加し、電話レイアウトが受信できない可能性があるため、ウィジェットは単に小さな画面で誰にとっても迷惑になります。 同様に、ウィジェットを削除し、別のレイアウトで孤立した参照を残すと、空のスロットが生成されます。 ダッシュボードが1つのデバイスと別のデバイスで間違っている場合、レイアウトはどこに見ても、ウィジェットはほぼ確かに良いです。
::

## コンテナとグループ化

コンテナグループウィジェットは、セットが配置され、表示または非表示にすることができます。 よく使うと、関連するウィジェットをブレークポイント全体で保持します。 重く使用されて、それらは複数のレベルを深く入れ、チェーンされた結合について理由が難しくなり、同じ保守性規則が適用されます。

## 往復テスト

::note{icon="i-lucide-refresh-cw"}
**任意のハンド編集後: 保存, ビルダーのダッシュボードをリロード, それはまだ開いて確認し、まだ編集.** いくつかの手書き構造が有効である JSON ビルダーは視覚的な形に再構築できないため、同僚がタイトルを変更しようとすると、直近で3週間後にはすぐに発見したい。 往復が失敗した場合は、開始前にエクスポートしたコピーに戻ります。
::
