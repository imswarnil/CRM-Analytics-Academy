# ステップとクエリ

ステップは、名前のクエリ定義です。 ウィジェットの表示はすべて1つから来ています。

## ステップが運ぶもの

- **データセット** — 読み込まれるもの。
- **その形状** — グループ化、対策、フィルタ、構造化されたプロパティとして、ビルダーが編集できるか、または未加工 SAQLお問い合わせ
- **その名前** —ウィジェットとバインディングが参照する方法。
- **その選択行動** — 視聴者がこのステップによって運転されている何かをクリックすると、他の人とその初期選択に直面しているかなど、何が起こります。

::warning{icon="i-lucide-lock"}
**一歩を生に変える SAQL 片道練習ができます。** ステップが手書きクエリを実行すると、ビジュアルエディタは構造化されたフォームを再構築できないため、次の人はテキストを編集したり、ウィジェットを再構築したりすることができます。 つまり、ビルダーが本物に表現できないような取引であり、好みの手元で書いたクエリの悪い取引です。
::

## 静的ステップ

すべてのステップのクエリデータではありません。 ツイート **静的ステップ** 値の固定リストを保持 — トグルのオプション, しきい値のセット, ラベルのリスト. 彼らは測定トグルがその選択肢を得る方法であり、それらは安い:クエリなし、往復しません。

::tip{icon="i-lucide-list"}
**静的なステップの値はビジネスルールである場合、それらは間違った場所にいます。** ダッシュボードの静的なステップにタイプされた境界は見えないように見えます。誰もダッシュボードのレビューをしません JSON 事業が「リスク」の定義を変更するとき。 バンドとしきい値は、バケットレッスンがそれらを置くレシピに所属しています。静的なステップは、 "ARR / Deal count" のようなインタフェースオプションです。
::

## フィルターは複数の場所で住んでいます

ウィジェットは、ステップの独自のフィルタによって、ダッシュボードフィルタによって、選択に直面し、セキュリティ述語によって絞り込むことができます。 ウィジェットが期待以上に少ない行を表示する場合、 JSON 誰が覚えていないかは、直接その最初のことを教えてくれます。
