# 漏斗と滝

2つのチャート **レイアウトは意味を運びます**お問い合わせ いずれかのどちらかを注文し、同じ主張であることを停止します。.

## ファンネル

シーケンシャルステージ、各サブセットの前に。 セッション → リード → 認定 → 機会 → クローズドウォン. 隣接するステージ間のドロップは、発見です。

::note{icon="i-lucide-arrow-down-narrow-wide"}
**注文を、決して大きさで分類しません処理して下さい。** サイズ別に分類されたファネルはバーチャートで、ファネルが1つを破壊します。それぞれに隣接するステージを置くと、それらの間のドロップは算術なしで表示されます。 これは、バーチャートの後にコースの最も結果的なソート設定です。
::

### スケールの問題

実質の漏斗はmagnitudeのスパンの発注、そしてそれは線形版を壊します:

::funnel-viz
---
stages:
  - label: "Webセッション"
    value: 4932
    note: "漏斗の頂上は、その下にあるすべてのものを矮化します"
  - label: "リード"
    value: 2800
    note: "まだ合法"
  - label: "資格取得"
    value: 1120
    note: "速い収縮"
  - label: "ニュース"
    value: 677
    note: "リニアスケールでは、これはスタブです"
  - label: "クローズド・ウォン"
    value: 275
    note: "そして、これはほとんど見えない"
caption: "Namilio、ログスケール — すべてのステージが読みやすくなります"
scale: "log"
---
::

::warning{icon="i-lucide-ruler"}
**ログスケールは正直言っています。** 線形軸線では、数千から数百のファンネルが、最後の4つのステージを同一のスライバーとしてレンダリングし、4つは販売が起こる場所です。 ログは、すべてのレガシーを保持します。 sneaky ではなく、正直なことは、軸を logarithmic としてラベル付けし、チャート上のコンバージョンパーセンテージを入れているので、誰もバーの長さを比率として読みません。
::

### ステージ間のレートはポイント

絶対カウントはコンテキストです。 **隣接したステージ間の変換** 誰かが何をしているか。 各ペアのパーセンテージを置き、使用したデノミネーターがステップツーステップ、または各ステージを上から使用することを明示します。 数字が異なるので、両方とも「コンバージョン率」と呼ばれます。

::field-table
---
dataset: "funnel conventions"
grain: "one row per decision"
fields:
  - name: "Step conversion"
    type: "stage ÷ previous stage"
    role: "measure"
    note: "診断:漏出である場所。 1週間から1週間に渡るチームです。"
  - name: "Cumulative conversion"
    type: "stage ÷ top of funnel"
    role: "measure"
    note: "戦略的:需要の分数が収益になるもの。 リークを見つけるために計画し、役に立たないために有用。"
  - name: "Cohorting"
    type: "by entry date"
    role: "date"
    note: "各ステージは、SAMEコホートをカウントし、前方に追跡しなければなりません。 各ステージがどの期間で起こったのかをカウントするファネルはファネルではありません。異なる時間で入力した人とコンバージョン率は何も意味しません。"
---
::

## ウォーターフォールズ

橋: 1 つの合計で始めて下さい、加え、引き込みは、別ので着きます。 Namilio の ARR の滝は正式なケースです。 ARR の開口部、プラスの新しい拡張、マイナスの収縮、マイナスのチューン、等しい閉鎖。

::lesson-cards
---
columns: 3
items:
  - title: "橋梁"
    icon: "i-lucide-waves"
    description: "各バーは、左前のバーをレベルに浮かぶので、目は実行中の合計に従います。 これは、同じ数字の積み重ねられた列とは異なるものです。"
  - title: "視覚的に問題の印"
    icon: "i-lucide-plus-minus"
    description: "Additions と subtraction は、一目で逆に読み込む必要があります。方向と色を一緒に、色を単独で着色しないでください。"
  - title: "開始および端はアンカーです"
    icon: "i-lucide-anchor"
    description: "開口部とクローズバーがベースラインに座って、フローティングされていない。 チャートのアンカーがなければ、スケールのないデルタのセットです。"
---
::

::tip{icon="i-lucide-calculator"}
**チャートを信頼する前に、1つの期間で算術をチェックしてください。** オープニングプラスの動きは正確に閉じる必要があります。 そうでない場合は、データやフィルタからの動きが欠落しているか、行を除外しています。そして、再構成しない滝は、読者が頭の追加を行うことができるため、提示する単一の最も恥ずかしいチャートです。
::

CRM Analytics すべてのリリースで専用のウォーターフォールウィジェットがないため、これは、目に見えないベースシリーズと積み重ねられた列として構築されることが多い、または実行中の合計で比較表として。 どちらが良いか。バーがフロートして、アンカーがベースラインに座っていることは何ですか。
