# フォーミュラとコンピューティングフィールド

2つの質問は、計算がどこに住んでいるかを決定します。 **行または集計後**と **会社またはこの画面に所属する**お問い合わせ

## 行ごと、または集計後

式ノード計算 **行**、グループ化の前に。 同じ行の値から派生した演算のために正しいです。

- `NetAmount = ListAmount - DiscountAmount`
- `DaysToClose = CloseDate - CreatedDate`
- `IsEnterprise = Segment == "Enterprise"`

最初は何も必要としない。 そして、分析における最も一般的な問題の答えは、ここに正確に住んでいます。

::warning{icon="i-lucide-divide"}
**比率の平均は合計の比率ではありません。** Namilioの引用符は、契約ごとに割引を運ぶ. それらの per-deal レートを重み合わせると、$ 5,000 の取引は、$ 2M とまったく同じです。そのため、かなりの割引の小さな取引は、実際に割引されていない会社のどこかで「平均割引」をドラッグします。 必要な人数は、合計リスト値で割った合計の割引です。 *アフター* 集計は、1列の列の平均値ではありません。
::

同じトラップは他の服を着ています: 応答全体の平均変換率、セグメント全体の平均勝率、アカウント全体の平均利用率。 各々は、ほぼ常にサイズで重み付けられることを意味します。

## バケット

トランスノードは、名前付き帯域に連続した値を持ちます。小/中/大にサイズを取引し、アンダー消費/ヘルシー/オーバーエイジでは、コホーツに耐えます。

::tip{icon="i-lucide-ruler"}
**一度バケット, レシピで, データセットのバンドの名前.** 各ダッシュボードが独自の方法でバケットする場合、"Large" の取引は、販売ダッシュボードの1つと、財務上の別のものを意味し、レビューではなく、会議での合意面を意味します。 バンドバウンダリは、正確に55%の活用が危険であるか、または健康であるかどうかのような、awkwardのものを含むメトリック定義の横に書く価値のあるビジネス決定です。
::

## ニュルス、なぜ彼らが見ているよりも重要であるのか

null はゼロではありません。 「私たちは知りません」であり、すべての集計で2つの動作は異なる:

- **ログイン** null を無視します。 40% の null の列の合計は、コメントなしで報告されたデータの 60% を超える合計です。
- **よくある質問** あまりにもデノミネーターでヌルを無視するので、平均値は値を持っていた行です。これは通常、あなたが望むものであり、あなたがチェックしたことはほとんどありません。
- **カウント** 非null値のカウントから行数を区別し、それらを混同することは一般的な静かなエラーです。

::warning{icon="i-lucide-circle-slash"}
**NamilioのCSAT調査は、作業例です。** クローズドケースの約42%が調査しています。 CSATの平均は、したがって、人々は、 *対応する*、顧客ではなく、喜ばれた、そして好奇心にこだわった回答者。 数字は間違っていません。ラベルの主張よりも狭い質問に答えます。 セクション10は、応答速度のない満足度は、測定ではなく広告であるため、永続的に表示される応答速度で構築します。
::
