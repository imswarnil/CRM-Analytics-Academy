# レシピのトラブルシューティング

メソッドは、順番で、デバッグは即興ではなく手順です。

## 注文

::lesson-steps
---
items:
  - title: "最初に監視して下さい"
    description: "いつ、何列が走ったのか? 「番号が間違っている」のレポートの3分の1はここに終了します。この答えは、金曜日に最後に実行されていることです。 15秒かかりますし、最大の単一カテゴリを除外します。"
  - title: "履歴に対する行数を比較する"
    description: "月間〜2,800行を保有するデータセットで、2,100件が問題ないダッシュボードが報告されます。 あなたのorgがこれを追跡しない場合は、予想される数をどこかに注意してください。それは利用可能な最も安い回帰テストです。"
  - title: "ノードプレビューを歩く"
    description: "各ノードを順番にクリックし、行数を読みます。 カウントが予期せず変化するノードは、問題のあるノードです。 これは、レシピがデバッグしなければならないもののためにデータフローを打つ理由です。"
  - title: "1つのエンティティティにフィルタをかける"
    description: "単一のアカウントまたは機会を選択し、プレビューをフィルタリングし、手でカウントします。 これは、その側面が多岐に渡るか、または消えた列を正確に教えてくれます。集合体で主演すると、何も教えてくれます。"
  - title: "それから、ダッシュボードだけ"
    description: "ウィジェットのクエリ、フェース、フィルタは、最後の疑いです。 彼らは通常、彼らが与えられたものを忠実に報告します。"
---

## 症状を引き起こす

::field-table
---
dataset: "diagnosis table"
grain: "one row per symptom"
fields:
  - name: "Total is 2× or 3×"
    type: "fan-out"
    role: "measure"
    note: "子行間で重複した親測定。 結合を歩くと、カウントがオフエンドノードでジャンプします。"
  - name: "Total is slightly high"
    type: "partial fan-out"
    role: "measure"
    note: "両親が複数の子供を持っているだけ。 クリーンな複数のものではなく、現実のデフォルトでスポットを探しにくい。"
  - name: "Rows missing for everyone"
    type: "inner join or upstream filter"
    role: "key"
    note: "インナーは、参加服を着るフィルターです。 また、条件がnullを意図せずに除外するフィルタノードもチェックします。'Stage != Close Lost'は、ステージがnullであるすべての行も削除します。"
  - name: "Rows missing for SOME users"
    type: "row-level security"
    role: "key"
    note: "レシピの問題は全くありません。 データの準備セクションごとに、相続を述または共有します。 言うことは、あなたにとっては良いことであり、それらのために間違っていることです。"
  - name: "A column is entirely null"
    type: "sync or permissions"
    role: "dimension"
    note: "フィールドは同期で選択されていないか、インテグレーションユーザは表示できません。 何も再構築する前に、入力ノードの列リストをチェックするのではなく、不在です。"
  - name: "Numbers change every run"
    type: "a non-deterministic recipe"
    role: "date"
    note: "通常、相対日付フィルタ — 'Last 30 days' が動きます。 または、任意のマッチを選ぶ非ユニークキーに参加する。 2 番目の 1 は nastier です。データが下にあるまで安定しています。"
  - name: "Everything is one day old"
    type: "schedule dependency"
    role: "date"
    note: "同期が完了する前にレシピが実行されます。 どこでも緑に、一貫して失います。 2つのスケジュールと実際の実行時間を比較します。"
---
::

::tip{icon="i-lucide-undo"}
**レシピが変更後に破棄されると、調査前に変更を解除します。** 壊れた状態から転送をデバッグするのが待ち時間です。作業中の1つに戻り、小さな部分で変更を再適用するのが高速です。 これは通常のエンジニアリングの規準であり、各編集が小さい感じている視覚用具で捨てることは珍しく容易です。
::
