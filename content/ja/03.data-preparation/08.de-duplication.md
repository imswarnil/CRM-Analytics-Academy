# デジュプリケーション

「重複している」と3つの無関係な問題について説明します。 それぞれの修正が異なり、それらが何かを削除してはならないので、あなたが持っている1つはレッスン全体である診断。

## 3種類

  - name: "Legitimate repetition"
    type: "the intended grain"
    role: "dimension"
    note: "毎月のスナップショットで18回表示されるアカウント、多くの機会に表示される製品。 正しく働く穀物です。 削除して、データセットの目的を破壊します。"
  - name: "Genuine duplicate records"
    type: "the real problem"
    role: "measure"
    note: "同じリアルワールドの事柄が2回入力 — 1つの会社に2つのアカウントレコードが3つのフォームから3回提出された。 これは、重複排除を求める唯一のケースで、3つの最もまれです。"
---
::

::warning{icon="i-lucide-triangle-alert"}
**ファンアウトを固定するための行を削除することは、利用可能な最も有害な応答です。** 全体がダウンします。, それが働いたように見えます, そして、あなたは今、間違ったjoinを所定の位置に残しながら、実際のレコードを削除しました — そのため、同じレシピに追加の次の測定は、再び間違っています, 異なる方向で, データセットは、もはやそのソースに一致しません. 削除前の診断:各結合ノードの前と後列をカウントし、それらが乗った場所を見つけます。
::

## サバイバーシップは価値が行くところです

::note{icon="i-lucide-merge"}
**最新の行を維持することは、多くの場合、ほとんどの情報を失います。** 先週作成した重複は、古い1つが12つある場所に3つのフィールドがポップアップ表示されます。 実際の複製は通常、マージします。現在のフィールドごとに最新の値を取り、古いレコードに戻り、行を選択して残りの部分を破棄します。 つまり、レシピの作業が進んでおり、清掃データと失うことの違いです。
::

## できる場所を上流に固定する

レシピの複製は、回避策です。 それは、毎晩実行します。, 永遠に, ソースシステムは、すべての他の消費者も処理しなければならない重複を生産し続ける.

::tip{icon="i-lucide-arrow-up"}
**重複したレートを、ソースを所有している人に戻します。** ソースによる新しい重複グループが毎週数えるのは、クリーンアップ自体よりも、より価値のある成果物です。それは目に見えないデータ品質の問題を誰かに所有することができる番号に変えます。 レシピレベルの修正は、ダッシュボードがその間に正しい状態に保ち、それはまさに回避策が何をすべきかです。実際の修正がどこかで起こる間、ラインを保持します。
::

## 後方確認

重複排除後、行数とソースに対するキー合計を比較します。 40行を削除し、8%による収益を変更したクリーンアップは重複を削除しませんでした。それは異なるレコードを削除し、チェックはダッシュボードがなくなる前にそれをキャッチする唯一のことです。
