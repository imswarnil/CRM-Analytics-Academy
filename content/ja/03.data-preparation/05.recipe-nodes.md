# レシピノデ

セブンノードタイプは、ほぼすべてを実行します。 それらを学習するための有用な方法は、アルファベットではなく、それはそれぞれがに何をするかです **ログイン**穀物は最初のノードから最後まで追跡しなければならない唯一のプロパティであるため。

## 参加: どの種類を選択したかを知る

- **ルックアップ/左** — 左のすべての行を保持し、マッチが存在する右側の列を追加します。 非一致行は左の値を保持し、null を取得します。 これは通常の選択肢です。
- **インナー** — 両側にマッチする行のみを保持します。 正当な「記録が欠落している」の静かな原因:アカウントが以前の黙って消えた機会。
- **外バリアント** — 一致しない行を 1 つの側または両方から保持し、null でギャップを埋めます。

::warning{icon="i-lucide-scissors"}
**インナーは、参加服を着るフィルターです。** 行を削除し、レコードを外すのではなく、列を追加することを考えている点でそうします。 行が欠落し、許可がチェックアウトされると、次の疑似は、上流の内側の結合です。
::

## レシピを小さく保つ

硬いノードの天井がなく、実用的なものもあります。 過去に約20ノードのレシピは、それを書いていなかった人によって読みやすくなり、失敗はローカライズを停止します。パイプラインのどの3分の1が壊れたかをもはや伝えません。

::note{icon="i-lucide-split"}
**サイズではなく、意味を分割します。** 1つのレシピによって生成されたクリーンなベースデータセットと、他の人がそれを読んだことによって生成された2つの派生したデータセットは、理由が容易です *そして、* 1つの長い鎖より固定する速い。 コストは正しく注文する別のスケジュールです。これは、前のレッスンの依存性トラップを与え、無視ではなく真剣に受け止める価値があります。
::
