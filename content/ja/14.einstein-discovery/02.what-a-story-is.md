# ストーリーとは

データセットを与え、あなたが気にしている列を名付けます — 勝ったり、紛失したり、保留したり、変換したりしません。 結果を分離する他の列のパターンを検索し、強さによってランク付けされたそれらを報告します。

## 実際に出力が言うもの

ストーリーは、それぞれに要因を与えます **インフォメーション** (結果から離れる)、 **パスワード**と、 **セグメント** 最も強く適用される場所。

::note{icon="i-lucide-quote"}
**主張は相乗的であり、フレーズはそれを忘れるためにあなたを招待します。** 「経済の買い手が特定されていない取引は、クローズする可能性が34%低い」は、履歴データにどのような共同取引が行われているかについての声明です。 経済バイヤーの特定が確立されていない *原因* 取引は閉じる - すでにうまく行く取引は、誰かがフィールドを埋めるために悩まされているものと同じです。 物語は、指示のセットではなく、見える場所のマップです。
::

## 3種類の要因

::field-table
---
dataset: "reading a factor"
grain: "one row per kind"
fields:
  - name: "Actionable"
    type: "you can change it"
    role: "key"
    note: "最後のアクティビティ、ディスカウントレベル、セキュリティレビューが始まったかどうか。 これらは、次のアクションが添付されているので、返信の前に置く価値のある要因です。"
  - name: "Descriptive"
    type: "true and unchangeable"
    role: "dimension"
    note: "区分、企業、会社のサイズ、地域。 実際の信号とそれについて何もしない - ターゲットと領土のデザインに有用で、レコードページでアドバイスとして役に立ちます。"
  - name: "Suspicious"
    type: "too good"
    role: "measure"
    note: "ほとんど完全に予測する要因は、通常漏れです。結果の前後に記録されたもの。 「署名された契約日は、絶妙な精度でクローズドウォンを予測し、すべてで何も言わない。"
---
::

::warning{icon="i-lucide-alert-triangle"}
**最も強い要因は、少なくとも有用です。** ストーリーは強さによってランク付けされるので、リストの一番上には、人が行動できるものではなく、記述的なものや漏れが頻繁にあります。 リスト全体を読み、次のアクションが存在するかどうかによって各要因を判断する - 担当者は、企業がセルフサーブよりも優れていると述べる必要はありません。
::

## 小さなデータが自信のないものに

Namilioには677の機会があります。 狭いセグメントについての自信のために、物語とどこにも十分です。

::tip{icon="i-lucide-microscope"}
**信じる前に要因の背後にある列の数を確認してください。** 「LATAM の技術的な評価が 60% を閉じる」は、100 件の取引を休止し、9 で休息するときに偶然の発見です。 話は、同じ声のトーンで報告し、セグメントサイズは、それらを区別する唯一のことです。
::
