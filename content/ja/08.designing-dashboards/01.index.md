# 決断のための設計

このセクションのすべてが1つの文に残ります。 **決定なしのダッシュボードは装飾です。**

::note{icon="i-lucide-target"}
**テスト。** 決定、それを作る名前、および頻度の名前を名前付ける。 「営業開発担当副社長が、月経を移動する場所を決定します。」 その文を埋めることができない場合は、ダッシュボードを設計していないので、チャートを配置しています。レイアウトのスキルはそれを助けません。
::

## 4秒のテスト

ダッシュボードが見つからなかった人達が開きます。 4秒で、物事が良いか悪いか、それが何であるかを言うことができるはずです。

4秒は1つのヘッドライン数、1つの形状、タイトルです。 これは、最初の印象のための予算全体です - 他のすべてが滞在することを決めた人のためのものです。

## 請負はスキル

誰でもウィジェットを追加できます。 4を削除し、ダッシュボードを残すことができる人 *おすすめ* 採用の価値はあります。

::tip{icon="i-lucide-scissors"}
**仕事を行う質問:「それが示されたものに応じて、異なることをしますか?」** 親切に、それは誰かから誰かの必要性が好奇心あるあることを区別します。 好奇心は正当性であり、それはすべての月曜日にチェック画面6人ではなく、レンズに属しています。 ひとつの質問は、設計の原則よりも多くの混乱を取り除きます。
::

このコースの全てのビルドは、 `notInScope` その理由の一覧です。 それは欠落しているものの謝罪ではありません - それは決定の記録であり、誰かが自分のチャートがそれにない理由を尋ねるときに、それはダッシュボードの防御可能になります。
