# 属性 — どの嘘を言おうか

開発者は3月にブログ投稿を読んで、5月に会議の話を見て、6月にベンダーについてClaudeに尋ね、7月に有料広告をクリックし、9月に署名した会社が$ 180,000で署名しました。

::note{icon="i-lucide-help-circle"}
**どのチャネルが$ 180,000で獲得したか?** すべての回答は守られず、すべての回答が間違っています。 このレッスンは、目的を一つ選び、理由を言うことができることについてです。
::

## データセットがあなたに与えるもの

2つの記憶された意見は、時間の約38%を失います。 このレッスンの正直な内容です。

::field-table
---
dataset: "leads.csv"
grain: "the attribution columns"
fields:
  - name: "FirstTouchChannel"
    type: "text"
    role: "dimension"
    note: "初めて登場したきっかけ クレジット発見 — ブログ, ドキュメント, オーガニック, アシスタント."
  - name: "LastTouchChannel"
    type: "text"
    role: "dimension"
    note: "変換直前のチャネル。 クレジットクローズ — 通常、支払い、ブランド、またはデモリクエスト。"
  - name: "CampaignId"
    type: "key"
    role: "key"
    note: "リードごとの単一のキャンペーン。 記録されたCRMが何であるか - 練習では、通常、最後のタッチ."
  - name: "SourceCategory"
    type: "text"
    role: "dimension"
    note: "インバウンドマーケティング/アウトバウンド/パートナー/製品。 粗く、4つの最も信頼できる。"
---
::

    description: "機会。 オリジン リード リード → リード. リード 新規取引のみが 1 つ; 拡張および更新はどれも、正しいと空白の Bucket に埋め込まれるのではなく、任意のアトリビューションチャートから除外する必要があります。"
  - title: "最初のタッチ測定をビルドする"
    description: "リードのFirstTouchChannel にグループ化された Sum クローズドウォン マウント。"
  - title: "最後のタッチは同じ方法を測定します"
    description: "同じ測定、LastTouch のグループ化 チャネル。 1つのグループ列チャートで両方のシリーズをプロットします。"
  - title: "同意のフラグを追加します。"
    description: "レシピの式: ファーストタッチ チャンネル != 最後のタッチ チャネル。 今、あなたは、写真の量がモデルの選択に依存する方法を定量化することができます - Namilioでは、それは約38%のリードです。"
  - title: "チャートにモデルを書く"
    description: "タイトルは「第1タッチチャンネル」ではなく「チャネルによる収益」です。 修飾子なしで、番号はデッキで引用され、誰も追跡できない事実になります。"
---
::

::tip{icon="i-lucide-scale"}
**2つのモデルが一致すると、あなたは何か固体を発見しました。** ドキュメント & Quickstartsは通常、開発者がそこに見つけ、そこに戻って来るので、両方で高いスコアをスコアします。 それはあなたが選んだモデルの下で勝つだけチャネルよりも投資のためのはるかに強いケースです。
::
