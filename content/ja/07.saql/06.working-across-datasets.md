# データセット間での作業

SAQL クエリ内で複数のストリームを運ぶことができ、それらを組み合わせることができます。 メカニックは直進する。判断はしない。

## 第一次審査

::warning{icon="i-lucide-git-branch"}
**2つのデータセットが複数のウィジェットを組み合わせる必要がある場合、レシピはそれをすべきです。** ウィジェットのクエリに書かれたjoinは、すべてのビューアのために、すべての読み込みに計算され、データセットやドキュメントを読んだ人には見えない。 2つのダッシュボードは、最終的には少し異なるように実装します。, 両方は、防御可能になります, そして、レビューではなく、会議での議論の面. Query-time の組み合わせは *比較*, ない *モデル*お問い合わせ
::

## 穀物トラップは、ここに続く

データセットとモデリングセクションはすべて、穀物がクエリ内で適用されると言います。 1 列ごとの複数の行で 1 つの列ごとの複数の行で 1 つの列で 1 列ごとの機会にストリームを組み合わせることは、レシピの結合として正確に結合します。, 正確に同じ方法でダブルカウント後、親測定を要約.

::note{icon="i-lucide-ruler"}
**組み合わせる前に両方の穀物を状態に, クエリエディタでは、レシピで.** クエリエディタは、レシピよりも軽く感じます。それは単なるテキストであり、何も再構築されていません。そして、人々がここにチェックをスキップする理由は、その光度は正確にです。 演算は、書いた場所を気にしない。
::

## 実用的な形

パターンは:各ストリームを別々に読み、形づけ、共有キーで結合し、計算します。

```
-- actuals by segment
act = load "Academy_Opportunities";
act = filter act by 'StageName' == "Closed Won";
act = group act by 'Segment';
act = foreach act generate 'Segment' as 'Segment', sum('Amount') as 'Actual';

-- targets by segment (a small, separate dataset)
tgt = load "Academy_Targets";
tgt = group tgt by 'Segment';
tgt = foreach tgt generate 'Segment' as 'Segment', sum('Target') as 'Target';
```

両方のストリームはセグメントごとに1列で既に存在しているので、それらを組み合わせることは何でも乗ることができません。これは、後方を発見するのではなく、意図的に整理するプロパティです。

::tip{icon="i-lucide-check"}
**各ストリームを組み合わせる前に、共有穀物に集計します。** 両側がキー1列の場合、組み合わせは構造で安全です。 これは「参加前に多くの側面を集計する」のクエリエディタバージョンであり、同じ理由で同じ修正です。
::

## 欠落した試合に注意

実際のところ存在するセグメントが、ターゲットから潜在するセグメント、または逆に1つの側面にnullを生成します。 どのような意味を決定: ターゲットのないセグメントは、おそらくサーフェシング価値のあるデータギャップです, 実際のもののないターゲットは何も販売されていないセグメントです。 — 見つかりません, ギャップではありません. サイレントゼロで両方を充填するのは簡単なオプションで、違いを隠します。
