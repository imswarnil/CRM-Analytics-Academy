## 日程表

日付 SAQL 年、四半期、月、週、日、直接グループ化できる部品で、プレーン値ではなく構造化されます。

- **`date('Field_Year', 'Field_Month', 'Field_Day')`** — 比較対象のパーツから日付を作成します。
- **`daysBetween(a, b)`** — スピード・トゥ・リード、デイズ・イン・ステージ、年齢、サイクルタイムの基礎
- **`toDate()` ・ `now()`** — 今日から測定されたもの
- **相対的な範囲** — 「現在の四半期」、「90日を過ぎる」 便利で、クエリを作る *非特徴的*: 同じクエリは、固定レポートに対して再調整する際に、ライブダッシュボードとトラップで正しい、明日の異なる番号を返します。

::note{icon="i-lucide-calendar"}
**あなたがグループ化した日付を常に言います。** 機会は、作成しました, 閉じます, 最終修正とステージエントリーの日付. 異なるものによってグループ化された同じデータセットは、本物的に異なる物語を伝え、クエリ内の関数呼び出しは、選択した読者に、ウィジェットのタイトルのみを伝えます。
::

## ストリング

`lower()` そして、 `upper()` ケースを気にしない比較では、 `trim()` から受けるデータ CSV, `substr()` プレフィックスを抽出し、コンポジットラベルを構築するためのコンファレンス。

::tip{icon="i-lucide-spell-check"}
**比較する前にノーマライズします。** `EMEA`, `emea` そして、 `EMEA ` 3つの異なるグループであり、1つの領域を分割するグループ化は、フォーマットではなく、データの問題のように見える。 クエリに問題がある場合、それは通常、レシピで重要である - それを上流に固定するので、すべてのダッシュボードは修正を継承します。
::

## 数学と条件

期待通りの有形作品。 知っておくべき条件 **`case`**クエリ内の Bucket の仕組みです。

```
q = foreach q generate 'Account' as 'Account',
      (case when 'UtilizationPct' < 55 then "At risk"
            when 'UtilizationPct' > 105 then "Overage"
            else "Healthy" end) as 'Band',
      sum('ARR') as 'ARR';
```

::warning{icon="i-lucide-repeat"}
**お問い合わせ `case` 複数のクエリで表示され、レシピに所属しています。** ウィジェットのドリフト全体に重複するルールをバケット:「リスク」は、1つのダッシュボードで55、もう1つのダッシュボードで60以下、会議で守られない、および解散面を意味します。 変換ノードで1回、全ての画面が同じバンドを継承します。
::

## 数値処理

Nullsは、間違った答えの静かなソースです。

- **`coalesce(a, b)`** — デフォルトを置換します。 deliberately を使う: null をゼロのターンで置き換える "unknown" を "none" に置き換える。
- **`is null` ・ `is not null`** — 明示的なテスト。
- **高品質トラップ** — — — `'Stage' != "Closed Lost"` また、ステージが null である全ての行を削除します。 決して意図せず、発表しません。
