# SAQL クリックすると実行アウト

SAQL ありません SQL 異なるキーワードで。 です。 **ストリーム変換言語**: 各ステートメントは、前のステートメントの結果を取り、それを変換します。 つまり、 *注文注文* of ステートメントクエリプランは、経験をキャッチする構造的な違いです。 SQL スタッフ

## クエリの形状

生成された 1 つを読んで、パターンはすぐに表示されます。

```
q = load "Namilio_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

6つのステートメント、各再割り当て `q`お問い合わせ 負荷、狭い、グループ、計算、順序、限界。

::note{icon="i-lucide-arrow-down"}
**注文は、それがない方法で問題 SQLお問い合わせ** ツイート SQL エンジンはあなたのためのあなたの照会をreorders。 ここでは、パイプラインを文字通り記述しています: グループ化後のフィルタリングは、捨てられた行を集計することを意味します。 初期にフィルターをかけると、いつもより速く、より近いです。
::

## 記憶に価値のある3つのパターン

### 1。 分岐数

細かい穀物では、行数が誤ったことをカウントします。

```
q = foreach q generate 'Segment' as 'Segment',
      unique('OpportunityId') as 'Deals',
      sum('LineAmount') as 'Revenue';
```

Namilio のライン item 穀物はこの本質を作ります: 1,378 行, 677 取引.

### 2。 株式総数

各グループは、クリックして、クリックするだけで、全対比で比較しました。 グループ別 `all` 全体を取得するには、グループごとに比較します。 これは、すべての「収益の割合」ウィジェットの背後にあるパターンであり、それは開く最も一般的な理由です SAQL お問い合わせ

### 3。 期間の比較

2つのフィルタリングされたストリーム、各集約、グループ化に加わりました。この四半期は、最後の四半期のそばにあり、デルタはそれらの間で計算されています。 セクション9のスピードビルドは、この形状を正確に使用しています。

::tip{icon="i-lucide-lightbulb"}
**生成できる構文を記憶しないでください。** クリックしてできる最も近いものをビルドし、切り替える SAQLそこから編集する。 フィールドの正しい参照、正しい引用、および無料の作業スケルトンを取得する — そして、引用は、手書きの場所です SAQL 通常は間違っています:フィールド名のための単一の引用符、文字列値の二重引用符、正確にセキュリティ述語のように。
