# 行レベルのセキュリティと述語

アプリ共有が決定 *ダッシュボードを開くことができる人*お問い合わせ 行レベルのセキュリティが決定 *開いてみると*お問い合わせ 彼らは独立しており、両方が必要です。

## セキュリティの述語

ツイート **セキュリティの述語** データセット自体に付随するフィルタで、ビューアごとに評価され、クエリ時に評価されます。 すべてのウィジェット、すべてのレンズ、すべてのエクスポートに対するすべてのクエリは、他のものの前に適用される述語を持っています。 ダッシュボード側からバイパスすることはできません。

形状は、データセット内の列と現在のユーザーに関する何かの比較です。

::field-table
---
dataset: "common predicate shapes"
grain: "one row per pattern"
fields:
  - name: "Own records only"
    type: "'OwnerId' == \"$User.Id\""
    role: "key"
    note: "最もシンプルで最も一般的な。 それぞれのビューアは、所有する行を表示します。 所有者のユーザ ID は、データセットの列である必要があります。つまり、同期され、レシピのすべての参加を通して実行する必要があります。"
  - name: "By a user attribute"
    type: "'Region' == \"$User.Region__c\""
    role: "dimension"
    note: "ユーザレコードのフィールドにデータセットの列を一致させます。 orgが既にユーザーのフィールドを維持しているとき、そしてそれがそうでないときのメンテナンス責任 - 空白のフィールドは、ビューアがまったく見ていないことを意味します。"
  - name: "Role hierarchy"
    type: "'RolePath' contains \"$User.UserRoleId\""
    role: "dimension"
    note: "マネージャーは、自分の行と下にあるすべての人を見る。 階層はフラットなノードによってデータセットにあらかじめ入力する必要があります。なぜなら、述語はクエリ時に階層を歩くことができません。"
  - name: "Everyone sees everything"
    type: "no predicate"
    role: "measure"
    note: "正当に非敏感なデータに対する正当な選択であり、省略ではなく記述された決定であるべきです。 「私たちは意図的にこれを制限しませんでした」と「誰もそれについて考えていません」は、設定で同じように見える。"
---
::

## フラット ノード、およびなぜそれが存在するのか

ロール階層はツリーです。 述語は比較です。 比較はツリーを登ることができませんので、ツリーは何かに匹敵する必要があります **前へ** データは、レシピの時間でqueriedされます。

::note{icon="i-lucide-git-branch"}
**フラットテンが生成するもの。** 各役割のために、その役割とすべての祖先を含む列は、パスです。 述語は、ビューアーのロールが行のパスのどこに表示されているかを尋ねます。 地方の取締役の役割は、その下にあるすべての担当者のパスに現れますので、彼らはそれらの行を見ます。それは兄弟の地域のパスには現れません。 階層全体の質問は1つの文字列の比較になります。そのため、すべてのクエリで実行するのに十分高速です。
::

これは、セキュリティが設計しなければならない具体的な理由です **前へ** データモデル: 述語は列を必要とし、列はレシピノードを必要とし、ノードは同期しなければならないフィールドを必要とします。 ダッシュボードが構築された後、階層の決定は、レシピを再構築し、すべてのデータセットの下流を意味します。

## セキュリティユーザー

述語が書かれた規則である場合、 **継承の共有** orgの共有決定をしましょう — そして、 **セキュリティユーザー** それを評価するアカウントです。 評価対象のフィールドへのアクセスは異なりますが、見られない場合は、継承は計算できません。

統合ユーザーのように扱います: 狭く、非審議し、文書化します。 両方とも、アクセスが設計の決定ではなく、後に求められている特別なアカウントです。

::warning{icon="i-lucide-lock"}
**述語は閉じられず、正しいデフォルトです。** typo、行方不明の列または空白のユーザーフィールドは、漏れではなく空のダッシュボードを生成します。 誰かが「ダッシュボードはチーム全体に空白になっている」と報告すると、最初に述語を疑って、この方向に壊れたことを感謝します。
::

## みんなをキャッチするトラップ

述語を追加し、自分のダッシュボードは空になります。

何も壊れません。 述語は、 *お問い合わせ* 同様に、あなたのユーザはそれを満たしません - あなたはレコードのどれもを所有しています、あなたの役割はパスの外にあります、あなたの領域フィールドは空白です。 管理者はデフォルトでは免除されません。

::tip{icon="i-lucide-user-cog"}
**免除を意図的に計画する** 自分自身をパニックで広めるのではなく。 述語で示された条件 — ロール、パーミッション、ユーザー属性の分析チームは — 明示的、レビュー可能であり、そのプロファイルを継承する次の人に対する同じ免除を静かに処理しません。
::
