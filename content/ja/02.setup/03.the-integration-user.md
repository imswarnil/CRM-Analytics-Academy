# インテグレーションユーザー

データ同期はそのまま実行しません。 専用のアカウントとして実行 — **統合ユーザ** つまり、アカウントの可視性は、すべての下流の天井です。

::warning{icon="i-lucide-ghost"}
**プラットフォーム全体で最も静かな失敗です。** インテグレーションユーザーがフィールドが見つからない場合、フィールドは到着しません。 同期レポートの成功。 レシピは緑色で実行されます。 データセットビルド。 ダッシュボードは、単にそのフィールドなしで計算される数をレンダリングします。 - 割引なしのマージン、セグメントなしのパイプライン、自信を持って、愚かに間違っています。 どこでも言うことはない。
::

## それが何か

分析に代わってデータを読むために存在する特別な、ライセンスされたアカウント。 それは人ではなく、誰もそれをログインし、その許可は意図的に狭いです。 *フィードバック* 何の分析は、他の何も見ていない必要があります.

そのオブジェクトとフィールドレベルのセキュリティは、したがって、設計決定は、デフォルトでは受け入れません。

## これを最大限に防ぐルール

::tip{icon="i-lucide-clipboard-check"}
**フィールドをレシピに追加するたびに、順番に3つのものを確認します。フィールドはインテグレーションユーザに表示され、フィールドはデータ同期で選択され、選択したので同期が実行されます。** フィールドが不在であることは間違いありません。 それは15秒かかりますし、それはバグのカテゴリ全体を削除します - それ以外の場合は、数を気にしている人の前に、数週間後に表面します。
::

## 狭く同期するが、初期同期

お互いに引っ張る2つの本能は、その両方が正反対です。

**同期 狭い**, すべてのフィールドは、店舗内のすべての実行とスペースに時間を費やすので, オブジェクトは、誰もグループ化しないフィールドの数十に沿って卸売ドラッグを同期.

**初期同期**, スナップショットのデータセットは、時間に同期されたものだけを覚えることができるので. 3月に同期し始めるフィールドは2月の値はありません。 フィールドがトレンド分析に問題が生じている場合は、必要な前にそれを追加します。つまり、現在の状態を保持するオブジェクトから、履歴を埋め戻すことはできません。

::note{icon="i-lucide-scale"}
**それを解決する方法。** ナビゲーション *オブジェクト*, 寛大に *トレンドの日付と寸法*お問い合わせ 高価なフィールドは、通常、長いテキストとまれに使用されている記述的な列です。安価で貴重なものは、日付、所有者、段階、セグメント、および量です。 日付フィールドに疑問がある場合、それを同期させます。
::

## Namilio, コンクリート

市場セクションで構築されるすべてのビルドは、この方法を失うのが簡単なフィールドに残ります。 `Discount` 引用符で、 `CommitState` 使用上の注意 `DeflectedByAI` 場合によっては、 `RootCause` 場合によっては、 `MovementType` ARRスナップショット

::warning{icon="i-lucide-pencil-ruler"}
**ログイン `MovementType` データセットとモデリングセクションのARRの滝は壊れません。** あらゆる動きが消えるので、新しいビジネス、拡大、収縮、そして1つのネット番号に崩壊。 チャートはまだレンダリングされます。 全体がまだ正しい。 インサイト全体が消えて、何も欠けていることを示唆する画面には何もありません。 これは、サイレントパーミッションの失敗が練習のように見えるものであり、このレッスンがコースにある理由です。
