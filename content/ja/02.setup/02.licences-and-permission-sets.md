# ライセンスとパーミッションセット

2つのレイヤーで、異なるレイヤーが失敗します。 ツイート **ライセンス** オルガが買ったものです。 ツイート **許可セット** 誰にでもその名が届くかです。 それらを混乱させ、午後を無駄にします。それらを分離すると、すべてのアクセスの問題が2分の診断になります。

## ライセンスレイヤー

CRM Analytics 販売から別にライセンス Service Cloud、層。 名前は製品名で変更され、再び変更されますので、形状を安定させ、ラベルを検証するために何かとして扱います。

::

::warning{icon="i-lucide-receipt"}
**ライセンスを過ぎても許可できません。** orgが存在しない場合 CRM Analytics タイトル、割り当てる権限、トグルの設定、および回避策はありません。 これは、新しいプロジェクトの最初の会話で確認する価値があります - 「私たちがライセンスされているもの、そして何のユーザーのために」 - 答えは、デザインを変更するので、単なる書類ではありません。
::

## パーミッションセットレイヤー

アクセスは、 **許可セット**プロフィールではなく。 これは、単一の最も一般的な一日の障害です。

::note{icon="i-lucide-shield-alert"}
**システム管理者は許可しません CRM Analytics 何でもアクセスして下さい。** 管理者は、org 内のすべてのレコードを表示でき、まだ何もない Analytics Studio タイルは、分析の許可が、他のように割り当てなければならない許可セットのライセンスを介して到着するので。 それはバグではありませんし、それは監督ではありません。 オルガは管理されていない人々に分析を与え、それを必要としない管理者からそれを見守るものです。
::

セットは、管理者とユーザーとしてペアリングします。

::

## あなた自身のorgのために書き留めるもの

3つの事実、あなたのプロジェクトノートのために渡すものは何でも。 3つを繰り返してお尋ねします。

1. **どの層** orgはライセンスされているため、 Einstein Discovery テーブルの上にあります。
2. **ユーザライセンスの数** 存在し、「営業チーム全体にロールアウト」が天井を持っているので、何が割り当てられます。
3. **管理者セットを保持する人**, そのリストは、他の人が見るものを変更することができますので、.
