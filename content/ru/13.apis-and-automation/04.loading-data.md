# Загрузка данных

Внешние данные API Как все без разъема попадает в CRM Analytics: экстракт склада, файл продавца, веб-сессии Академии и расходы.

## Три шага в порядке

::lesson-steps
---
items:
  - title: "Объявить о работе"
    description: "Создайте запись, описывающую то, что вы собираетесь загрузить: имя набора данных, операцию — перезапись, добавление, добавление, удаление — и метаданные, описывающие поля. Пока ничего не загружено."
  - title: "Загрузить данные по частям"
    description: "Ряды идут вверх как пронумерованные части, а не как одна полезная нагрузка. Каждая часть является частью файла, и нумерация - это то, как платформа собирает их. Большие грузы — это много частей, маленькие — одна."
  - title: "Завершение сигнала"
    description: "Установите статус работы, чтобы указать, что все части отправлены. Только сейчас начинается обработка. Пропуск этого - это провал, который каждый поражает один раз, и он не производит ошибки - части просто сидят там и не появляется набор данных."
---
::

::warning{icon="i-lucide-flag"}
**Молчаливый провал забывает третий шаг.** Декларация удалась, каждая часть была успешно загружена, ничего не было ошибочно — и нет набора данных. Работа, оставшаяся незамеченной, неотличима от работы, которая все еще продолжается. Когда нагрузка «работает, но ничего не производит», проверьте статус работы.
::

## Файл метаданных определяет типы полей

Метаданные, отправленные с декларацией, сообщают платформе, что представляет собой каждое поле: его название, его метка и является ли оно текстом, числом или датой, а также форматами и точностью.

::note{icon="i-lucide-type"}
**Это урок загрузки CSV из раздела подготовки данных в коде.** Те же самые три ошибки, с теми же затратами, и теперь они находятся в файле, который вы контролируете, а не в диалоге, через который вы нажали: дата, объявленная в качестве текста, никогда не может быть изменена, числовой идентификатор, объявленный в качестве меры, будет в конечном итоге кем-то суммирован, и валюта с неправильной шкалой будет удалена в сто раз. Преимущество этого заключается в том, что метаданные являются кодом — они просматриваемы, дифференцируемы и идентичны в каждом запуске.
::

## Операции

::field-table
---
dataset: "load operations"
grain: "one row per operation"
fields:
  - name: "Overwrite"
    type: "replace everything"
    role: "key"
    note: "Самый простой и правильный по умолчанию для умеренного набора данных, перестроенного из источника каждую ночь. Также самый дорогой по мере роста объема, потому что вы отправляете все, чтобы изменить долю."
  - name: "Append"
    type: "add rows"
    role: "measure"
    note: "Для аккумулирования данных — события и шаблон моментального снимка из наборов данных и раздела моделирования, где каждый запуск добавляет новый период, а не пересказывает всю историю."
  - name: "Upsert"
    type: "update or insert by key"
    role: "key"
    note: "Дополнительный вариант, и он полностью зависит от действительно уникального ключа. Ключ, который не является уникальным, тихо сливается с рядами, которые должны быть отдельными, которые всплывают позже в виде слишком низкого количества."
  - name: "Delete"
    type: "remove by key"
    role: "dimension"
    note: "Записи, которые исчезли у источника. Без него перезапись является единственным способом потерять удаленную строку, а конвейер только с приложением ведет записи, которых у источника больше нет."
---
::

## Инкрементный не автоматически лучше

::compare-cols
---
items:
  - title: "Полная перезапись"
    subtitle: "Send everything"
    icon: "i-lucide-refresh-cw"
    pros:
      - "Self-correcting — a bad run is fixed by the next good one"
      - "No key required, no drift possible"
      - "Far easier to reason about at 2am"
    cons:
      - "Wasteful as the dataset grows"
      - "Longer run, larger API footprint"
    verdict: "Right until volume makes it wrong. Start here."
  - title: "Инкрементный восходящий"
    subtitle: "Send what changed"
    icon: "i-lucide-git-pull-request"
    pros:
      - "Fast, small, cheap on API allowance"
      - "Necessary at large volumes"
    cons:
      - "Needs a reliable change marker and a genuinely unique key"
      - "Drifts silently when a change is missed — nothing errors, the dataset is just slightly wrong, forever"
      - "Needs periodic full reconciliation to catch that"
    verdict: "Adopt when volume demands it, with a reconciliation job."
---
::

::tip{icon="i-lucide-check-check"}
**Что бы вы ни выбрали, проверьте количество строк после загрузки.** Прочитайте метаданные набора данных и сравните с тем, что вы отправили. Это несколько строк кода, он работает каждую ночь, и он улавливает частичную нагрузку, которую в противном случае обнаружил бы кто-то, глядя на приборную панель через неделю.
::
