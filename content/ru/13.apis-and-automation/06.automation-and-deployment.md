# Автоматизация и развертывание

Сценарий – это легкая половина. Заставить их работать надежно и сделать изменения рецензируемыми - это половина, которая решает, выживет ли кто-либо из них.

## Расписание и порядок

Ловушка зависимости из раздела подготовки данных хуже со скриптами, потому что скрипт не появляется в собственном мониторе платформы:

::warning{icon="i-lucide-clock-alert"}
**Нагрузка, которая работает после рецепта, который потребляет его, создает приборную панель, которая всегда отстает на один день, успешно, навсегда.** Все сообщает о зеленом. Закажите цепочку явным образом — загрузите, затем синхронизируйте, затем рецепты — с реальным запасом хода, а не с оптимистичными пробелами, и предпочтите работу, которая будет работать. *проверка* Его зависимость завершилась над той, которая только начинается позже и надеется.
::

## Полномочия

Одно правило, применяемое без исключения: **Сценарий никогда не содержит секретов.** Переменные среды, полученные из секретного хранилища или секретного хранилища провайдера CI, выделенного пользователя интеграции и ротации, которым кто-то владеет. Удостоверение в публичном хранилище не смущает, это инцидент.

## Песочница для производства

Перемещение аналитической работы между оргами действительно неудобно: наборы данных являются локальными, идентификаторы отличаются, а панель инструментов, экспортируемая из одной организации, ссылается на вещи, которые могут не существовать в другой.

::tip{icon="i-lucide-map"}
**Автоматизируйте повторяемую часть и сохраните письменный контрольный список для остальных.** приборная панель JSON Они могут быть шаблонизированы и отодвинуты; идентификаторы набора данных, предикаты безопасности и графики обычно требуют внимания. Чек-лист, который честно говорит о том, какие шаги являются ручными, бьет сценарий, который притворяется, что они не являются, и тихо развертывает панель инструментов, указывающую на набор данных, которого не существует.
::
