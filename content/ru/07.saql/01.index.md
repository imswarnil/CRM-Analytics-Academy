# Почему SAQL существующий

Каждый объектив, каждый виджет и каждый запрос приборной панели SAQL Снизу. Нажатие создает его; вы пишете его только тогда, когда интерфейс клика заканчивается.

::note{icon="i-lucide-waves"}
**SAQL Это преобразование потока, а не декларативный запрос.** Каждое утверждение принимает результат предыдущего утверждения и преобразует его, переназначая одну и ту же переменную потока. Оптимизатор не переупорядочивает вашу работу, поэтому **Порядок, в котором вы пишете заявления, - это план, который работает.** Фильтрация после группировки действительно делает агрегированные строки, которые вы собирались отбросить. Это единственное структурное различие, которое ловит людей, которые знают. SQL Хорошо.
::

## Форма

```
q = load "Academy_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Загрузка, узкая, группа, вычисление, порядок, лимит. Шесть заявлений, каждое из которых `q`Каждый потребляет то, что произвел последний.

::warning{icon="i-lucide-eye-off"}
**Что? SAQL Не следует использовать для определения бизнес-метрики.** Определение, записанное в запрос одного виджета, невидимо для тех, кто читает набор данных, рецепт или документацию. Через несколько месяцев он будет вновь открыт кем-то, кто выяснит, почему две панели приборов не согласны, и ни одна из них не ошибется. Форма запросов в SAQLОпределите метрики в рецепте.
::
