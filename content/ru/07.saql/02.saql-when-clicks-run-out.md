# SAQL Когда клики заканчиваются

SAQL не является SQL с различными ключевыми словами. Это а **Язык трансформации потоков**Каждое утверждение принимает результат предыдущего утверждения и преобразует его. Это делает *приказ* План запроса, который является единственным структурным различием, которое улавливает опытный SQL людей.

## Форма запроса

Прочитайте сгенерированный, и шаблон сразу станет виден:

```
q = load "Namilio_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Шесть заявлений, каждое из которых `q`. Загрузка, узкая, группа, вычисление, порядок, лимит.

::note{icon="i-lucide-arrow-down"}
**Порядок имеет значение таким образом, что он не SQL.** А. SQL Двигатель переупорядочивает ваш запрос. Здесь вы описываете трубопровод буквально: фильтрация после группировки означает агрегирование строк, которые вы собираетесь отбросить. Фильтр рано, всегда — он и быстрее, и ближе к тому, что вы имели в виду.
::

## Три шаблона, которые стоит запомнить

### 1. Отличительный счет

При мелком зерне подсчет рядов подсчитывает неверную вещь:

```
q = foreach q generate 'Segment' as 'Segment',
      unique('OpportunityId') as 'Deals',
      sum('LineAmount') as 'Revenue';
```

Зерно из линейного предмета Намилио делает это необходимым: 1378 рядов, 677 сделок.

### 2. Доля от общего

Каждая группа сравнивалась с целым — неловко, нажимая, прямолинейно здесь. Группа `all` Чтобы получить общую сумму, сравните каждую группу с ней. Это шаблон, лежащий в основе каждого виджета «процентного дохода», и это самая распространенная причина для открытия. SAQL Во всяком случае.

### 3. Сравнение периодов

Два фильтрованных потока, каждый из которых агрегировался, затем соединились в группировку — этот квартал рядом с прошлым кварталом, с дельтой, вычисленной между ними. Скоростная сборка раздела 9 использует именно эту форму.

::tip{icon="i-lucide-lightbulb"}
**Не запоминайте синтаксис, который вы можете создать.** Создайте самое близкое, что вы можете, нажав, переключиться на SAQLИ редактировать оттуда. Вы получаете правильные ссылки на поле, правильное цитирование и рабочий скелет бесплатно - и цитирование - это то, где написано от руки. SAQL Обычно все идет не так: одиночные котировки для названий полей, двойные котировки для значений строк, точно так же, как в предикате безопасности.
::

## Когда дотянуться до него и когда не дотянуться

---
items:
  - title: "Достичь SAQL"
    subtitle: "Clicks genuinely cannot express it"
    icon: "i-lucide-code"
    pros:
      - "Share of total, ratios across groups, windowed comparisons"
      - "Multi-step calculations in one query"
      - "Precise control over what the widget asks for"
    cons:
      - "Harder for the next person to maintain"
      - "Easy to embed a business definition where nobody will find it"
    verdict: "Use it, and leave a comment saying what it computes."
  - title: "Не тянуться к SAQL"
    subtitle: "When the recipe is the right place"
    icon: "i-lucide-database"
    pros:
      - "A company-wide metric computed once agrees everywhere"
    cons:
      - "A definition written into a widget query is invisible to everyone else"
      - "Two dashboards with the same metric in SAQL will drift, and neither will be wrong"
    verdict: "If ten dashboards need it, it belongs in the recipe."
---
::

::warning{icon="i-lucide-eye-off"}
**Ловушка технического обслуживания.** Метрика, определенная в рукописном виде SAQL Внутри одного виджета не видно никого, кто смотрит на набор данных, рецепт или документацию. Через несколько месяцев его снова откроет кто-то, пытающийся выяснить, почему две панели приборов не согласны. Использовать SAQL для формирования запроса; используйте рецепт для определения метрики.
::
