# Группировка и окно

Все здесь отвечает на вопрос формы *"Этот ряд, по сравнению с другими"* Это именно то, что не может сделать простая агрегация, потому что агрегация разрушает остальные.

## Группа для всех

Простейший двухуровневый расчет. `group q by all` производит одно ведро, содержащее все, что дает вам общую компанию для сравнения отдельных групп.

```
-- revenue per segment, and each segment's share of the company total
q = load "Academy_Opportunities";
q = filter q by 'StageName' == "Closed Won";
total = group q by all;
total = foreach total generate sum('Amount') as 'Total';
seg = group q by 'Segment';
seg = foreach seg generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
```

Затем два потока объединяются, чтобы каждый ряд сегментов мог видеть общую сумму. Это форма каждого виджета «процентного дохода», и это самая распространенная причина, по которой кто-либо вообще открывает редактор запросов.

::note{icon="i-lucide-percent"}
**Общая доля — это канонический двухуровневый запрос.** Как только вы можете написать его, остальная часть семьи — индекс против среднего, вклад в рост, концентрация верхнего N — это тот же маневр с другой арифметикой.
::

## окно

Функция окна вычисляет через *набор соседних рядов* Не разрушая их. Три применения охватывают практически все:

::field-table
---
dataset: "window calculations"
grain: "one row per pattern"
fields:
  - name: "Running total"
    type: "accumulate in order"
    role: "measure"
    note: "Кумулятивный ARR по месяцам, кумулятивный трубопровод, созданный за квартал. Требуется явное упорядочивание — результат без него бессмыслен, и запрос в любом случае будет успешно выполняться."
  - name: "Moving average"
    type: "smooth a noisy series"
    role: "measure"
    note: "Средняя продолжительность 3 или 7 периодов. Честное сглаживание, когда ежедневные серии слишком шумны для чтения; нечестно, когда шипы были находкой, и вы сглаживали их из виду."
  - name: "Rank within a group"
    type: "partitioned"
    role: "dimension"
    note: "Топ-три представительства на регион, топ-продукт на сегмент. Раздел является важной частью — без него вы получаете один глобальный рейтинг, и каждый ряд в самом маленьком регионе находится внизу."
  - name: "Period over period"
    type: "compare to the previous row"
    role: "date"
    note: "В этом месяце против последнего, как дельта или процент, в одном запросе вместо двух виджетов читатель должен вычесть на глаз."
---
::

::warning{icon="i-lucide-arrow-down-up"}
**Окно без явного заказа - это ошибка, которая не объявляет себя.** Итоги выполнения, период за периодом и ранжирование зависят от порядка строки, и если вы не укажете его, двигатель использует любой порядок, который он произвел — стабильный сегодня, отличный после следующего обновления данных. Цифры меняются, и ничто в запросе не выглядит неправильным.
::

## Разделение — это когда люди ошибаются

Рейтинг представителей *в каждом регионе* Это означает, что окно сбрасывается на регион. Рейтинг всех повторений по всему миру, а затем фильтрация в одном регионе дает вам рейтинги 14, 27 и 31, а не 1, 2 и 3 — арифметически правильный и неправильный для вопроса.

::tip{icon="i-lucide-group"}
**Скажите раздел вслух, прежде чем писать его: «Лучшие три повторения в каждом регионе».** Фраза «в каждом» — это раздел. Если в предложении нет «в каждом», вам, вероятно, вообще не нужно окно — подойдет простая группа и порядок.
::

## Когда окно не тот инструмент

::compare-cols
---
items:
  - title: "Окно в запросе"
    subtitle: "Exploratory, per widget"
    icon: "i-lucide-code"
    pros:
      - "No recipe change, immediate"
      - "Right for a one-off comparison on one dashboard"
      - "Keeps the underlying dataset general"
    cons:
      - "Recomputed on every load, for every viewer"
      - "Invisible to anyone reading the dataset"
    verdict: "Fine for one widget. Not for a company metric."
  - title: "Precompute в рецепте"
    subtitle: "Shared, and defined once"
    icon: "i-lucide-database"
    pros:
      - "Computed once overnight rather than per view"
      - "Every dashboard gets the same definition"
      - "Much faster on a dashboard many people open"
    cons:
      - "Another column, another rebuild to change"
    verdict: "Anything more than one widget needs belongs here."
