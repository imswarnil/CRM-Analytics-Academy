# Бег и устранение неполадок Dataflow

Вы нажали «Создать набор данных», который **выполняет поток данных**. Теперь давайте посмотрим, как он работает, поймем, что он на самом деле делает, и исправим ошибку, которая ловит почти всех в первый раз.

## Что «управляет потоком данных» на самом деле

Когда Dataset Builder пишет в **поток данных по умолчанию**Он не только строит *твой* Dataset — работает **все** в этом потоке данных. В обучающей организации, которая не пуста: она поставляется с другими наборами данных и инструкциями. Таким образом, запуск потока данных по умолчанию выполняет все это, а не только набор данных возможностей, который вы только что разработали.

::tip{icon="i-lucide-git-branch"}
Именно поэтому опытные строители в конечном итоге создают свои **собственный** потоки данных. Единый общий поток данных по умолчанию означает, что каждая сборка перезапускает все. По мере роста вы будете разделять работу на названные потоки данных (или рецепты), чтобы каждый из них обновлял известный набор наборов данных по своему собственному графику.
::

Направляйся **Data Manager Монитор** И вы увидите, что ваш поток данных по умолчанию работает.

## Классическая ошибка первого запуска

На совершенно новой организации — или в первый раз, когда вы запустите это — поток данных может **Неудача с ошибкой**. Не паникуйте. Причина почти всегда проста: поток данных запрашивает объекты, которые **еще не был втянут в синхронизирующий слой**.

Запомните цепочку: поток данных считывает из **Подключение/Sync**не от Salesforce напрямую. Если Connect не заполнил Учетную запись, Возможность и Пользователя, потоку данных нечего читать, и он ошибается.

## Забыл поле? Редактировать узел дайджеста

Потому что ты не можешь снова открыть Dataset Builder Выбор поля, редактирование полей позже происходит в **узлы дайджеста потока данных**.

- Откройте поток данных, щелкните соответствующий узел дайджеста (скажем, **Счет**), и повторно добавить поле через **Выберите поля**.
- При этом, когда и когда, то, по желанию, **распространять** Поле вплоть до конечного узла регистрации — в противном случае оно останавливается на полпути и никогда не достигает вашего набора данных.
- Обновление и **снова запустить поток данных** Таким образом, новое поле материализуется.

Мы охватываем дайджест-узлы, атрибуты поля и правильное редактирование потока данных в Data Manager Уроки — этого достаточно, чтобы развязать вас.

## Вы создали свой первый набор данных

Как только поток данных завершится зеленым, перепрыгните обратно в Analytics Studio и вот он — ваш набор данных о возможностях, сидящий в вашем частном приложении, готовый к изучению. На ландшафтной диаграмме он теперь живет в **слой набора данных**, построенный потоком данных, который считывает из синхронизации.

::tip{icon="i-lucide-check-check"}
Ментальный контрольный список, когда поток данных выходит из строя: **(1)** Являются ли исходные объекты синхронизированными? **2)** Соединение действительно закончилось до того, как начался поток данных? **3)** Каждое поле, которое вам нужно, распространяется на регистровый узел? На девять из десяти неудач первого этапа отвечают эти три вопроса.
::

Dataset Builder дружественный, но он запирает вас в поиске и потоке данных. Далее мы строим **Точно такой же набор данных** с одним **рецепт** Больше кликов вперед, больше контроля и направление, в котором движется платформа.
