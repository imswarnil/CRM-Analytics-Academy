# Проектирование набора данных

Начните с вопросов, а не со столов. Таблицы говорят вам, что возможно; вопросы говорят вам, что построить.

## Дизайн из четырех вопросов

::lesson-steps
---
items:
  - title: "Запишите вопросы, на которые он должен ответить"
    description: "Пять или шесть на простом языке. Какие сегменты удерживают нашу ARR? Какие сделки застряли дольше всего Если вы не можете их перечислить, вы создаете копию исходной таблицы, а не набор данных."
  - title: "Вырвать зерно из лучшего вопроса"
    description: "Если какой-либо вопрос касается отдельных сделок, зерно составляет один ряд за сделку. Если речь идет о ежемесячных суммах по сегментам, это может быть один ряд на сегмент в месяц, и это будет намного быстрее."
  - title: "Перечислите столбцы, в которых нуждается каждый вопрос"
    description: "Размеры для группирования, меры для агрегирования, даты для тренда. Все, что не отвечает на перечисленный вопрос, является кандидатом на исключение: каждая дополнительная колонка стоит времени и затрудняет чтение списка поля для следующего человека."
  - title: "Решить, что навсегда исключено"
    description: "Тестовые записи, внутренние счета, продуктовая линейка, о которой никто не сообщает. Если строка никогда не должна появляться в каком-либо ответе, который дает этот набор данных, отфильтровать его здесь, а не просить каждую панель инструментов запомнить."

    note: "Тестовые учетные записи, удаленные записи, сегмент, который не является частью цели этого набора данных. Никто не должен быть в состоянии исключить их, очистив контроль, и каждый потребитель наследует исключение, не зная, чтобы спросить."
  - name: "In the widget's query"
    type: "this widget always"
    role: "measure"
    note: "«Открытый трубопровод» никогда не должен показывать закрытые сделки, потому что кто-то сбрасывает фильтр. Структура виджета, а не набора данных, потому что другой виджет на том же наборе данных законно хочет эти строки."
  - name: "On the dashboard"
    type: "exploratory"
    role: "dimension"
    note: "Период, регион, сегмент — вещи, которые зрители должны уметь менять. Если фильтр — это контроль, то он здесь."
---
::

::warning{icon="i-lucide-filter-x"}
**Фильтр в наборе данных невидим для всех ниже по течению.** Это его ценность и риск: аналитик, сравнивающий ваш набор данных с источником, найдет разницу и не сможет понять, почему. Поместите каждый фильтр уровня набора данных в описание набора данных — «исключает тестовые учетные записи и внутреннюю организацию песочницы» — или вас спросят о несоответствии несколько раз.
::

## Один набор данных или два?

Искушение всегда заключается в расширении существующего. Два сигнала, которые вы должны разделить:

::compare-cols
---
items:
  - title: "Раскол"
    subtitle: "Different grain, or different purpose"
    icon: "i-lucide-split"
    pros:
      - "Each is simple enough to reason about"
      - "The daily dashboard gets a fast pre-aggregated dataset while exploration keeps the detail"
      - "One recipe can produce both outputs, so the logic is still defined once"
    cons:
      - "Two things to schedule and monitor"
    verdict: "Usually right when the grains genuinely differ."
  - title: "Виден"
    subtitle: "Add columns to the existing one"
    icon: "i-lucide-move-horizontal"
    pros:
      - "One thing to maintain"
      - "Fine when the new questions live at the same grain"
    cons:
      - "A dataset serving everybody eventually serves nobody well"
      - "Sixty columns of which fifteen matter is hostile to self-service"
    verdict: "Right only while the grain and purpose still match."
---
::

::tip{icon="i-lucide-git-branch"}
**Два вывода из одного рецепта являются недоиспользованным вариантом.** Соединения, очистка и определения происходят один раз; затем рецепт записывает подробный набор данных и агрегированный. Вы получаете скорость там, где это важно, и детали там, где это необходимо, без двух копий логики, дрейфующей врозь.
::

## Напишите зерно в описании

Каждый набор данных, одно предложение: *Один ряд за возможность для продукта*. Это пять секунд работы и самое полезное, что кто-либо читает ниже по течению — разница между коллегой, подводящим правильную колонку и подводящим дублированную, никогда не зная.
