# 跨数据集工作

SAQL 在查询中可以携带不止一个流并结合它们. 力学是直截了当的;判断不是。

## 判决第一

::warning{icon="i-lucide-git-branch"}
**如果两个数据集需要组合一个以上的部件,则配方应该这样做。** 输入一个部件查询的组合在每一个负载上被计算出来,每个浏览器,任何人读取数据集或其文档都看不见。 两个仪表板最终会稍有不同地执行,两者都是可辩驳的,分歧的出现是在会议而非审查中. 查询时间组合用于 *比较*,不用于 *模型*。 。 。 。
::

::note{icon="i-lucide-ruler"}
**在合并之前,在查询编辑器和食谱中都说明两种谷物。** 查询编辑器感觉比一种配方轻——它只是文字,没有任何东西正在重建——而轻度正是人们在这里跳过支票的原因. 算术不在乎你写在哪里
::

## 实际形状

模式是:装入并分别塑造每个流,然后在一个共享的密钥上结合,然后计算.

```
-- actuals by segment
act = load "Namilio_Opportunities";
act = filter act by 'StageName' == "Closed Won";
act = group act by 'Segment';
act = foreach act generate 'Segment' as 'Segment', sum('Amount') as 'Actual';

-- targets by segment (a small, separate dataset)
tgt = load "Namilio_Targets";
tgt = group tgt by 'Segment';
tgt = foreach tgt generate 'Segment' as 'Segment', sum('Target') as 'Target';
```

两条溪流已经是每段一行,所以结合它们不能乘以任何东西——这就是有意安排而不是事后发现的财产.

::tip{icon="i-lucide-check"}
**结合前将每条溪流集合到共享的谷物中.** 如果双方每键为一排,组合通过构造是安全的. 这是查询编辑版的"集合加入前的多个侧面",出于同样的原因,它是相同的固定.
::

## 缺少匹配的注释

以实际值显示但未出现在目标中,或相反,一方将产生无值值。 决定那意味着什么:一个没有目标的片段很可能是一个值得浮出水面的数据缺口,而一个没有实际数据的目标则是一无所获的片段——这是一个发现,而不是缺口. 以零声无声地填充两者是容易的选择,它隐藏了区别.
