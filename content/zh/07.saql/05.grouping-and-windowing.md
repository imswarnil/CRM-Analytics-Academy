# 组合和窗口

这里的一切都回答了一个形式问题 *"这排,比起其他的"* 这恰恰是纯粹的汇总无法做到的,因为汇总会使其他人崩溃。

## 分组

最简单的两级计算. `group q by all` 生产一个装满一切的桶, 这给你一个公司总数来比较个人群体。

```
-- revenue per segment, and each segment's share of the company total
q = load "Namilio_Opportunities";
q = filter q by 'StageName' == "Closed Won";
total = group q by all;
total = foreach total generate sum('Amount') as 'Total';
seg = group q by 'Segment';
seg = foreach seg generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
```

然后两条溪流合并,使每个段行都能看到总数. 这是每个“ 收入百分比” 部件背后的形状, 这是最普遍的原因 任何人打开查询编辑器 。

::note{icon="i-lucide-percent"}
**占总数的份额是Canonical双层查询.** 一旦你能够写出来,家庭的其余部分——指数相对于平均,对增长的贡献,N顶级的集中——就是与不同的算术相同的动作.
::

## 窗口

窗口函数计算横跨 a *相邻行集* 不让他们崩溃。 三种用途几乎覆盖一切:

::field-table
---
dataset: "window calculations"
grain: "one row per pattern"
fields:
  - name: "Running total"
    type: "accumulate in order"
    role: "measure"
    note: "按月计算累计ARR,在四分之一内建立累计输油管. 需要明确命令——没有命令的结果是毫无意义的,而且查询无论如何都会顺利进行."
  - name: "Moving average"
    type: "smooth a noisy series"
    role: "measure"
    note: "3或7个时期的后期 诚实的平滑,当一个日常的系列太吵 阅读;不诚实,当 钉子是发现, 你平滑了它们 的视线。"
  - name: "Rank within a group"
    type: "partitioned"
    role: "dimension"
    note: "每区前三名代表,每段产品最高. 分区是一个重要的部分——没有它,你就获得一个单一的全球排名,最小区域的每一行都坐落在底部."
  - name: "Period over period"
    type: "compare to the previous row"
    role: "date"
    note: "本月, 作为三角洲或百分比, 在一个查询中而不是两个部件中, 读者必须用眼睛减去。"
---
::

::warning{icon="i-lucide-arrow-down-up"}
**没有明确命令的窗口是不会宣布自己的错误.** 运行总和,跨期和排位都取决于行顺序,如果不指定它,引擎使用它所产生的任何顺序——今天稳定,在下一次数据刷新后不同. 数字变化和查询中的任何内容看起来都是错误的。
::

## 分尸是人们错的

排名代表 *每一区域内* 表示每个区域的窗口重排. 将所有代表排在全球,然后过滤到一个区域,使你排在第14、27和31位,而不是第1、第2和第3位。

::tip{icon="i-lucide-group"}
**在写前大声说分界线:"每个地区最好的三个代表".** "各"字为分区. 如果句子没有"每句",你可能根本不需要窗口——一个普通的组和一个命令就可以了.
::
