# 调试查询

错误的查询会告诉你在哪里找。 一个返回错误答案的查询告诉你什么也没有,这就是值得有一个方法的情况。

## 方法

::lesson-steps
---
items:
  - title: "切回负载"
    description: "删除后所有内容 `load` 并检查行数与数据集应持有的值。 如果这已经是错误的,问题在于上游,没有多少查询编辑会解决."
  - title: "一次添加一个声明"
    description: "重新添加过滤器,然后组合,然后放出,检查计数和每个计数后的样本值. 数字停止的语句是带有bug的语句. 这大约需要两分钟,并取代一小时的视线."
  - title: "缩小为一个实体"
    description: "过滤到一个单一的账户或机会,你可以用手数。 集合不能告诉你是哪一边的乘数;屏幕上的六行可以."
  - title: "把它当输油管读,大声说出来"
    description: "把所有东西都拿走, 保持闭路, 分组,总和。 大声说,在错误的地方过滤器或缺失的明显计数通常会在你完成句子之前变得明显."
---
::

## 业绩,简要

最慢的询问有以下三个原因之一:

1. **过滤迟到 。** 行合并,然后丢弃。 将过滤器上移.
2. **每次装货都装满精美的谷物** 如果很多人每天打开这个,在食谱中预先汇总.
3. **在查询中处理食谱中属于什么 。** 加入和衍生字段重算每个视图,每个视图.

::tip{icon="i-lucide-gauge"}
**以正常的用户,而不是以你自己的方式衡量。** 管理员可能会跳过一个真正的浏览者为每个查询付费的安全评价,所以对于实际使用的人来说,一个感觉很快的仪表板会明显地慢一些.
::

## 请留言

手写查询可以生存到一个运来的仪表板上,应该说明它计算了什么,为什么它不在食谱中. 一行经. 这是下一个人理解它和下一个人重建旁边的仪表板的区别.
