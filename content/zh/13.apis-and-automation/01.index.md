# 分析可以自动化

数据集、查询、仪表板和元数据都可以在程序上达到。 这使得一套手工杂务变成了预定的工作,它把仪表板变成了可以生成而非手工制造的东西.

::note{icon="i-lucide-shield-check"}
**那个 API 不是绕过安全模式的路** 请求认证为用户,且用户的权限设定,共享和行级安全与界面中一样适用. 一个作为集成账户运行的脚本可以看到该账户能够看到什么——这是正确的行为,值得直截了当地说明,因为"只要使用该账户. API" 偶尔作为准入问题的一种变通办法。 这不是一个。
::

## 什么是应该保持手动

::warning{icon="i-lucide-hand"}
**自动化一个你每年做两次的事情是一种责任。** 剧本腐烂,其资历过期,写作者在下一次运行时已经忘记了它——因此年度任务变成了"调试一个12个月内无人看过的剧本",而不是"花一个小时点击". 每周发生或更频繁发生的事情 或每次必须相同的事情 其他东西用手都便宜
::

设计工作是另一类。 一个仪表板的布局,它的拒绝和标题是判断性的,从一个模板中生成它们产生40个屏幕,这些屏幕始终是平庸的而不是正确的.
