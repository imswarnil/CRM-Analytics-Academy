# 自动化和部署

剧本是轻松的一半. 让他们可靠运行,并让变化可以审查,是决定其中任何一种是否存活的一半.

## 时间安排和顺序

数据准备部分的依赖性陷阱与脚本相比更为糟糕,因为一个脚本不出现在平台自己的显示器中:

::warning{icon="i-lucide-clock-alert"}
**在食谱之后运行的负载 会产生一个总落后一天的仪表盘 成功 永远** 一切报道绿色。 明确排序链条——装货,然后同步,然后配方——与真正的头室而不是乐观的缺口,更喜欢一种工作, *检查* 它的依赖性完成了一个仅仅开始于后来和希望。
::

## 全权证书

一项规则毫无例外地适用: **剧本里没有秘密** 环境变量来源于一个秘密商店或CI提供者的秘密存储,一个专用的集成用户,以及某人拥有的旋转. 在公共存放处的证明不是尴尬的,而是意外。

## 沙盒待生产

在Orgs之间移动分析工作是真正尴尬的:数据集为Org-local,IDs不同,从一个Org参考物中导出一个可能不存在在另一个参考物的仪表板.

::tip{icon="i-lucide-map"}
**自动化可重复部分,并为其余部分保留书面核对表。** 电线板 JSON 可以被模板和推; 数据集 ids, 安全上游和调度通常需要注意每个org. 一个诚实的、手动步骤的核对表会击败一个假装没有步骤的脚本,并默默地部署一个指向不存在的数据集的仪表板。
::
