# 奥尔格设置和推出

手接前还有两件事: 交换机, 和把它摆在人们面前 没有坏的第一个星期。

## 推出:工作顺序

技术工作是在收养工作之前很久完成的。 下面的顺序不是官僚主义——每个步骤之所以存在,是因为跳过它会产生具体的,可预测的失败:

::field-table
---
dataset: "rollout sequence"
grain: "one row per step"
fields:
  - name: "1 — Two or three real users"
    type: "before anything else"
    role: "key"
    note: "将做出决定的人 仪表板支持。 不是委员会,也不是观众 他们会在10分钟内告诉你屏幕是否回答了他们的问题,而反馈比任何内部审查都值钱."
  - name: "2 — Verify as them, not as you"
    type: "the non-negotiable step"
    role: "key"
    note: "作为限制用户登录 。 管理者能看见一切 所以任何安全错误 对建造它的人来说都是隐形的 这就是一个仪表板如何在观众面前空空地到达——或者显示另一个地区的交易."
  - name: "3 — One team"
    type: "a week or two"
    role: "dimension"
    note: "现在问题从\"这是权利\"变成\"我如何使用它\". 这就是你发现哪些标签是模糊的, 哪些部件每个人都读错了。"
  - name: "4 — Everyone who needs it"
    type: "with the definitions attached"
    role: "dimension"
    note: "在仪表板旁边运输测量定义。 一个没有定义的数字在第一次与某人的电子表格产生分歧时就成为一个论据——它将会。"
  - name: "5 — A named owner"
    type: "permanent"
    role: "measure"
    note: "有人拥有时间表,定义和请求. 一个无人拥有的仪表板会悄悄地退化:食谱漂移,一个字段会改变意义,信任在任何人提出罚单之前就会发生."
---
::

## 人们实际上问的两件事

::compare-cols
---
items:
  - title: "' 为什么这个号码不一样?  '"
    subtitle: "Asked within the first week, always"
    icon: "i-lucide-equal-not"
    pros:
      - "Almost always a definition difference, not an error"
      - "Answerable in seconds if the metric spec exists"
    cons:
      - "Without a written definition it becomes a multi-day investigation, and trust drops while it runs"
    verdict: "Publish the definitions with the dashboard. Every time."
  - title: "' 这是直播吗?  '"
    subtitle: "Asked the moment a number looks wrong"
    icon: "i-lucide-clock"
    pros:
      - "A visible 'last refreshed' timestamp answers it permanently"
      - "Costs one text widget"
    cons:
      - "Without it, every staleness question becomes a personal support request to you"
    verdict: "Put the refresh time on the dashboard."
---
::

::tip{icon="i-lucide-timer-reset"}
**任何生产仪表板上唯一价值最高的部件** 是一个文本框,显示数据上次刷新时。 它转移了整个问题类别,使实现是诚实的而不是隐蔽的,需要两分钟的时间来补充.
::

## 前进的方向

- 先在安全的地方启用新东西,然后写下您启用的东西 。
- 在别人看到它之前,作为受限制的用户进行校验——这是协作部分一直坚持的习惯.
- 船的定义和每个仪表板的更新时间戳
- 给每个仪表板一个主人, 或者期望它腐烂。
