# 行级安全和优先级

应用共享决定 *谁能打开仪表板*。 。 。 。 行级安全决定 *他们看到它打开后*。 。 。 。 他们是独立的, 你需要两者。

## 安全前提

页:1 **安全前提** 是数据集本身所附的过滤器,每个查看器在查询时间进行评估。 针对该数据集的每一个查询——每一个部件,每一个镜头,每一个导出——在其它事情发生之前都应用了上游. 它不能绕过仪表板一侧,这正是你想要的财产.

该形状是对数据集中的一列和当前用户的某物的比较:

::field-table
---
dataset: "common predicate shapes"
grain: "one row per pattern"
fields:
  - name: "Own records only"
    type: "'OwnerId' == \"$User.Id\""
    role: "key"
    note: "最简单最常见的 每个观众可以看到他们拥有的行. 要求所有者的用户ID成为数据集中的一列——这意味着它必须同步,并且通过食谱中的每一个加入来携带."
  - name: "By a user attribute"
    type: "'Region' == \"$User.Region__c\""
    role: "dimension"
    note: "将数据集列匹配到用户记录中的字段。 当Org已经维持了该字段对用户,当它没有维护责任时——空白字段意味着查看者什么都看不到."
  - name: "Role hierarchy"
    type: "'RolePath' contains \"$User.UserRoleId\""
    role: "dimension"
    note: "经理看到自己的排和下面的所有人 需要由平坦的节点预先计算到数据集中的层次,因为一个上游无法在查询时行走层次."
  - name: "Everyone sees everything"
    type: "no predicate"
    role: "measure"
    note: "真正非敏感数据的正当选择,应该写下决定,而不是遗漏。 \"我们故意没有限制这个\" \"没有人想过它\" 在配置上看起来是一样的。"
---
::

## 平坦的节点,为什么它存在

角色等级是树. 上游是比较. 比较一下不能爬树 所以树必须被扁平成相当的东西 **在此之前** 在食谱时间询问数据。

::note{icon="i-lucide-git-branch"}
**平坦的产生。** 对于每一个角色来说,一个包含这个角色及其所有祖先的专栏——一条道路. 上游则询问观众角色是否出现在行路的任何地方. 区域主任的作用出现在他们下面的每一个代表的道路上,所以他们看到这些行;它没有出现在兄弟地区的道路上,所以没有出现。 整个等级问题变成了一个字符串比较,这就是为什么它足够快地运行在每个查询上.
::

这就是设计安全的具体原因 **在此之前** 数据模型:上游需要一列,列需要一个食谱节点,节点需要必须同步的字段. 在仪表板建成后确定等级意味着重建食谱及其下游的每一个数据集.

## 安全用户

如果上游是你写的规则, **分享遗产** 让兽人自己分享决定 **安全用户** 是用来评价它的账户。 它需要进入评价所依赖的领域,如果它看不到这些领域,则不能计算继承。

视之为集成用户:狭义,刻意,且有文献记载. 这两个账户都是专门账户,其访问是设计决定,而不是事后考虑。

::warning{icon="i-lucide-lock"}
**预测失败关闭,这是正确的默认。** 一个打字,一个缺失的列或空白的用户字段会产生一个空的仪表板而不是漏出. 因此,当有人报告"仪表板对于整个团队来说是空白的"时,首先怀疑上游——并感激它朝这个方向突破.
::

## 抓住每个人的陷阱

你加一个上游, 和你自己的仪表板去空。

无有破坏. 上游评价为: *老师* 还有,而你的用户并不满足它——你没有拥有任何记录,你的角色在路径之外,你的区域域是空白的. 管理员不因默认而免除.

::tip{icon="i-lucide-user-cog"}
**计划豁免** 而不是在恐慌中给自己一些宽广的东西。 上游中一个被命名的条件——一个角色,一个许可,一个用户将分析团队所携带的属性——是明确的,可审查的,并且不会悄悄地将同样的豁免交给继承该配置的下一个人.
::
