# 整合用户

数据同步不会像你一样运行 。 它作为一个专用账户运作—— **集成用户** 这个账户的能见度是下游所有东西的上限。

::warning{icon="i-lucide-ghost"}
**这是整个平台中最安静的失败.** 如果集成用户无法看到一个字段,则该字段不会到达. 同步报告成功。 菜谱是绿色的。 数据集构建. 仪表板使一个没有这个字段就简单的计算出来的数字——一个没有折扣的比值,一个没有段的管道,这个总数充满信心,完全错误。 任何地方都没有这么说。
::

## 这是什么

一个特殊,许可的账户,存在用来代表分析员读取数据. 它不是一个人,没有人登录它,它的权限是故意缩小的:它需要 *读* 分析家必须看到什么,别无他法。

因此,其对象和场级安全是设计决定,而不是默认接受:

## 阻止大多数事情发生的规则

::tip{icon="i-lucide-clipboard-check"}
**每当在食谱中添加一个字段时,请确认三件事,顺序是:字段对集成用户可见,字段在数据同步中被选择,同步自你选中后运行.** 任何一位小姐和球场缺席。 它需要15秒,它清除了一整类的bug——一个在几周后浮出水面的,在关心数字的人面前.
::

## 同步缩小, 但同步提前

两种本能相互牵制,两者部分正确.

**同步缩小**因为每个额外的现场花费时间 在商店的每一个运行和空间, 以及一个同步的 批发的物体拖累 沿着数十个田。

**提前同步**,因为快照数据集只能记住当时同步的内容. 三月开始同步的字段没有二月值,永远不会有. 如果一个字段对趋势分析有合理意义,在您需要它之前加上它——历史不能从一个只保持当前状态的对象中回填.

::note{icon="i-lucide-scale"}
**如何解决.** 缩小 *对象*慷慨无私 *日期和维度*。 。 。 昂贵的字段通常是长的文字和很少使用的描述栏;廉价和有价值的字段是日期、所有者、阶段、部分和金额。 当对一个约会字段产生疑问时,请同步它.
::

## 学院,具体来说

上市区的每一块建筑都建立在容易输掉的田地上: `Discount` 以引言盟誓, `CommitState` 关于用法, `DeflectedByAI` 关于案件, `RootCause` 关于案件, `MovementType` 在ARR的快照。

::warning{icon="i-lucide-pencil-ruler"}
**输了 `MovementType` 而数据集和建模部分的ARR瀑布并没有断裂——它是扁平的.** 每一个运动都变得无法区分,所以新的业务,扩张,收缩和骨折都变成了一个净数. 图表仍然有效。 总数仍然是正确的。 整个洞察力已经消失,屏幕上没有任何东西可以暗示缺少任何东西. 这就是一个沉默的许可失败在实际中的样子,这就是为什么这一教训正在上路。
::
