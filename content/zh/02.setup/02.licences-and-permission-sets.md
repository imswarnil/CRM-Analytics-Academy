# 许可证和权限集

两层,它们失败的方式不同。 页:1 **许可证** 兽人买的 页:1 **权限设置** 这项权利是如何惠及一个人的。 在一个下午把废物混为一谈;把它们分开,每一次接触都会产生两分钟的诊断。

::warning{icon="i-lucide-receipt"}
**你不能允许你通过许可证。** 如果兽类没有 CRM Analytics 没有设定指定权限,没有设定切换,也没有工作。 这值得在任何新项目的第一次对话中确认——"我们获得什么许可,以及有多少用户"——因为答案改变了设计,而不仅仅是文件工作.
::

## 权限设置层

访问由 **权限设置**,而不是通过剖析。 这是第一天最常见的障碍。

::note{icon="i-lucide-shield-alert"}
**系统管理员给予无 CRM Analytics 随便你** 管理者可以看到每个记录在 Org 中,仍然没有 Analytics Studio 平板,因为分析权限通过许可证设定到达,这些许可证必须像其他任何许可证一样分配。 它不是虫子,也不是监督;它让一个兽人给那些不是管理员的人分析,并且不让那些不需要它的人去分析。
::

设置为管理员和用户,每级:

## 自己写什么

3个事实,不管你的项目说明是什么 你会被反复询问所有三个:

1. **哪个级别** 矿石是否获得许可,以及是否 Einstein Discovery 已经上桌了
2. **有多少用户许可证** ,以及分配了多少——因为"推出给整个销售团队"有一个上限.
3. **谁负责管理**因为名单可以改变别人所看到的
