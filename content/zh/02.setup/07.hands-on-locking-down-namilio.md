## 语法,因为这是常见的绊倒

```
'Region' == "$User.Sales_Region__c"
```

**单引号** 包裹数据集列。 **双引号** 覆盖用户属性。 非对称性是语法如何将一个列和一个值区分开来,反转它就是您至少要犯一次的错误.

混合条件使用 `||` 用于或 `&&` 用于:

```
'Region' == "$User.Sales_Region__c" || "$User.Sales_Region__c" == "ALL"
```

::warning{icon="i-lucide-spell-check"}
**预测精确比较字符串 。** `EMEA`, (中文). `emea` 和 `EMEA ` 后面的空间是三个不同的区域。 如果一个上游返回什么也没有,而语法是正确的,请在用户记录上打印列的不同值和值,并按字符比较. 这是继空白字段之后的第二常见原因,它看起来与一个破规则完全相同.
::

## 为什么这里有用户属性和生产中的等级

此课在用户记录上使用一个字段,因为它使机制显眼:一个列,一个比较,一个地方,当它行为不当时可以查看.

多数制作人最终想要角色等级,一个管理者看到他们下面的一切,没有人在数百个用户上维持一个区域域. 这需要一个平整的节点 在食谱, 这是数据准备部分的材料。 机制是相同的;只有上游与变化相比较的栏。

::tip{icon="i-lucide-notebook-pen"}
**今写四行.** 哪个数据集有上游, 每个人在英语中都说, 谁被豁免, 如何, 和什么是后退。 今天需要两分钟,为继承矿石的人节省一个星期的时间——可能是你忘记了。
::
