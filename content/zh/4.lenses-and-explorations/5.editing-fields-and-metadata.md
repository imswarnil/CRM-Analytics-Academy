# 编辑字段和数据集元数据

在刚建成的数据集上打开一个镜头 看起来很粗糙 尺寸叫做 `AccountId.Name` 和 `StageName`。 。 。 数量显示为没有货币符号的赤色数字和八位小数。 你各个阶段的图都选了不同的颜色

这一切 **数据集元数据**,然后从一个镜头内部——通过 **字段** 显示面板。

::tip{icon="i-lucide-triangle-alert"}
仔细阅读: 字段面板确实如此 **没有** 编辑镜头。 它编辑 **数据集**。 。 。 。 您在此保存的每个更改都适用于该数据集 **到处都是** ——每一个现有的镜头,每一个仪表板,每一个故事,每一个用户. 这就是它的力量所在,这也是为什么你应该把它当作一种刻意的行为而不是一种化妆品的修饰.
::

你需要那个 **管理分析** 或 **编辑数据流** 允许进行这些编辑。 没有它,菲尔兹面板只读。

## 打开球场面板

从一个开放的镜头,寻找 **字段** 选项(通常是在镜头菜单中或与字段列表一起)。 它列出了数据集中的每个字段, 并分为 **尺寸**, (中文). **措施**,以及 **日期**。 。 。 。 选择一个字段及其设置出现在右边。

四事值汝时.

## 一、导 言 值表的默认字段

当有人打开这个数据集并切换到一个 **数值表**他们应该先看哪个栏?

左撇子,你可以得到数据集所建的顺序——常常是前部的ID和系统字段. 在字段面板中,您可以设置 **默认字段**: 选择实际讲述故事的几列( 账户名称、 舞台、 关闭日期、 数量、 拥有者) 并设定顺序 。

其变化小,影响大. 每一个打开数据集的同事现在都从可读的东西开始,而不是从18个特征的墙壁开始。

## 2. 重新标注维度

选择一个尺寸并编辑其 **标签**。 。 。 。 `AccountId.Name` 变成 **账户名称**。 。 。 。 `StageName` 变成 **阶段**。 。 。 。 `Owner.UserRole.Name` 变成 **销售角色**。 。 。 。

这是这个课中价值最高,功率最低的东西. 标签是字段拾取器,图表轴,传奇,工具提示,和表格头中出现的内容——任何地方都有商业用户阅读. 没人该知道你的物体模型 才能使用你的仪表板

::tip{icon="i-lucide-info"}
重新标签更改 **仅标签**。 。 。 。 那个 **API 名称不变** 高级/高级SAQL 模式你仍然会写 `'AccountId.Name'`没有 `'Account Name'`。 。 。 。 约束和过滤定义相同。 如果一个 SAQL 重新标签后的查询中断, 重新标签不是原因; 查看其它地方 。
::

## 3个 编辑值和指定颜色

扩展一个维度,你可以看到它 **数值**,对每一个设置 **颜色**。 。 。 。

这就是你得到的 **在您 Org 的每个图表中, 颜色一致且有意义的**。 。 。 在每个舞台上选一个颜色——闭元绿,闭元红,所有东西都插在合理坡道之间——从那时起 *每个* 按Stage组合的图表在每个仪表板中自动使用这些颜色。 每张图表不再重新选颜色, 也不再"等待,绿色是赢还是输?"

为在任何地方出现的维度:阶段,类型,工业,优先,状态. 红/琥珀/绿色 任何有内在的好坏订单 立即支付自己。

您也可以编辑 **显示值** - 但这里你需要小心。

::tip{icon="i-lucide-triangle-alert"}
**在此更改标签; 在数据层更改实际值 。** 在此面板中重命名一个值只会改变什么 *显示*。 。 。 。 内在价值未受破坏,所以 SAQL 查询、过滤定义、绑定和导出都仍然显示原件。 在图表中看到"企业"然后写作 `filter q by 'Segment' == "Enterprise"` 如果存储值真的存在, 将获得零行 `ENT`。 。 。 。 如果一个值真的错误,请在 **食谱或数据流** 与一个桶或一个变形——这样存储值和显示值就一致,没有人在六个月后会感到困惑.
::

## 保存

保存,变化是活的。 不是"活在这个镜头里"——活在数据集里. 重新打开它上的任何现有的仪表板,并且已经应用了标签,颜色,和货币格式,没有重建的余地.
