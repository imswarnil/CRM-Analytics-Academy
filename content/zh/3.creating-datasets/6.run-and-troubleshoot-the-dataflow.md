# 运行和解决问题 Dataflow

您点击了创建数据集, 哪个 **执行数据流**。 。 。 现在让我们看它运行, 了解它实际在做什么, 并修正错误, 几乎每个人第一次抓住。

## "运行数据流"到底做什么

何时 Dataset Builder 写到 **默认数据流**它不只是建造 *您的电话* 数据集——它运行 **所有的东西** 在数据流。 在不空的训练中:它会预先装入其他数据集和指令. 所以运行默认的数据流会执行全部, 不仅仅是你刚刚设计的机会数据集。

::tip{icon="i-lucide-git-branch"}
这正是为什么有经验的建筑商最终创造他们的 **拥有** 数据流。 单一共享默认数据流意味着每个架构都重新运行所有信息. 随着你的成长,你会将工作分成命名的数据流(或食谱),所以每个工作都会在自己的日程上刷新一套已知的数据集.
::

前往 **Data Manager 监测** 你会看到默认的数据流运行。

## 经典的首运行错误

数据流可能会在全新的窗口上运行,或者在您第一次运行时 **失败时发生错误**。 。 。 别慌 原因几乎总是简单的: 数据流要求对象 **还没有被拉进同步层**。 。 。 。

记住链条: 数据流读取自 **连接/同步**,不是从 Salesforce 直接来 如果Connect还没有Hubliced Account,机会,和用户,则数据流没有读取内容,错误出局.

## 修复: 手动运行连接

::tip{icon="i-lucide-workflow"}
当一切都是 **预定** 这是自动的 : 数据流询问同步层“ 是否是这里的数据 ” , 如果没有, Connect 将启动并在数据流开始前带入 。 只有在环境不同步时,你才用手来做这个工作——一般是第一天的新鲜训练。
::

## 忘了一块田地? 编辑文摘节点

因为你不能重新打开 Dataset Builder 字段拾取器,编辑字段 **数据流的文摘节点**。 。 。 。

- 打开数据流,单击相关的文摘节点(say, **账户**),并通过 **选择字段**。 。 。 。
- 保存, 当提示时, 选择 **宣传** 字段一直延伸到最后的寄存器节点——否则它会停在部分路段,永远不会到达您的数据集.
- 更新和 **再次运行数据流** 因此,新领域被实现。

我们覆盖摘要节点、字段属性和数据流编辑 Data Manager 教训——这足以解除你的束缚。

## 你建了第一个数据集

一旦数据流完成绿色,跳回 Analytics Studio 在那里,你的机会 数据集,坐在你的私人应用,准备探索。 在地貌图上 它现在生活在 **数据集层**,由同步读取的数据流构建。

::tip{icon="i-lucide-check-check"}
数据流失败时的心理清单 : **(1) 国家** 源对象同步吗 ? **(二)** 连接在数据流运行前是否真的完成 ? **(三) 国家** 你需要向寄存器节点推广的每一个字段吗? 十个首选失败中,有九个由这三个问题回答。
::

Dataset Builder 这是友好的,但它锁定你 检查和数据流。 接下来我们建造 **完全相同的数据集** 带有 **食谱** ——更多点击前方,控制量大得多,平台正走向.
