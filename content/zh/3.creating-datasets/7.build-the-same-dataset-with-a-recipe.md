# 用食谱构建同一数据集

我们来建造 **完全一样** 机会数据集-机会+账户+用户-但 **食谱** 这次 食谱是现代的数据准备引擎:拖放,视觉,以及远比数据流更灵活. 权衡是 *老师* 拥有关系。 Dataset Builder 找出了下一个对象和组合键 在一个配方中,你决定什么是组合,什么是组合。

## 开始新的食谱

从 Analytics Studio, (中文). **创建 ~ 数据集** 从您的数据集或同步对象中选择 。 此选项将打开 a **食谱** 输入 Data Manager (数据流) & 食谱 − **食谱** • 新的食谱)。

在食谱中, **选择数据** 显示您可用的一切: 您创建的数据集、 外部来源、 连接/ 同步对象 Salesforce。 。 。 。 抓住同样的三个... **机会**, (中文). **账户**, (中文). **用户**。 。 。 。

::tip{icon="i-lucide-list-checks"}
第一个真正的区别与 Dataset Builder: 您可以 **全部选择** 字段,而不是一个接一个地单击它们——宽对象上的巨大时间保护符。 但别. 如果一个对象有150+字段,则不需要全部;一个过于宽广的数据集在滚动时很痛苦,而查询时也比较慢. 只带仪表板需要的
::

单击 **下一个** 你坐在食谱的帆布里, **未连接**。 。 。 这就是核心区别:在食谱中,连接它们是你的工作。

## 加入对象

谷物规则仍然适用: **机会是最低的**,所以所有东西都加入其中。

::lesson-steps
---
items:
  - title: "将账户连接到机会"
    description: "从机会节点加到账户 。 它成为联合节点。 配方正确拾取账户ID=账户ID——验证后应用."
  - title: "连接用户到 机会——注意关键"
    description: "将用户添加到机会( 不添加到账户中—— 所有者属于机会) 。 这里的食谱猜测错误: 它匹配机会ID到用户ID. 您想要拥有者身份 – 用户身份 。 手执修钥."
  - title: "应用每个步骤"
    description: "食谱不会像您所期望的那样保存——单击底部,在前进前将每个节点都输入。"
---
::

::tip{icon="i-lucide-triangle-alert"}
这是食谱税,值得内化: **它自动选择一个结合键, 它可以选择错误的键。** 为了你需要的主人 `OwnerId → User.Id`没有 `Opportunity.Id → User.Id`。 。 。 。 你必须 *知道你的目标* 足够抓住它。 Dataset Builder 绝对不会让你犯这个错误 那就是你为了控制而交换的安全
::

## 控制您的列

食谱给您对输出列的真正控制 :

- **加入类型** ——扩大加盟节点以选择一个 **查询** 完全加入我们。 (我们在谷类课中阐述了为什么这很重要,
- **前缀** - 账户中的字段为 `Account.Name`, (中文). `Account.Industry`,等等。 (笑声) 您可以重命名这些前缀, 所以最终列读取你想要的方式 。
- **保留或减少** 预览收到的列和 **隐藏** 那些你不需要的,所以他们永远达不到输出。 调理 `User.` 字段下到所有者的名字和照片,例如。

## 添加输出节点

这是台阶 人们忘记: **在添加输出( 注册) 节点之前, 无可用数据集存在 。** 单靠这些合唱团就无济于事了

::lesson-steps

items:
  - title: "添加输出节点"
    description: "单击上次加盟后的加号并添加输出节点。 这就是数据集的实现。"
  - title: "刻意点名"
    description: "给它一个明确的标签(例如‘Opp Owner Acc – from cute'). 标签可以有空格; API 名称不能。 使用干净 API 名称可以在以后粘贴成捆绑。"
  - title: "应用,然后保存和运行"
    description: "应用输出节点,然后保存和运行食谱. 它执行并构建您的数据集 。"
---
::
