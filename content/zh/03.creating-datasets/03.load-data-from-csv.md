# 从 a 装入数据 CSV 文件

最快的数据输入方式 CRM Analytics 是一个 **CSV 上传**。 。 。 它是一个手工的,一次性的负载——没有同步,没有数据流,没有食谱——它对于活着的数据来说是完美的. *外部* Salesforce 或者你只需要快点进去

我们的例子文件, `Opportunity External Amounts`,EA训练文件中的舰只(第一视频的拉链). 它模仿从一个单独的系统获得的数据:a **名称**,一个 **原数额**,则 **外部发票数额**。 。 。 。 想象一下财务追踪一个外部发票数字 Salesforce 没有,你把它出口到 CSV。 。 。 。

当你降落回到工作室, 数据集已经准备好使用。 从上一课注意到数据-景观图上的重要内容:a CSV 数据集位置 **独自一人** - 这是 *没有* 连接到数据流或同步中,因为它是手动的一次性负载. 数据就在那里,准备好了

## 元数据计划( 稍高级)

上传时,数据引擎会读取您的 CSV 和 **猜测** 每个字段的类型:文本变为一个 **维度**数字变为 **措施**。 。 。 。 你可以在UI中推翻那些猜测

典型的例子是 **zip 代码**。 。 。 。 是数字 所以引擎读成 *计量* (总和或平均值)——但你绝对不会加拉链码。 你切片和组合 由他们。 所以改变它从 **计量** 改为 **维度** 在现场。

多数时候你只需要UI 但有些东西,比如 **多值字段** ——无法在UI中定义. 对于这些,下载生成的 **元数据计划文件**,用手编辑它(例如,设置) `isMultiValue: true` 并完成上传。

::tip{icon="i-lucide-info"}
只有在UI无法表达你需要的东西时,才能到达schema文件——多值字段,精确数字格式化,或强迫引擎出错的类型. 对于90%的上传,屏幕尺寸/度量/日期审查就足够了. 我们把计划文件全写在 Data Manager 教训
::
