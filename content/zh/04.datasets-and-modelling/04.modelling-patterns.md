# 建模模式

CRM Analytics 不是仓库,它的数据集不是恒星计划,而是同样的形状重复出现——并且认识到它们可以拯救你,避免重新发现每一个。

## 事实和参考

::field-table
---
dataset: "the two roles"
grain: "one row per role"
fields:
  - name: "Fact tables"
    type: "things that happened"
    role: "measure"
    note: "机会,线索,案件,用法,开庭. 许多行,携带量度和日期及钥匙. 这些是你们汇总的。"
  - name: "Reference tables"
    type: "things that are"
    role: "dimension"
    note: "账户,产品,代表,运动. 几行,带属性. 你加入他们来获得标签和分组——将任何东西一一归纳起来几乎总是个错误,账户表中的ARR一栏是站立的陷阱,因为它既是属性,也是度量."
---
::

::warning{icon="i-lucide-alert-triangle"}
**在事实表格中加入参考表格是安全的;相反的乘数。** 把一个账户的部分 在每个机会 保持机会的谷物。 把每个机会都带到每个账户行上并不重要——如果你再把账户的ARR相加,你就会把它乘以账户的交易数。 这是从上一节课中出来的粉丝 从另一个方向来的
::

## 宽对长

每个实体采用两种方法维持若干衡量标准:

::compare-cols
---
items:
  - title: "宽"
    subtitle: "One column per metric"
    icon: "i-lucide-table-columns"
    pros:
      - "Natural for charts — pick the column you want"
      - "Obvious to read in a table preview"
      - "Fine when the metric list is short and stable"
    cons:
      - "A new metric means a schema change and a rebuild"
      - "Charting many metrics together needs one widget per column"
    verdict: "Default for a small, settled set."
  - title: "长"
    subtitle: "One row per entity per metric"
    icon: "i-lucide-rows-3"
    pros:
      - "New metrics are new rows, not schema changes"
      - "One widget can chart any metric, chosen by a filter"
      - "Natural fit for a metric-toggle binding"
    cons:
      - "Every query must filter to a metric, and forgetting sums unrelated things together"
      - "Harder to read raw"
    verdict: "Right when metrics are added often."
---
::

::note{icon="i-lucide-alert-circle"}
**长格式的失败是壮观和沉默的:跨越度量衡进行总结.** 一个忽略过滤到一个公尺的查询会增加收入,处理计数到换算率并返回一个数字. 没有错误。 如果您建模长长, 则将测量过滤器作为每个部件基础查询的一部分, 而不是信任每个构建者来记住 。
::

## 衍生层

食谱可以读取另一种食谱的输出. 这就是你如何获得一个干净的基底数据集, 供奉几个专门建造的基底数据集—— GTM工程部分的仓库使用的模式。

::lesson-steps
---
items:
  - title: "保持链条的浅"
    description: "基础,然后衍生出来。 三,四层联系深,在开头的失败在结尾是看不见的,没有人能说哪层引入了错误的数字."
  - title: "排好前排"
    description: "依赖陷阱再次:一种衍生的食谱,在源头完成前开始,在昨天的数据上成功运行,每天晚上,并报告绿色."
  - title: "命名图层"
    description: "一个前缀说一个数据集是用来做什么的——基础,报告,执行——告诉下一个人他们正在寻找的链条中的位置,没有其他财产会看到."
  - title: "将定义放在底部"
    description: "基层中计算出的量子由建筑下游的一切继承。 在衍生数据集中添加的定义适用于一个分支,并且与它的兄弟姐妹悄悄地不同。"
---
::

## 桥台

当两件事有多种关系时——机会和产品,运动和领导——会合桌. *这是* 你必须尊重的谷物。

`opportunity_products.csv` 是Namilio的:1 378行连接了677个机会和6个产品。 任何针对它的询问都是在线粒体上,所以交易计数需要不同的计数,母计量不能被归纳. 在看到一个桥台时——这个桌子大多是钥匙——在写东西之前就告诉你了。
