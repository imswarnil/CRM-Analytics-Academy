# 设计数据集

从问题开始 不是从桌子开始 这些表格告诉你什么是可能的;问题告诉你建造什么。

## 四问题设计

::lesson-steps
---
items:
  - title: "写下它必须回答的问题"
    description: "五六,以平话. 哪个部分会挡住我们的警报 哪些交易持续时间最长 如果您无法列出它们, 您正在构建一个源表的复制件, 而不是一个数据集 。"
  - title: "从最好的问题中获取谷物"
    description: "如果问题涉及个人交易,每笔交易的谷物为一行. 如果它们都是按区段分列的每月总数,那么每个区段可以是一行——而且速度会快得多。"
  - title: "列出每个问题需要的列"
    description: "按组别、综合措施、日期和趋势分列的数量。 任何不符合所列问题要求的,都是要回避的人选:每增加一栏费用,就会花时间,使下一个人更难阅读外地名单。"
  - title: "决定哪些被永久排除"
    description: "测试记录,内部账户, 一个产品线 没有人报告。 如果一行从不出现在数据集给出的任何答案中,请在此过滤,而不是要求每个仪表板记住."
---
::

## 在数据集或仪表板上过滤?

::field-table
---
dataset: "where a filter belongs"

    role: "key"
    note: "测试帐号, 删除的记录, 此段不属于此数据集的目的 。 任何人都不能通过清理控制来排除它们,每个消费者在不知情的情况下继承排除。"
  - name: "In the widget's query"
    type: "this widget always"
    role: "measure"
    note: "\"开放的管道\"不应该显示封闭的丢失交易 因为有人重置了过滤器 结构到部件,而不是到数据集, 因为同一数据集的另一个部件 合法想要这些行 。"
  - name: "On the dashboard"
    type: "exploratory"
    role: "dimension"
    note: "期间,区域,部分——事物观众应该能够改变. 如果过滤器是一个控制器,它就在这里。"
---
::

::warning{icon="i-lucide-filter-x"}
**数据集中的过滤器对下游每个人来说都是看不见的.** 这就是它的价值和风险:一个将你的数据集与源进行调和的分析师会发现一个差异,并且没有办法去理解原因. 在数据集的描述中放置每个数据集级别过滤器——“不包括测试账户和内部沙盒 Org”——否则将反复被问及差异.
::

## 一个数据集还是两个?

诱惑总是要扩大现有的范围。 有两个信号表示你应该分开:

::compare-cols
---
items:
  - title: "分开"
    subtitle: "Different grain, or different purpose"
    icon: "i-lucide-split"
    pros:
      - "Each is simple enough to reason about"
      - "The daily dashboard gets a fast pre-aggregated dataset while exploration keeps the detail"
      - "One recipe can produce both outputs, so the logic is still defined once"
    cons:
      - "Two things to schedule and monitor"
    verdict: "Usually right when the grains genuinely differ."
  - title: "宽度"
    subtitle: "Add columns to the existing one"
    icon: "i-lucide-move-horizontal"
    pros:
      - "One thing to maintain"
      - "Fine when the new questions live at the same grain"
    cons:
      - "A dataset serving everybody eventually serves nobody well"
      - "Sixty columns of which fifteen matter is hostile to self-service"
    verdict: "Right only while the grain and purpose still match."
---
::

::tip{icon="i-lucide-git-branch"}
**一种配方的两个产出是未充分利用的选择。** 加入,清洗和定义发生一次;食谱然后写一个详细的数据集和一个汇总数据集. 你得到它重要的地方的速度 和它需要的地方的细节, 没有两个复制 逻辑漂移。
::

## 在描述中写入谷物

每个数据集,一句话: *每个产品每机会一行*。 。 。 这是5秒钟的工作,是下游任何人都读到的最有用的东西——一个同事在总结正确的一栏和在永远不知道的情况下总结一个重复的一栏之间的区别。
