# 部署和回写

已部署的模型计分记录并将结果写回 Salesforce 记录——这就是它停止分析并开始影响行为的时刻。

## 把它放在工作地点

::note{icon="i-lucide-map-pin"}
**写回最强的东西是放置.** 在仪表盘上得分是代表必须去查看的;他们已经打开的机会得分是他们不能错过的。 这与嵌入在 Einstein Discovery 改变人们所做的事的模型与 被人们敬仰和忽视的模型之间的区别
::

## 得分是多少

三件事 第二件事就是被丢掉的一件事

::lesson-steps
---
items:
  - title: "预测"
    description: "数或分类. 它本身是惰性的——代表不能用23%做任何事情。"
  - title: "首要因素,用普通语言"
    description: "三件事把它拉下来, 说成一个人会说。 这部分使得分数成为待办事项列表而不是判决,而这是最经常省略的部分,因为它是更多的工作来浮出水面."
  - title: "得分的日期"
    description: "六个星期前的预言 一项从那时起两次进化的交易 比没有预言还糟糕 如果分数是停滞的,请在显示地点说."
---
::

::warning{icon="i-lucide-bell-off"}
**一个无缘无故的分数在一个月内被忽略,然后被不信任.** 序列是可以预测的:它到达了,人们看着它,它没有告诉他们该怎么做,他们停止了寻找,当后来有人问为什么AI投资没有改变任何事情时,答案是它从来没有给过任何人一个行动. 克服这些因素不是抛光——而是部署。
::

## 校对

记录变更。 刻意决定重新计分的频率,

- **刷新时** ——分数跟随数据集的时间表. 很简单 今早搬来的一个交易 仍然有昨晚的成绩
- **关于变化** ——更接近实时,更昂贵;只有在一天之内有人按分数行事时才值得.

两者皆可辩. 不可辩驳的是没有人知道哪一个已经到位,因为那时没有人知道有多少人可以信任一个与他们面前的记录有分歧的分数.

## 监测

::field-table
---
dataset: "what to watch after deployment"
grain: "one row per check"
fields:
  - name: "Does it still predict?"
    type: "monthly"
    role: "key"
    note: "把预测与实际发生的情况相比较。 在一个新产品推出前经过训练的模型可以查看旧的组合,衰变是正常的条件而不是缺陷."
  - name: "Does anybody act on it?"
    type: "the adoption check"
    role: "dimension"
    note: "人人都忽略的模型 是一种没有回报的维护成本 这是可以衡量的——低分数交易是否得到不同的处理,而且几乎从来没有衡量过。"
  - name: "Has the input data drifted?"
    type: "quietly fatal"
    role: "measure"
    note: "一个不再有人居住的领域,一个获得价值的选手,一个被重新命名的片段. 该模型一直充满信心地对不再具有意义的投入进行评分。"
  - name: "Is it changing the data it learns from?"
    type: "the feedback loop"
    role: "measure"
    note: "如果代表填写一个字段,因为模型奖励它,那么这个字段就停止测量它测量到什么. 模型的降解正是因为它被使用,只有一次定期的重新检查才能捕获它."
---
::

## 退休计划

::tip{icon="i-lucide-power-off"}
**在部署时决定 是什么让你关掉的** 低于规定门槛值的准确性,一个投资组合改变得足够大,以至于培训数据不再描述业务,或者仅仅四分之一时间没有人在业务上采取行动。 一个没有退休条件的模型永远不会退休——它只是悄悄地不再被人们相信,这更糟糕,因为它停留在唱片页面上看起来具有权威性.
::
