# 何谓故事

你给它一个数据集,并命名你所关心的栏目——胜或败,曲折或保留,转换或不转换。 它寻找其他栏中区分结果的图案,并报告它们按强度排列.

## 输出内容

一个故事会给你各种因素,每个因素都有 **方向** (向结果或远离结果)a **数量**,则 **段数** 应用最强。

::note{icon="i-lucide-quote"}
**这种说法是关联性的,措辞让你忘记这一点。** "没有经济买家识别值 34% 不太可能关闭" 是关于你历史数据中共同存在的内容的声明 它没有确定经济买方的身份。 *原因* 交易的结束——至少有一点是可信的,即交易已经顺利进行,这是有人费心去填字的。 故事是一幅地图,说明该看哪里,而不是一套指示.
::

## 三类因素

::field-table
---
dataset: "reading a factor"
grain: "one row per kind"
fields:
  - name: "Actionable"
    type: "you can change it"
    role: "key"
    note: "上次活动后的几天,折扣水平,供应商审查是否已经开始。 这些是值得摆在代表面前的因素,因为还有下一个行动。"
  - name: "Descriptive"
    type: "true and unchangeable"
    role: "dimension"
    note: "分部,行业,公司规模,区域. 真正的信号和对此无所作为——对瞄准和领土设计有用,在记录页上作为建议是无用的."
  - name: "Suspicious"
    type: "too good"
    role: "measure"
    note: "一个几乎可以完美预测的因子通常是渗漏:在结果或结果之后记录到的东西. \"有一个签了合同的日期\" 预言的闭关时间 惊人的准确 并告诉你什么都没有。"
---
::

::warning{icon="i-lucide-alert-triangle"}
**最强的因素往往最无用。** 故事按力量排列,所以列表的首位经常是描述性或泄露出来的事物,而不是一个人能够采取行动的事物. 阅读整个列表,并根据是否存在下一个动作来判断每个因素——不需要告诉代表企业部处理的近似于"自助".
::

## 小数据让自信无稽之谈

学院有608个机会. 对于一个故事来说,这已经足够了,对于狭隘部分的信心来说,这远远不够。

::tip{icon="i-lucide-microscope"}
**请检查date=中的日期值 (帮助) 有多少行坐落在一个因素后方才能相信.** “技术评价在LATAM中更频繁地接近60%”是一个结论, 一个故事会以相同的音调来报告两者,片段大小是唯一能让他们分辨的.
::
