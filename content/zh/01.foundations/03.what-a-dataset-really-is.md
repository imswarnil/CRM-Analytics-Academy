# 真正的数据集是

一个数据集看起来像一个表格,表现得像一个决定. 这个教训是关于决定的.

## 已经实现,没有生命

当一个食谱运行时,它读取它的源头,做它的工作,和 **写入新副本** 中的数据 CRM Analytics自己的专栏店。 那个副本是数据集。 在下一次运行之前,它不会改变——当一个代表编辑一个机会时,当一个记录被删除时,当重新装入仪表板时,它也不会改变.

::note{icon="i-lucide-clock"}
**每一次"号码错误"的调查都从同一个问题开始:这最后一次运行是什么时候?.** Data Manager监控标签有答案 大约三分之一的时间是整个调查 这不是一个绕圈子——僵化是一种设计财产,为了能够加入五个来源,在一秒之内累计数百万行而交易。
::

这也产生了一个数据集最有用的属性. 那个 Salesforce 机会对象持有 **今天的会** 数额和 **今天的会** 阶段; 它没有记忆。 数据集每周运行一次,每次附加当前状态,积累对象不能给你的历史——这就是为什么数据集和建模部分的ARR瀑布是完全可能的,为什么它坚持 `arr_snapshots.csv` 是一个快照 而不是从当前状态重现的东西。

## 谷物:一个问题

::tip{icon="i-lucide-ruler"}
**一行代表着什么?** 问它每个数据集, 在你建立东西之前, 并写下答案。 分析中几乎每个错误的数字都是从未问过的谷类问题.
::

学院自己的表, 说成谷物:

::field-table
---
dataset: "Academy — grain of each table"
grain: "one row per table"
fields:
  - name: "accounts.csv"
    type: "one row per account"
    role: "dimension"
    note: "140行经. 一个参考表:加入它,你很少汇总它. 拍下这里的一切几乎总是个错误."
  - name: "opportunities.csv"
    type: "one row per opportunity"
    role: "fact"
    note: "608行. 每笔交易一次 这是收入正确的谷物。"
  - name: "opportunity_products.csv"
    type: "one row per opportunity per product"
    role: "fact"
    note: "1,192行——大约每个机会两行. 数量也出现在父母中。 粗心细意地加入这两部作品,学院的1340万美元闭元变为3690万美元."
  - name: "usage_monthly.csv"
    type: "one row per month per account per product"
    role: "fact"
    note: "2,612列车. 谷中三维. 将其中任何一个集合起来,而不说哪个答案是毫无意义的,而不是错误的。"
  - name: "arr_snapshots.csv"
    type: "one row per month per account"
    role: "fact"
    note: "1,579行车. 同一账户出现18次,每月一次,每行约该月的报表。 各行的汇总ARR产生18年的收入。"
  - name: "platform_health_daily.csv"
    type: "one row per day per product"
    role: "fact"
    note: "3,244行,和无账户密钥。 它完全不能与一个账户合并,这就是重点:它回答‘是我们'有关平台,而不是客户."
---
::

## 风扇,昂贵的

两张桌子,一对一的关系,还有一笔总和. 它在5分钟内发生,并活下来的审查,因为每个个人数字看起来都是合理的.

::

修补不聪明: **组合加入前的多个方位,或者不将父方的度量负下。** 数据集和建模部分以两种方式构建它,而RevOps部分则使其成为一种习惯. 这里重要的是要识别症状—— 大约是2×,3×, 或者是你所期望的可疑圆倍。

::warning{icon="i-lucide-search"}
**告诉。** 如果一个数字在添加一个分组时双倍,分组不会引起问题——它是 *揭示* 这个 重复已经存在;分组刚刚使重复的行在单独的桶中可见.
::

## 尺寸、措施、日期

CRM Analytics 将每个字段作为三件事之一,类型决定字段可以做什么:

- **尺寸** - 东西你组合或过滤。 文字,通常. `Segment`, (中文). `Region`, (中文). `StageName`和每个身份证。
- **措施** - 一些你汇总。 数字。 `Amount`, (中文). `Quantity`, (中文). `UsedUnits`。 。 。 。
- **日期** ——一个日期,打成一个字,这就是使日期过滤器,月份分组和趋势线成为可能的原因.

::note{icon="i-lucide-alert-circle"}
**两个打字错误要花时间** 以文字加载的日期在表格中看起来很好,不能呈趋势,不能按范围过滤,也不能按月份分组——固定它意味着重新加载。 数字化的ID作为衡量标准 意味着产品将乐于提供总和 `AccountId`最后有人接受了这个提议 装入时强制识别码到维度; 您永远不会想要它们的和 。
::

## 数据集是一个决定,而不是一个容器

因为一个数据集是构建的而不是询问的,所以有人会选择它的谷物,它的结合,它的过滤器和它的字段. 这些选择决定了哪些问题可以回答,哪些问题不能回答,而且与仓库不同,你无法在以后用一个聪明的查询来逃避它们。
