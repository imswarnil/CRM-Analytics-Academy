# 面部和过滤器

**面对** 是一个部件交互过滤其它部件的行为。 它将一个仪表板与一页图片分隔开来,默认它在同一数据集的部件之间。

## 为什么默认是正确的

单击条形图中的一段和标题编号、表格和趋势都缩小到它。 观众在不知道自己正在这样做的情况下问了后续问题——没有过滤菜单,没有重新装填,也没有训练.

::note{icon="i-lucide-mouse-pointer-click"}
**这是使自助服务发挥作用的单一特征。** 大多数人永远不会造一个镜头。 几乎每个人都会点击一个栏杆看看里面是什么。 设计使任何点击都会产生一个明智的缩小,那就是一个仪表板是如何解答你没有预料到的问题的——这是协作部分自我服务论点的全部承诺.
::

## 什么时候关掉

有三起案件值得一见,

::field-table
---
dataset: "when faceting should be off"
grain: "one row per case"
fields:
  - name: "The reference widget"
    type: "must not move"
    role: "key"
    note: "一个全公司的总数,在一切其它过滤的同时保持固定,这样读者就可以看到这个部分与整个部分相对. 如果随选择而缩小,则当它变得有用时它就消失而存在的比较."
  - name: "Different grain"
    type: "would mislead"
    role: "measure"
    note: "学院的平台健康数据根本没有账户密钥. 通过账户选择过滤它并不仅仅是无益的——它默默地暗示了平台的运行时间与数据不能支持的一个客户之间的关系."
  - name: "Context panels"
    type: "static by design"
    role: "dimension"
    note: "定义,刷新时间戳,与度量谱的链接. 这些是家具;它们不应该对任何东西作出反应。"
---
::

::warning{icon="i-lucide-link-2-off"}
**横跨数据集需要精心布线。** 同一数据集的部件会自动显示;不同数据集的部件不会显示,除非您将它们连接起来。 陷阱是一个仪表板,一半的部件对一个过滤器做出响应,一半的部件悄悄地不做——查看器过滤器对EMEA,四个部件缩小,三个继续显示全局数字,屏幕上的每个数字都是个别正确的,而屏幕整体是谎言. 在传送前检查每个部件的过滤器 。
::

## 空状态

查看器过滤到没有数据的东西,部件会空白。 布兰克是诚实的。 没有解释的空白看起来断了,"仪表板断了"的传播速度比任何更正都要快.

::tip{icon="i-lucide-message-square"}
**给重要部件一个空状态消息** ——"没有与这个过滤器相匹配的病例",而不是一无所有. 这是收缩滤镜的观众和报告停电的观众的区别. 这对合法经常空出的部件来说最为重要,就像一个风险表,当事情进展顺利时就是空的。
::
