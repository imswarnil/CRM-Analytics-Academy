# 部件上的有条件格式

条件格式化是您在仪表板上花费的 最高的5分钟 它需要一张中性蓝条的图表,并把它变成读者可以一目了然地解释的东西: **红色是问题,绿色是好的**。 。 。 。 没有传说 没有解释 没有训练

它住在部件的属性面板,在一个 **计量**在条形图、值表和 **编号** 部件一样

## 何处找

选择要颜色的部件,打开右侧属性面板,并查找 **有条件的格式** 节。 打开它,你得到一个需要的选择: **哪个量度驱动颜色**。 。 。 图表通常只有一个,但如果您返回了几个查询,请慎重考虑——您可能以 *边距* 栏长显示时 *收入*。 。 。 。

## 纸箱和阈值

页:1 **选项** 只是一个带有颜色的数值范围。 默认给你三个,这几乎总是你想要的,因为大多数商业规则是三态的:低于目标,接近目标,高于目标.

门槛是 **由你选择**,而这就是实际发生的想法。 别选圆数,因为它们是圆的. 选一个对企业有意义的数字——配额,更新底线,低于的比值,交易不值得做. 匹配真正决定边界的阈值使颜色可以操作;任意的阈值使图表变得多彩。

## 重命名标签

从盒子里,每个垃圾箱 被命名为可以忘记的东西 *组合 1*。 。 。 。 覆盖他们。 类型 **低档**, (中文). **中型**,以及 **高级** - 或者更好,你的团队实际使用的词: *风险*, (中文). *在轨道上*, (中文). *超过*。 。 。 。

这比看起来更重要,因为这些标签在部件的传说和工具提示中浮出水面。 一个读作"Low /中/高"的传说是自我文件化的. 一读"Bin 1 / Bin 2 / Bin 3",读者会问其含义,这正是好设计删除的问题.

::tip{icon="i-lucide-info"}
保持颜色意义 **整个仪表板一致**。 。 。 如果红色在上图中意为"后方目标",则不能在下方的图中意为"高音量". 读者在前三秒钟学习你的色彩语言,然后相信它——沉默地打破它比完全不使用色彩更糟糕.
::

## 宾比梯度

discrete bins是默认,但图表也提供了 **渐变** 选项。 颜色不是三个硬桶,而是在数值范围内连续地移动——低端苍白,高端饱和.

要使用什么, 取决于您的规则是否有边缘 :

- **纸箱** 当有真正的截断。 配额实现,苏丹解放军违反,通过/失败。 读者需要知道每行值的哪一边坐着,硬色变化会立刻传达.
- **渐变** 当你出现时 *相对* 大小,没有有意义的边界。 按区域、活动计数、热态比较分列的收入。 一个梯度显示分布的形状而不假想有一个不存在的阈值.

一个很好的直肠检查:如果可以在句子中命名阈值,则使用bins. 如果你发现自己发明了一个数字来证明一个截断的理由,请使用梯度.

## 对数字部件也有用

条件格式化不仅仅针对图表. 应用到一个 **编号** 部件和大数字本身会改变颜色——一个 KPI 当它落到目标下时 就会变成红色 这是一个非常有效的使用仪表板房地产:一个数字,没有传说,没有图表,国家从一个房间对面是不可混淆的.

当我们组装时,我们会建造 精确的这种格式化的数字部件 KPI 本节后行.

现在,你的图表带有色彩的意义,下一个问题是让用户 *切点* 他们没有通过过滤板打猎。 下一个: **日期切换和面部**。 。 。 。
