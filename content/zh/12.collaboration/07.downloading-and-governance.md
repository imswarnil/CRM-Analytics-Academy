# 下载和治理

两个决定作品是否存续一年的不光彩话题.

## 下载

人员出口. 他们输出来做仪表板没有做的事情,而输出通常是信号而不是问题.

::lesson-steps
---
items:
  - title: "问他们拿它做什么"
    description: "通常有三件事: 计算仪表板不能提供, 需要工作的清单, 或者别人要求的格式。 每种都有不同的修补方法,三种方法中有两个是你们可以建造的东西."
  - title: "建造他们正在重建的东西"
    description: "每周导出一个总是得到同样应用的枢轴的部件 。 这是真正想要的特征的唯一最可靠的来源。"
  - title: "把名单给他们"
    description: "如果需要穿行,这是合理的。 将仪表板保留在前十位,并提供其旁边的全部下载,而不是在屏幕上放置140个滚动行."
  - title: "接受剩下的东西"
    description: "有些出口之所以存在,是因为银行、审计员或董事会需要文件。 这很好——目标不是零出口,而是零出口重新创建仪表板。"
---
::

::warning{icon="i-lucide-file-spreadsheet"}
**相互竞争的真实问题是真正的风险。** 一个导出的电子表格是一个从不刷新、编辑、共享的快照,在六周后被引用到一个经过纠正的仪表板上。 没有人恶意行事,而且两个数字都有其来源——这使分歧比简单的错误更难解决。 下载不是敌人;下载成为某人永久的工作副本就是敌人.
::

行级安全适用于出口,如同它适用于查询:人们下载他们能看到的东西. 这是正确的,这意味着两个人 输出相同的部件 可以产生不同的文件,合法。

## 最小的有用形式的治理

小型兽群的治理不需要一个委员会。 它需要写下四件事 和一个责任人:

::field-table
---
dataset: "the minimum that actually works"
grain: "one row per artefact"
fields:
  - name: "An owner per dashboard"
    type: "a name"
    role: "key"
    note: "回答问题,维持定义和决定变化的人. 没有这个仪表板会无声无息地退化——时间表会漂移,一个字段会改变意思是上游,信任会远早于任何人提交罚单."
  - name: "Metric definitions"
    type: "one page"
    role: "key"
    note: "公式,谷物,来源,已知的陷阱——全程使用的度量光谱形状. 答案是“为什么这和我的数字不同”,这是人们首先提出的问题。"
  - name: "The security note"
    type: "four lines"
    role: "dimension"
    note: "哪个数据集带有上游,每个数据集在英语中都说,谁可以豁免,什么是后退. 安全配置作为配置无法读取 。"
  - name: "A deprecation habit"
    type: "quarterly"
    role: "measure"
    note: "删除或归档无人打开的仪表板。 四个定义略有不同的管道仪表板比一个更糟糕,因为它保证了一个论点,即没有多少正确性解决."
---
::

::tip{icon="i-lucide-trash-2"}
**删除是一项治理活动。** 每个未使用的仪表板都是未来的论证,维护成本,在错误的时刻有人会发现并信任的东西. 审查没有人打开和消除它,是不光彩的,它是任何人从事的最高杠杆治理——远远超过新工作的批准程序。
::

## 所有权判决

::note{icon="i-lucide-user-check"}
**"这个仪表盘是X拥有的,定义在这里,它夜以继日的03:00".** 该句附在仪表板上,是治理的大部分内容。 它回答谁要问,数字意味着什么,以及它们是如何流动的——这是任何人实际上只有的三个问题。
::
