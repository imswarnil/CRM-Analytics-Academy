# 巢穴和限制

装订物 选择输入一个查询,其结果输入标题,标题输入第三个部件的过滤器。 每个步骤都是合理的;积聚就是仪表板死亡的地方.

## 连锁成本

::warning{icon="i-lucide-git-branch"}
**三个成本,只有第一个是可见的。** 部件按顺序执行,而不是平行执行,所以屏幕的部件计数无法解释。 对第一个部件的更改会打破第三个部件,因为屏幕上没有任何建议。 而依赖图只存在于配置面板中, 所以理解它意味着一次打开每个部件, 并在你的脑中保持结构。
::

绑定物没有文件记载的上限,且号码不是:

::note{icon="i-lucide-user-check"}
**测试:一个同事能否在下个月不问你问题的情况下,在这个仪表板上添加一个部件?** 如果诚实的回答是否定的,那么束缚已经越过了界限——不是因为太多,而是因为它们的效果从外部看是不可预测的. 只有一个人可以改变的仪表板是有一个故障点的仪表板,它最终会休假.
::

## 有三种习惯可以维持

::lesson-steps
---
items:
  - title: "文档每行装订为一行"
    description: "在仪表板描述中:“Region filter → replefilter list; replefilter → 所有管道部件; 公司平均查询 → 段图上的颜色阈值 。” 三行,下一个人可以不打开单个配置面板来解释屏幕."
  - title: "偏重宽度到深度"
    description: "每个直接绑在一个过滤器上的五个部件是好的。 捆绑在链条中的三个部件更糟糕,尽管捆绑较少——深度使得效果无法预测."
  - title: "查询名称"
    description: "企业*页:1*而不是\"7号\" 按名称绑定参考查询,因此名称是整个安排中唯一可读的部分."
---
::

## 什么时候停下来分开

四个信号,其中任何一个都足够:

- 您不能用三句大声描述绑定结构 。
- 仪表盘为两个观众服务,每个观众都忽略了其中的一半.
- 一个新部件需要先了解三个现有部件才能添加。
- 负载的顺序足以使屏幕处于可见的阶段.

::tip{icon="i-lucide-scissors"}
**分裂几乎总是正确的答案,很少是诱人的答案。** 聪明的单面仪表板感觉像是更好的动画;两个平面仪表板更容易阅读,加载速度更快,更简单地分享给不同的观众,也可以被别人改变. 第12节关于应用共享的论点也在这里适用——当单位较小时治理就更容易了.
::

## 什么是真正值得 复杂

并不是一切都应该简化。 依赖一个40个项目列表的过滤器,动态标题,一个跟随当前时期的阈值——这些都赢得了保存,如果删除,每个都会被错过. 判决不是"束缚性约束",而是"每个束缚性支付自己,安排可以辨别".
