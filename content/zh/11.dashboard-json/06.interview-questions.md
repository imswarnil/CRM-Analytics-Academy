interview:
  - q: "你和仪表板合作过吗? JSON为什么?"
    a: "主要用于批量编辑和审查. 将一个字段重命名为30个部件或重新指定数据集重命名后的每一个步骤,就是文本中一个查找和替换的字段,以及构建器中的30个配置面板,并有缺失一个的好机会. 因为 JSON 是文本 diffs, 它将“ 我更新了仪表板” 变成一个可审查的列表 确切的变化。 我所避免的就是用它来做建造者做的完全不错的普通工作, 因为手写的结构可能不会绕行,然后只有我才能维护仪表板。"
  - q: "仪表板文件的哪些部分?"
    a: "国家包裹三个集合:步骤,部件和布局. 步骤是查询定义——数据集,分组,措施,过滤器,有时是原始的. SAQL -每个都有名字 部件是所绘制的,它们指代的是逐个名字而不是包含查询. 布局是位置和大小,单独和通常每个断点,这就是为什么一个在电话上看错的部件是一个布局问题,从不是一个部件问题."
  - q: "你会如何审计一个缓慢的仪表板 从它的 JSON? 。 。 。"
    a: "数步骤对部件。 十二个部件的十一步意味着什么也没有共享,屏幕正在进行十一次圆形旅行;十二个部件的四步是一个有人想到的屏幕. 然后,我寻找只在演示文稿中有所不同的步骤——一个标题编号,一个条形图和一个相同度量的表格通常可以是一个查询. 审计在文本编辑器中需要30秒左右,在构建器中做起来很尴尬."
  - q: "你怎么在你继承的仪表盘上 找到每个绑起来的?"
    a: "搜索 JSON 用于绑定语法. 绑定物在界面中是看不见的——它们生活在单个的配置面板中——因此在构建器中发现它们都意味着打开每一个部件. 在文档中,它们是可擦拭的, 10秒给你的依赖地图, 否则需要一个下午。 然后把地图写进仪表板的描述 这样下一个人就不会重复练习了"
  - q: "剪辑前要注意什么?"
    a: "先导出一份副本, 每次—— 撤销的故事是我事先保存的。 保存前验证, 因为跟踪的逗号会产生一个不会加载的文件, 以及比验证器给出的更模糊的错误 。 绕行它:在构建器中重新装入并确认它仍然打开并仍然视线编辑, 因为有效 JSON 建造者无法重建 才是最重要的失败 并将其检查为受限制的用户,因为编辑到阶梯和过滤器以管理员账户无法看到的方式与行级安全交互."
  - q: "你会把仪表板 JSON 在版本控制中?"
    a: "对于生产仪表板,是的——每个仪表板出口,经过重大改变后再出口,承诺有句子说明原因. 它不是部署自动化;仪表板仍然在矿石中。 这是一种记录,也是改变控制产品报价的最接近的事情。 当有人问为什么数字在3月移动, 历史通常是整个调查。"
  - q: "你从不拿什么?"
    a: "正在添加或删除部件 。 建造者保持部件、其步骤和每个布局的一致性;通过手,我必须正确地将其添加到每个断点上,失败是沉默的——一个放在桌面上的部件,在电话上完全没有。 机械的,重复的改变作为文本;界面的结构变化."

# 电线板 JSON: 访谈问题

这个问题通常是一个代理. 采访者想知道你是否 维持了规模的仪表板, 因为最后谁在 JSON。 。 。 。

::note{icon="i-lucide-star"}
**土地是审计的答案** 计数步骤与部件,以解释慢仪表板. 这是具体的,这是一件你只能通过完成它才能知道的事情, 它显示你把性能当作是衡量的东西而不是猜测的东西。
::

## 值得回忆的三句话

1. **"步骤是查询,部件按名称参考,布局是每个断点的位置".**
2. **"与部件相对立的步骤——这就是负载时间的故事".**
3. **"编辑前的输出; 撤销的故事是你所保存的一切。"**
