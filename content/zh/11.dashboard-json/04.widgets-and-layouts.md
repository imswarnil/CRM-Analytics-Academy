# 部件和布局

一个部件是 *什麽* 绘制。 一个布局是 *它坐在这里*。 。 。 将它们分开是让一个部件在宽屏幕和电话上位置不同的原因——这就是为什么部件中从未出现定位问题。

## 部件

每个部件条目都命名其类型、输入步骤及其显示参数。 文本中值得知道的属性 :

::field-table
---
dataset: "widget properties"
grain: "one row per property group"
fields:
  - name: "type and step"
    type: "what and from where"
    role: "key"
    note: "图表、表格、数字、文本、过滤器、图像、容器。 加上阶名. 更改部件读取的步骤是在此编辑一个字, 并在构建器中点击若干次 。"
  - name: "title and subtitle"
    type: "the text"
    role: "dimension"
    note: "包括任何使标题动态的绑定表达式. 搜索标题是找到屏幕上可以看到的部件的最快方法 。"
  - name: "formatting"
    type: "number format, colours"
    role: "measure"
    note: "小数位,货币,缩写,有条件的格式化规则及其阈值. 批量编辑最常见的是,因为格式化决定通常同时适用于十几个部件."
  - name: "faceting behaviour"
    type: "does it respond"
    role: "dimension"
    note: "此部件是否对其它选项作出反应 。 不可移动的引用部件是这里的属性 -- -- 在 JSON 可以在每一个部件上一目了然,而不是打开每个面板。"
---
::

::tip{icon="i-lucide-replace"}
**散装格式化是每天最好使用的 JSON。 。 。 。** 有人决定货币的缩写 整个仪表盘上没有小数 在十二个面板的建造者中,以及缺少一个面板的好机会;作为文本,它是一个寻找和替换的场所,不能错过任何面板。 屏幕上每个有条件格式的阈值变化也是如此。
::

## 布局,为什么会让人惊讶

布局是抓住你的一部分, 因为通常有 **多个** ——一组断点,每个断点都有自己的位置和大小.

::warning{icon="i-lucide-smartphone"}
**一个部件可以存在于一个布局而不是另一个布局中.** 在预览桌面时在构建器中添加一个部件,电话布局可能无法接收到它——所以对于一个小屏幕上的任何人来说,这个部件只是缺失,没有任何东西可以表示. 同样,删除一个部件并在另一个布局中留下一个已忽略的引用会产生空位 。 如果一个仪表盘在一个设备上看错,另一个设备右侧,布局就是在那里看,部件几乎肯定很好.
::

::lesson-steps
---
items:
  - title: "结构变化后检查每个断点"
    description: "添加、删除或调整部件大小默认会影响一个布局。 在运算前的桌面,平板电脑和电话宽度预览——分析标签比 Studio 更窄,这是许多观众实际所在的地方."

  - title: "照顾孤儿"
    description: "引用一个已不存在的部件的布局条目会留下空白 。 那个 JSON 这使得它可以找到; 建造者大多没有。"
---
::

## 集装箱和组合

容器组装部件,使一组部件能够定位、显示或隐藏在一起。 习惯上,它们把相关的部件放在交叉点上 大量使用时,它们会筑起若干层深的巢穴,变得像连锁绑定一样难以解释——同样的可维护性规则适用.

## 往返测试

::note{icon="i-lucide-refresh-cw"}
**在任何手编辑后:保存,在构建器中重新装入仪表板,并确认它仍然打开和编辑.** 一些手写结构是有效的 JSON 建设者无法重建成其视觉形式,您想在三周后当同事试图改变标题时立即发现这一点。 如果往返失败, 请返回您在开始前出口的复制件 。
::
