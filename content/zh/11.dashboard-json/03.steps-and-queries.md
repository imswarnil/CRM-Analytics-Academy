# 步骤和查询

一个步骤是带有名称的查询定义. 所有部件显示都来自一个

## 脚踏实地

- **它的数据集** - 读到哪个
- **形状** 组合、计量和过滤器,作为结构化属性,构建者可以编辑或作为原始 SAQL。 。 。 。
- **它的名称** ——部件和装订如何称呼它.
- **其选择行为** ——当一个查看器点击这个步骤驱动的东西时会发生什么,包括它是否与其它东西和它的初始选择相关.

::warning{icon="i-lucide-lock"}
**将步骤转换为原始 SAQL 在实践中可以是单向的。** 一旦一个步骤带有手写查询,视觉编辑器可能无法重建结构化的形式,所以下一个人物会编辑文本或重建部件. 对于建设者真正无法表达的事物来说,这是可以接受的交易,对于你用手书写出的一个问题来说,是可怜的交易。
::

## 静态步骤

不是每个步骤查询数据。 页:1 **静态步骤** 持有一个固定的值列表——切换中的选项,一组阈值,一个标签列表. 它们是如何切换一个措施 得到它的选择, 而且它们很便宜: 没有查询, 没有往返。

::tip{icon="i-lucide-list"}
**如果静态步骤的价值观是商业规则,那么它们的位置就错了.** 输入仪表板静态步骤的阈值会隐蔽不动——没有人审查仪表板的 JSON 当企业更改其"处于风险"的定义时. 带和阈值属于食谱中,桶装课所放;静态步骤是用于"ARR / Deal count"等接口选项.
::

## 过滤器居住在多个地方

一个部件可以通过步骤本身的过滤器,仪表板过滤器,面部选择器,以及安全前提来缩小. 当部件显示的行数少于预期时, JSON 告诉你第一个——人们常常记得那里有一个。
