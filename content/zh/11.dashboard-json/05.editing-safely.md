# 安全编辑

Dashboards是没有真实版本历史的Org元数据. 无论什么纪律,你带来的纪律。

## 四个习惯

::lesson-steps
---
items:
  - title: "在编辑前导出"
    description: "每次,无一例外。 手部编辑的倒数故事 是您事先保存的拷贝, 您需要的时候是您没有接受的时候。"
  - title: "保存前验证"
    description: "粘贴到任意 JSON 验证器 。 后面的逗号或不平衡的牙套会产生一个不会加载的文件,而你得到的错误很少像验证器给你的那么具体."
  - title: "在建设者中绕行"
    description: "重新装入并确认它仍然打开, 并且仍然在视觉上编辑 。 有效 JSON 建构者无法重建是最重要的失败模式,它出现在此处而不是验证器中."
  - title: "检查为受限制的用户"
    description: "这条路和其他地方一样 编辑更改步骤或过滤器可以以管理员账户中看不见的方式与行级安全交互."
---
::

## 迪夫是真正的奖品

::note{icon="i-lucide-git-compare"}
**JSON 是文本,所以更改为 diff 。** 这使得"我更新了输油管仪表板"——不可审查,一周内被遗忘——变为14行,显示究竟移动了哪些阈值,增加了哪些滤波器. 改变对这个产品的控制是最接近的, 它的成本仅是保存出口文件的历史。
::

一个可操作的、低效的版本:

- 导出每台生产仪表板 JSON 进入仓库,每个仪表板一个文件。
- 任何重大变更后再出口,并作出有关原因的判决。
- 当一个数字被争议,历史答案 *什么变化和何时* 直接——这通常是整个调查.

这不是部署自动化;仪表板仍然在矿石中。 这是一个记录,一个记录是你想要的 现在有人问为什么数字在3月份移动。

## 批量编辑, 小心完成

::warning{icon="i-lucide-search-x"}
**寻与换位是来此之因,是破一切之道.** 重新命名一个字段,有一个简短的,通用的名称—— `Amount`, (中文). `Type`, (中文). `Region` ——也会在标题,标签和不相关的属性内击中它. 匹配比空字更多的上下文,审查每个替换而不是替换全部,并保持编辑的狭义,使diff在之后可以读取.
::
