# 盘片解剖

四部分,一旦你知道是什么, 一个不熟悉的仪表板文件停止 恐吓。

## 四个部分

::field-table
---
dataset: "top-level structure"
grain: "one row per part"
fields:
  - name: "state"
    type: "the container"
    role: "key"
    note: "包罗下面的一切——仪表盘自己的设置加上三个收藏. 当文件说\"仪表盘\" JSON',这通常是它的意思。"
  - name: "steps"
    type: "where data comes from"
    role: "key"
    note: "查询定义,各有名称. 一个步骤命名其数据集、其组合和措施、任何过滤器,并经常标明 SAQL 它本身。 部件按名称引用步骤,这就是为什么正确命名它们很重要的原因."
  - name: "widgets"
    type: "what is drawn"
    role: "dimension"
    note: "每个可见元素一个条目:类型(图,表,数字,文本,过滤器),该步骤为它提供素材,其显示参数——标题,格式,颜色,面部行为."
  - name: "layouts"
    type: "where things sit"
    role: "dimension"
    note: "位置和大小,与部件本身分开。 通常不同屏幕宽度的多个布局,这就是为什么一个在构建器中看起来正确的变化在电话上可能是错误的."
---
::

## 他们如何互相称呼

部件不包含查询; 它 **命名一个步骤**。 。 。 几个部件可以命名相同的步骤,这正是标题编号,条形图和表格可以共享一个查询而不是发布三个查询的方式.

::tip{icon="i-lucide-merge"}
**阅读 JSON 是审计仪表板性能最快的方法.** 数步数部件. 12个部件对11个步骤意味着几乎什么也没有共享,屏幕正在进行11次往返;12个部件对4个步骤是一个有人想到的仪表板。 本次审计在文本编辑器中需要30秒,在构建器中完全表现尴尬.
::

## 名称是可读层

步骤名称随处可见:部件参考它们,装订参考它们,它们是你在追踪任何东西时所读到的.

`step_7` 告诉你什么。 `closed_won_by_segment` 告诉下一个人,在他们读出其中的一行之前查询是什么——由于按名称绑定参考步骤,好的名字是可辨别的安排和谜题的区别.
