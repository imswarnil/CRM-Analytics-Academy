# 栏和列图

相同的图表,两个方向,以及更多的仪表板是由它的排序顺序决定的,而不是本节中的其他任何东西.

## 水平或垂直

::compare-cols
---
items:
  - title: "水平条"
    subtitle: "Categories that are words"
    icon: "i-lucide-align-left"
    pros:
      - "Labels read naturally, at any length"
      - "Ranking reads top to bottom, matching how people scan"
      - "Handles many categories without rotating text"
    cons:
      - "Feels unfamiliar to people expecting columns"
    verdict: "The default for segments, products, reps, sources."
  - title: "垂直列"
    subtitle: "Categories that are periods"
    icon: "i-lucide-align-end-horizontal"
    pros:
      - "Time reads left to right, which readers expect"
      - "Good for a small number of short labels"
      - "Pairs naturally with a line on the same axis"
    cons:
      - "Long labels rotate, and rotated labels slow reading"
    verdict: "Months, quarters, stages — anything with a natural order."
---
::

## 排序是最重要的环境

CRM Analytics 类型 **分组** 默认,表示文本类别的字母。 这几乎从来都不是条形图的目的。

::warning{icon="i-lucide-arrow-down-wide-narrow"}
**读者假设栏杆排名.** 出示条形图后,眼睛将第一根条作为最大的条,不再检查. 当顺序按字母顺序排列时,这个假设是沉默错误的,误读是隐形的——图表正确,读者不是. 按任何绝对组合的尺度来排序,并且只按时间和真正有序的阶段来维持组合本身的顺序.
::

## 基线规则

对于酒吧, **长度是编码**。 。 。 一个酒吧两倍长意味着价值的两倍,读者不考虑就依靠它.

::note{icon="i-lucide-ruler"}
**因此条形图的轴必须从零开始.** 将其截断到40,因为每件东西都坐落在40到60之间,20%的差值变为3倍长的条,图中记录的是比例,而每个标签仍然准确. 如果细小的差别和零使它们变得无形,那就是使用线条图、点图或三角形对照目标的信号——而不是移动条的基线。
::

## 需要改变的实际环境

::lesson-steps
---
items:
  - title: "按尺度排序"
    description: "为每一个绝对的组合。 这是部件上唯一的最高值变化 。"
  - title: "限制在顶级N,并在标题中这样说"
    description: "十条可读;四十条是纹理. '按ARR算出10个账户'而不是‘按ARR算出账',否则有人将可见的栏杆进行总和,报告总数是错误的."
  - title: "把值放在栏上"
    description: "数据标签完全为少数条删除轴读步骤. 一旦图表足够密集,它们就会碰撞"
  - title: "使用一个颜色"
    description: "每个类别都有单独的颜色编码无——该类别已经是轴标签. 将颜色花在需要注意的一个栏上,其余的保持中立."
---
::

::tip{icon="i-lucide-palette"}
**一种颜色,一种例外。** 条形图中,每个条是不同的颜色外观,设计时不会额外沟通. 一个条形图在一个单一的中性,口音中一个条在阈值以上或以下,在读者读取标签之前,传达一个发现.
::
