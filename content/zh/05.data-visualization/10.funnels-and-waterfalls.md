# 漏斗和瀑布

两张图 **布局带有含义**。 。 。 。 重新订购其中之一,它就不再是同一索赔。

## 漏斗

顺序阶段,每一个子集之前的。 会议——领导——合格——机会——结业获胜。 相邻阶段之间的下降是发现.

::note{icon="i-lucide-arrow-down-narrow-wide"}
**过程顺序,从不大小顺序.** 一个按大小排序的漏斗只是条形图,它摧毁了一个漏斗所做的一件事:将相邻的相位放在相邻的相邻的相邻的相位上,这样它们之间的滴滴就可见了,而没有算术. 这是在条形图之后的赛程中最间接的排序。
::

### 尺度问题

真正的漏斗横跨数量级,打破线性版本:

---

    note: "漏斗的顶部矮化了下面的一切"
  - label: "铅"
    value: 2800
    note: "还能看出来"
  - label: "合格"
    value: 1120
    note: "摇摇晃晃"
  - label: "机会"
    value: 677
    note: "在线性尺度上,这是根根"
  - label: "已关闭赢"
    value: 275
    note: "这几乎是无形的"
caption: "Namilio,日志尺度——每个阶段都可读取"
scale: "log"
---
::

::warning{icon="i-lucide-ruler"}
**这里的日志表是诚实的,只要你说。** 在线性轴上,一个数十万至数百个漏斗使最后四个阶段成为相同的疏漏阶段——这四个阶段是销售发生的地方。 日志可以辨认出来 是什么让它诚实而不是狡猾 标注轴作为对数 并把转换百分比 放在图表上, 所以没有人读巴长度 是一个比例。
::

### 阶段之间的速率是点数

绝对数是上下文; **相邻阶段之间的转换** 是别人的行为 将百分比放在每一对之间, 并明确你使用的分母—— 一步到一步,或者每个阶段对顶。 它们是不同的数字,两者都被称为"转换率".

::field-table
---
dataset: "funnel conventions"
grain: "one row per decision"
fields:
  - name: "Step conversion"
    type: "stage ÷ previous stage"
    role: "measure"
    note: "诊断:漏水在哪里。 这是一个团队每周演出。"
  - name: "Cumulative conversion"
    type: "stage ÷ top of funnel"
    role: "measure"
    note: "战略:需求的多少部分成为收入。 有用於计划 也没用於发现泄漏"
  - name: "Cohorting"
    type: "by entry date"
    role: "date"
    note: "每一个阶段都必须计算出 跟踪到的同母体群 每一个阶段都计算这个时期所发生的事情的漏斗并不是漏斗——它混合了在不同时间进入的人,转换率意味着什么."
---
::

## 瀑布

一座桥:从一个总数开始,加减,到另一个总数。 纳米利奥的ARR瀑布是犬科的病例——打开ARR,加上新的,加上扩张,减收缩,减切,等于关闭.

::lesson-cards
---
columns: 3
items:
  - title: "桥"
    icon: "i-lucide-waves"
    description: "每个栏在前一栏所剩的关卡上浮起,所以眼跟随运行的总数. 这使得它与同一数字的叠列不同."
  - title: "视觉标志"
    icon: "i-lucide-plus-minus"
    description: "添加和减值需要一目了然地读作相反的——方向和颜色在一起,永远不要单独着色."
  - title: "始末为锚"
    icon: "i-lucide-anchor"
    description: "打开和关闭的栏杆坐落在基线上,而不是浮动. 没有这些锚 图表是一组三角洲 没有尺度。"
---
::

::tip{icon="i-lucide-calculator"}
**请在信任图表之前的某个时期检查算术.** 开放加上运动应该完全结束。 如果没有,则数据中缺少一个运动,或者过滤器排除了行——一个不调和的瀑布是目前最尴尬的单一图表,因为读者可以做他们头部的添加.
::

CRM Analytics 每个发行版中都没有专门的瀑布部件,所以这往往被建为带有隐形基序列的堆叠柱,或者作为与运行中计算总量的比较表。 两者都很好;重要的是,栏杆浮起,锚坐到基线上。
