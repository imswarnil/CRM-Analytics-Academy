# 重复

"我们有重复"描述了三个无关的问题. 判断你拥有的哪个是整个教训,因为每个教训的修补是不同的,其中两个不应该涉及删除任何东西.

## 这三种

::field-table
---
dataset: "what \"duplicate\" means"
grain: "one row per kind"
fields:
  - name: "A join artefact"
    type: "most common, not a duplicate at all"
    role: "key"
    note: "行乘以一对多加. 记录很好; 查询错误 。 定律是在加入之前将许多方面聚合起来,或者不将母计量带向下——从不重复步骤,这可以删除真实数据,在不良的加入周围工作."
  - name: "Legitimate repetition"
    type: "the intended grain"
    role: "dimension"
    note: "一个账户在每月的快照中出现18次,这个产品出现在许多机会上. 这是谷类的正常工作。 拿掉它,你就破坏数据集的目的"
  - name: "Genuine duplicate records"
    type: "the real problem"
    role: "measure"
    note: "同一个现实世界的东西输入了两次——一个公司的两个账户记录,一个线索从三个表格中提交了三次. 唯此二法求解脱二谛,是三谛中最难得."
---
::

::warning{icon="i-lucide-triangle-alert"}
**删除行以修正扇形出局是目前最有害的反应.** 总数下来了,所以看起来它奏效了,你现在删除了真实的记录,同时把错误的加入留在原位上——所以在同一个食谱上添加的下一个度量又错了,在不同的方向上,数据集不再符合它的源. 删除前进行诊断:在每个连接节点前后进行数行,并查找其乘数位置.
::

## 找到真实的重复

::lesson-steps
---
items:
  - title: "定义“ 相同” 的含义"
    description: "同样的电子邮件? 相同的公司名称和域名? 相同的名字和邮编? 这是一个商业决定,它决定了下游的一切——一个集团的两个子公司可能是或者不是同一个账户,答案因公司而异."
  - title: "先数候选人"
    description: "每组按键和数行分组,然后触摸任何东西。 30个重复组是一个清理;3 000个组是一个源系统或整合问题,下游的修复就是永远治疗一种症状。"
  - title: "用眼睛检查样本"
    description: "拔十种复组看. 它们往往根本不是重复的——一个母公司和一个子公司,两个真正不同的联系人和一个共享的收件箱——而你的匹配规则过于松散."

    description: "最近从首选源系统修改,最完整. 写下来, 一致应用, 永远不要“ 哪个先来” , 因为这很稳定, 直到数据以不同的顺序到达。"

## 幸存者就是价值所在

::note{icon="i-lucide-merge"}
**保持最新的一行往往会失去最多的信息.** 上星期创建的复制品可能包含三个区域,其中较大的一个有12个。 真正的去重复通常会合并——在现时的每个字段取最新值,回落到旧的记录中——而不是选择一行,抛弃其余的. 这是食谱中更多的工作,也是清理数据与丢失数据的区别。
::

## 将它往上游修

在食谱中减少重复是一种工作。 它夜以继日,永远运行,源系统不断产生复制品,其他消费者也必须处理.

::tip{icon="i-lucide-arrow-up"}
**向拥有源头的人报告重复率。** 每周按来源统计新的重复组比清理本身更有价值的可交付性:它将一个无形的数据质量问题变成一个人可以拥有的数字。 食谱级的修补使你的仪表板在此期间正确无误,这正是一个工作周期应该做的——在真正的修补发生在别的地方时保持线条.
::

## 检查后

在任何切换后,将行数和密钥总数与源数进行比较. 清除了40行,收入变动了8%的清理并没有消除重复——它删除了不同的记录,而检查是唯一在仪表盘之前捕获它的东西.
