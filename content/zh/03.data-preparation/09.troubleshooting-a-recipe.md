# 解决食谱问题

一种方法,按照顺序,所以调试是一种程序,而不是即兴.

## 命令

::lesson-steps
---
items:
  - title: "先监视器"
    description: "它运行,何时, 和多少行? 大约三分之一的“数字是错误的”报告在这里结束——答案是,它最后一次运行是在星期五。 这需要15秒 排除最大的单一类别。"
  - title: "比较行数与历史"
    description: "一个连续数月持-2,800行,现在持2,100行的数据集存在问题,没有仪表板会报告. 如果您的鼠标没有跟踪到此点, 请在某个地方注意预期的数—— 这是可用的最便宜的回归测试 。"
  - title: "移动节点预览"
    description: "按顺序单击每个节点并读取其行数。 计数发生意外变化的节点是问题所在的节点. 这在大约一分钟内将一个谷物问题本地化,这就是为什么食谱会为任何你需要调试的东西击败数据流的原因."
  - title: "过滤到一个实体"
    description: "选择单一的账户或机会,过滤预览到它,然后用手数. 这能告诉你究竟哪边是乘数 哪个行消失了 看着一个聚合物什么也不告诉你"
  - title: "然后,只有那时,仪表板"
    description: "部件查询,面部和过滤器是最后的嫌疑人. 他们通常忠实地报告他们得到什么。"
---
::

## 引起症状

::field-table
---
dataset: "diagnosis table"
grain: "one row per symptom"
fields:
  - name: "Total is 2× or 3×"
    type: "fan-out"
    role: "measure"
    note: "父母的衡量标准在子女行之间重复。 行走合场;计数跳过违法节点."
  - name: "Total is slightly high"
    type: "partial fan-out"
    role: "measure"
    note: "只有部分父母有多个孩子. 更难发现,因为它不是一个干净的多重——即现实世界的默认."
  - name: "Rows missing for everyone"
    type: "inner join or upstream filter"
    role: "key"
    note: "内联是穿联赛服装的过滤器. 请检查access-date=中的日期值 (帮助)"
  - name: "Rows missing for SOME users"
    type: "row-level security"
    role: "key"
    note: "完全不是一个食谱问题。 上游或分享遗产,按数据准备部分。 事实是,这对你很好,对他们来说是错误的。"
  - name: "A column is entirely null"
    type: "sync or permissions"
    role: "dimension"
    note: "字段没有同步选择,或者集成用户无法看到. 它不存在而不是空——在重建任何东西之前检查输入节点的列列表."
  - name: "Numbers change every run"
    type: "a non-deterministic recipe"
    role: "date"
    note: "通常相对日期过滤器——\"最后30天\"的动作,或者在非唯一密钥上选择任意匹配的加入. 第二个是Nastier:它稳定,直到下面的数据发生变化。"
  - name: "Everything is one day old"
    type: "schedule dependency"
    role: "date"
    note: "食谱在同步完成前运行. 到处都是绿色的, 总是僵化。 比较两个时间表和实际运行时间."
---
::

::tip{icon="i-lucide-undo"}
**当你做出改变后 食谱就失效了 在调查前取消更改** 从破碎的状态向前调试是诱人的;返回工作状态并重新应用小块的变化速度更快。 这是普通的工程学科,在每部编辑都觉得小的视觉工具中被抛弃是异常容易的.
::
