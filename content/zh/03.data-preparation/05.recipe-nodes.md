# 管道节点

七个节点类型几乎什么都做。 学习他们的有益方式不是按字母顺序排列的,而是按每个人对 **谷物**,因为谷物是唯一必须跟踪从第一个节点到最后一个节点的财产.

## 按谷物的影响分类

  - name: "Formula"

## 你将不断使用的模式

**集合,然后回来。** 几乎每个"我每Y需要一个X数"就是这个形状:

::lesson-steps
---
items:
  - title: "分行多边"
    description: "将机会作为自己分支的投入,独立于账户。"
  - title: "把它加起来"
    description: "按账户分组 Id;制作机会数,总和,最大接近日期——无论账户行实际需要什么."
  - title: "回到一边去"
    description: "按 AccountId 将合计数并入账户 。 现在两边每个帐户各一行,所以加盟不能乘."
  - title: "检查计数"
    description: "140个账户,140个账户。 如果不是140,总和并没有像你想象的那样崩溃,在到达仪表板之前你已经发现了问题."
---
::

::tip{icon="i-lucide-eye"}
**经常使用节点预览,而不是偶尔使用.** 每个节点都显示其输出. 点击链条并观看每一步的行数,是产品中最快的调试工具,它使得一个粒变化不可能错过——在你面前的数字变化,在负责的确切节点.
::

## 加入: 知道你选择哪一种

- **查找/ 左边** ——将每行保留在左边,在有匹配的地方从右边添加列. 非匹配行保留左值并获得无值. 这是通常的选择。
- **内在** ——两侧只保持行匹配. 合法,而"记录缺失"的静悄悄的原因:一个被提前过滤出账户的机会悄悄消失了.
- **外部变体** ——不让一边或两边不匹配的行,以空补空补空.

::warning{icon="i-lucide-scissors"}
**内联是穿联赛服装的过滤器.** 它可以删除行,它这样做是在你考虑添加列而不是删除记录的时候. 当行缺失和权限检查出时,下一个嫌疑人是上游的内联.
::

## 保留小菜谱

没有硬节点天花板,有一个实用的天花板。 过去大约20个节点的食谱不再被任何不写它的人读取,失败也停止了本地化——你再也无法知道三分之一的管道坏了。

::note{icon="i-lucide-split"}
**分于意义,而非大小.** 由一种食谱制作的清洁基础数据集,以及由其他阅读者制作的两个衍生数据集,比较容易说明理由。 *和* 修复速度快于一个长链. 费用是正确订购的又一个时间表——鉴于以往课程的依赖性陷阱,这是一个值得认真对待而不是忽视的费用。
::
