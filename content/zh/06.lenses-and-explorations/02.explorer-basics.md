# 探索者基础

四个控制。 探索中的其他一切都是它们的结合.

## 措施回答"多少"

衡量是总和:总和、数行、平均日数、最大关闭时间。 改变度量衡会改变问题,而根本不改变图表的形状——这是值得注意的,因为它是最干净的证明,一个图表就是对一个查询的渲染,而不是事物本身.

::warning{icon="i-lucide-hash"}
**行数是指行数,而不是你所想的.** 在纳米利奥的线粒体中,1,378行是677个机会. 如果您的数据集的谷物比您所统计的实体要精细, 请使用该实体的密钥来进行明确的计数 。 这是从数据集和建模部分 穿不同衣服的同样的谷类问题, 它抓住了那些认为他们学到了它的人。
::

## 分组回答“按什么”

添加一个组合, 一个栏变成很多 。 分析内容是:按部门、区域、月、代表、来源。

::note{icon="i-lucide-layers"}
**第二组是大多数图表死的地方.** 一个分组是一个比较。 二是对比较的比较,读者在解码一个传说时,必须把两者都放在头上. 偶尔,这正是重点所在——逐段收入确实需要两者。 之所以增加第二个分组,是因为有可能。 当你添加一个,问它回答什么问题 第一个没有。
::

## 过滤器回答“ 在哪个”

过滤器将行缩小 。 两个值得提前内化的点:

- **无效者不因不平等而受排斥。** `Stage != "Closed Lost"` 也删除了Stage为无效的每行,这很少是打算而且从未宣布。
- **勘探上的过滤器不是仪表板上的过滤器.** 第5节涵盖了仪表板滤镜,面部和这个相互作用的方式;目前,知道一个镜头滤镜属于镜头.

## 限制和诚实问题

显示140个账户中前十名是很好的设计. 显示140个账户中前十个账户 *上面写着,好像他们都是一样* 是误导。

::tip{icon="i-lucide-tag"}
**设限于标题.** "ARR的Top 10账户"而不是"ARR的账户". 它花费4个字,它去掉了一整类的误读——包括有人将可见的栏杆加起来,得出总数是错误的.
::
