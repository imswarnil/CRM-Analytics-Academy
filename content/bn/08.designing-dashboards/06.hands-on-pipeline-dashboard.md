  org: "Analytics Studio, the Academy Analytics app, with the opportunities dataset loaded and its grain confirmed"
  shots:
    - shot: "Write the brief before opening the builder"
      screen: "Notes — audience, question, decision, cadence"
      say: "The VP of Sales opens this on Monday morning and decides two things: whether the quarter is covered, and which stage needs attention this week. Write that down first. Every widget from here either serves those two decisions or does not go on."
      onscreen: "Two decisions. That is the scope."
      seconds: 45
    - shot: "The headline, top left"
      screen: "New dashboard → Number widget → open pipeline amount, current quarter"
      say: "Open pipeline for the current quarter, top left, where reading order begins. Someone who reads nothing else leaves with the number the screen is about. Format it as abbreviated currency — no cents on a multi-million figure."
      onscreen: "$ headline, top left"
      seconds: 40
    - shot: "Coverage, beside it"
      screen: "Number widget → pipeline ÷ quota, as a ratio with one decimal"
      say: "Coverage is pipeline divided by the number the team has to hit. This is the widget that turns a big number into a judgement — four million is meaningless until you know whether the target is one million or eight. Put the target in the widget's subtitle so nobody has to ask."
      onscreen: "A number needs a denominator"
      seconds: 45
    - shot: "The funnel"
      screen: "Funnel or bar widget → count and amount by StageName, in stage order"
      say: "Stages in process order, not sorted by size. This is the one chart where alphabetical or descending sorting destroys the meaning — the sequence IS the argument, because the drop between two adjacent stages is what you are looking for."
      onscreen: "Process order, never size order"
      seconds: 45
    - shot: "The trend"
      screen: "Line widget → pipeline created by month, last six months"
      say: "Pipeline created per month for six months. This answers is-this-normal, which a single number can never answer. Group by created month, not close month — cohorting on the wrong date is the error section three warned about and it looks completely plausible."
      onscreen: "Created month. Not close month."
      seconds: 45
    - shot: "The exception table"
      screen: "Table widget → deals over 60 days in stage, columns: Deal, Account, Stage, Amount, Days"
      say: "Ten rows maximum, sorted by days in stage descending. This is the widget that makes the dashboard actionable — it names the deals somebody should chase today. Give it an empty-state message, because when the team is doing well this table is empty and an empty table with no words looks broken."
      onscreen: "Name the deals. Ten rows."
      seconds: 50
    - shot: "Turn off faceting on the reference"
      screen: "Select the coverage widget → properties → faceting off"
      say: "Coverage against the full quarter target must not move when somebody clicks a stage. If it filters along with everything else, the comparison it exists for disappears at the exact moment it becomes useful. This is the one widget on the screen that should ignore the rest."
      onscreen: "A reference must not move"
      seconds: 40
    - shot: "Dynamic titles everywhere"
      screen: "Each widget title → bind the current filter selection"
      say: "Bind the selection into the titles. Assume every one of these widgets will be screenshotted and pasted into a message with no context — a title reading pipeline, EMEA only, Q3 survives that journey, and a title reading pipeline becomes a company-wide number in somebody else's argument by Thursday."
      onscreen: "Titles survive screenshots"
      seconds: 45
    - shot: "Check against the answer key"
      screen: "README.md → open pipeline total → compare"
      say: "Compare your headline with the README. If it is high by a clean multiple you have a fan-out from a join; if it is low, check whether a filter is excluding nulls as well as the values you meant to exclude. Do not ship until it matches, and do not tell yourself it is close enough."
      onscreen: "Match, or find out why not"
      seconds: 40
    - shot: "Open it as somebody else"
      screen: "Log in as the restricted test user from the access section"
      say: "Last step, every time. Open it as the test user you created when you set up the predicate. You are checking two things: that they can see it at all, and that what they see is their slice rather than everybody's. Signing off a dashboard from your own admin account is how security mistakes reach an audience."
      onscreen: "Never sign off from your own account"
      seconds: 45

# হাত: পিলাইন ড্যাশবোর্ড

৯০ মিনিট। সিক্স উইজেট, ৩ টা প্রত্যাখ্যান করে, আর ঐ দুটো চেক যে কেউ দেখতে পাবে না।

::build-brief
---
dashboard: "Pipeline Health"
audience: "The VP of Sales and four regional directors"
question: "Is the quarter covered, and which stage needs attention this week?"
decision: "Where the leadership team spends this week's attention — which stage, which region, which deals"
cadence: "Opened Monday morning; reviewed in the weekly pipeline call"
success: "Coverage readable in four seconds, and the stuck-deal table short enough to act on the same day"
datasets:
  - "opportunities.csv"
  - "accounts.csv"
  - "reps.csv"
notInScope:
  - "Rep leaderboards. The directors asked; the answer is no on this screen, because a dashboard that ranks people gets read for the ranking and the pipeline question stops being asked"
  - "Forecast. Forecasting is Build 13 in the RevOps section and it is a different discipline — putting a forecast beside raw pipeline invites people to treat pipeline as a forecast"
  - "Closed-won revenue. This screen is about unsold pipeline; mixing sold and unsold on one dashboard is the most common way an exec screen misleads"
---
::

## মেট্রিক, উল্লিখিত

::metric-spec
---
items:
  - name: "Open Pipeline"
    formula: "sum(Amount) where the opportunity is open and CloseDate falls in the selected quarter"
    grain: "one value per filter selection"
    source: "opportunities.csv"
    watchout: "Open means not closed-won AND not closed-lost. Writing it as 'StageName != Closed Won' silently keeps every closed-lost deal in the pipeline, and the number looks healthy for exactly the wrong reason."
  - name: "Coverage"
    formula: "Open Pipeline ÷ quarter target"
    grain: "one value per filter selection"
    source: "opportunities.csv, with the target as a fixed figure"
    watchout: "The target must not facet with the selection. Filter to EMEA and the pipeline narrows correctly while the company target stays put — which is why this widget has faceting off and its denominator stated in the subtitle."
  - name: "Days in Stage"
    formula: "today − the date the opportunity entered its current stage"
    grain: "one value per opportunity"
    source: "opportunities.csv"
    watchout: "Needs a stage-entry date. If the dataset only carries the last-modified date, this measures editing activity rather than stage movement — a deal someone touched yesterday looks fresh while having sat in the same stage for four months."
---
::
