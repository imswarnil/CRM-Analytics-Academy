      screen: "A notes file, before touching Salesforce"
      say: "Write the sentence before the syntax: a rep sees accounts in their own region, a regional director sees their whole region, and finance sees everything. If you cannot write that sentence you are not ready to write the predicate — and the sentence goes in the project notes, because in six months it is the only thing that explains the configuration."
      onscreen: "Sentence first. Syntax second."
      seconds: 40
    - shot: "Create the test user"
      screen: "Setup → Users → New User → a standard user, not an admin"
      say: "Create one ordinary user. Not an administrator — the whole point of this exercise is that administrators see everything and therefore cannot test security. Give them the CRM Analytics Plus User permission set so they can open Analytics at all, and nothing more."
      onscreen: "Plus User only"
      seconds: 45
    - shot: "Put the region on the user record"
      screen: "Setup → Object Manager → User → Fields → New → Text field 'Sales Region'"
      say: "The predicate has to compare something in the dataset against something about the viewer, so the viewer needs to carry a region. Add a custom text field to the User object, call it Sales Region, and set it to EMEA on your test user. In a real org this field usually already exists in some form — find it before creating another one, because two competing region fields on the user record is its own kind of long-running problem."
      onscreen: "User.Sales_Region__c = EMEA"
      seconds: 50
    - shot: "Confirm the column exists on the data side"
      screen: "Analytics Studio → Browse → accounts → open the lens → group by Region"
      say: "Check the dataset actually carries a Region column and look at its values. Predicates compare strings exactly, so EMEA and E-M-E-A with different spacing or casing are different regions as far as the rule is concerned. This ten-second check saves a long confusing debug later."
      onscreen: "Exact string match"
      seconds: 35
    - shot: "Open the dataset's security settings"
      screen: "Analytics Studio → Browse → accounts → the dropdown → Edit → Security Predicate"
      say: "The predicate lives on the dataset, not on the dashboard and not on the app. That is the important structural point: every query against this dataset gets the rule applied, from any dashboard, any lens, any export. There is no way to build around it from the dashboard side, which is exactly the property you want from a security control."
      onscreen: "On the dataset. Not the dashboard."
      seconds: 45
    - shot: "Write the predicate"
      screen: "The predicate field → 'Region' == \"$User.Sales_Region__c\""
      say: "Single quotes around the dataset column, double quotes around the user attribute. That asymmetry is not stylistic — it is how the syntax distinguishes a column from a value, and getting it backwards is the most common syntax error here. Save it."
      onscreen: "'Column' == \"$User.Field__c\""
      seconds: 40
    - shot: "Watch your own dashboard go empty"
      screen: "Open the Account Base Overview dashboard as yourself"
      say: "Your dashboard is probably now empty, and nothing is broken. The predicate is evaluated for you too, and your own user has no Sales Region, so you match nothing. Administrators are not exempt by default. This is the moment every person learns it, and it is much better to learn it here than in production."
      onscreen: "Admins are not exempt"
      seconds: 45
    - shot: "Add the exemption deliberately"
      screen: "Back to the predicate → 'Region' == \"$User.Sales_Region__c\" || \"$User.Sales_Region__c\" == \"ALL\""
      say: "Extend the rule so anyone whose region is the literal word ALL sees everything, and set your own user to ALL. Name the exemption in the rule rather than granting yourself something broad in a panic: it is explicit, it is reviewable, and it does not quietly hand the same exemption to the next person who inherits a profile."
      onscreen: "A named exemption, not a broad grant"
      seconds: 50
    - shot: "Now the real test"
      screen: "Log in as the test user → Analytics → the shared app → the dashboard"
      say: "Log in as the test user and open the dashboard. You should see EMEA accounts only, and the total A-R-R should be lower than yours by exactly the amount the other regions hold. If they see everything, the predicate is not saving or the field is blank; if they see nothing, check the string values match exactly. Either way you are now testing the thing you actually shipped."
      onscreen: "Check as them, never as you"
      seconds: 55
    - shot: "Check the third case"
      screen: "Clear Sales Region on the test user → reload the dashboard as them"
      say: "Blank the region field and reload. They now see nothing at all, because a null in a predicate field fails closed rather than open. That is the right behaviour and it is worth seeing once with your own eyes, so that when somebody reports an empty dashboard you already suspect a blank field on their user record."
      onscreen: "Null fails CLOSED"
      seconds: 40

# হাত: একাডেমি বন্ধ করে দেওয়া

চল্লিশ মিনিট। একটি ডাটাসেট, একটি পূর্বক গ্রহণ, ব্যবহারকারীর জন্য একটি পরীক্ষা, এবং তিনটি ফলাফল আপনি বাস্তব হিসাবে এটি করার আগে দেখা প্রয়োজন।

---

audience: "A regional sales rep, and their director"

cadence: "Same as the dashboard; the predicate applies to every query"

## বাক্যরীতি, কারণ এটা সাধারণ হোতা

```
'Region' == "$User.Sales_Region__c"
```

**একটি উদ্ধৃতি** কলামের শিরোনাম পরিবর্তন । **দ্বিগুণ উদ্ধৃতি** ব্যবহারকারীর বৈশিষ্ট্যের মান পরিবর্তন করা হবে। নিয়ম-কানুন কিভাবে একটি কলামকে একটি মান থেকে আলাদা বলে, এবং এটি সমাধান করতে আপনি অন্তত একবারই সমাধান করবেন।

সংযুক্তকারী অবস্থা ব্যবহার করা হচ্ছে `||` অথবা অথবা `&&` এবং এর জন্য

```
'Region' == "$User.Sales_Region__c" || "$User.Sales_Region__c" == "ALL"
```

::warning{icon="i-lucide-spell-check"}
**স্ট্রিং ঠিক মত তুলনা করা হয়।** `EMEA`'%s' `emea` এবং `EMEA ` অনুসরণকারীরা তিনটি ভিন্ন অঞ্চল। বৈশিষ্ট্য ধার্য করা হলে কোনো কারণ উৎপন্ন না হলে, সংশ্লিষ্ট কলামের নিজস্ব মান প্রিন্ট করা হবে এবং ব্যবহারকারীর অক্ষরের মধ্যে এর সাদৃশ্য প্রয়োগ করা হবে। এটা ফাঁকা ঘরের পর দ্বিতীয় সাধারণ কারণ, আর এটাকে ভাঙ্গা নিয়মের সমান মনে হচ্ছে।
::

## এখানে ব্যবহারকারীর বৈশিষ্ট্য ও অনুক্রম হওয়া উচিত

এই শিক্ষাটি ব্যবহারকারীর রেকর্ডের ক্ষেত্রে একটি ক্ষেত্র ব্যবহার করে কারণ এটি পদ্ধতিটিকে দৃশ্যমান করে: একটি কলাম, একটি স্থান যেখানে ভুল চেহারা দেখা যায়।

বেশির ভাগ উৎপাদন বা শর্করা অবশেষে ভূমিকা পালন করতে চায় । এই রেসিপিতে একটা ফ্ল্যাটেনের নোড লাগবে, যা ডাটা সেকশনের উপাদান। পদ্ধতিটি একরকম; শুধুমাত্র কলামটি পরিবর্তন সম্পর্কিত তুলনা করো ।

::tip{icon="i-lucide-notebook-pen"}
**চার লাইন লিখে দাও.** যে সমস্ত ডাটাতে তথ্য প্রদান করা হয়েছে, তা হচ্ছে ইংরেজী ভাষায় যা বলা হয়, যার মানে সে ছেড়ে দিচ্ছে এবং কি ভাবে এবং কি ভাবে ফল পাওয়া যায়। আজকে দুই মিনিট সময় লাগে এবং যার উত্তরাধিকার আছে তার জন্য এক সপ্তাহ সময় নেয় — সম্ভবত আপনি ভুলে যান ।
::
