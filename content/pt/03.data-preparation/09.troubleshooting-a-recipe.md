# Resolvendo problemas com uma receita

Um método, em ordem, para que depuração seja um procedimento em vez de uma improvisação.

## A ordem.

::lesson-steps
---
items:
  - title: "Monitore primeiro."
    description: "Correu, quando e quantas fileiras? Cerca de um terço dos relatórios \"o número está errado\" terminam aqui. A resposta é que a última foi na sexta-feira. Isso leva 15 segundos e exclui a maior categoria individual."
  - title: "Compare a contagem de linhas com a história."
    description: "Um conjunto de dados que manteve ~ 2.800 linhas por meses e agora detém 2.100 tem um problema que nenhum painel irá relatar. Se sua orgia não rastrear isso, note que o esperado conta em algum lugar, é o teste de regressão mais barato disponível."
  - title: "Caminhe com as prévias do nó."
    description: "Clique em cada nó em ordem e leia sua contagem de linhas. O nó onde a contagem muda inesperadamente é o nó com o problema. Isso localiza um problema de grãos em cerca de um minuto, por isso receitas batem os fluxos de dados para qualquer coisa que você terá que depurar."
  - title: "Filtrar para uma entidade"
    description: "Escolha uma única conta ou oportunidade, filtre a prévia e conte à mão. Isso diz exatamente qual lado se multiplicou ou quais fileiras desapareceram, onde olhar para um agregado não diz nada."
  - title: "Então, e só então, o painel"
    description: "Consultas de elementos, faces e filtros são os últimos suspeitos. Eles costumam relatar fielmente o que lhes foi dado."
---
::

## Sintomas para causar

::field-table
---
dataset: "diagnosis table"
grain: "one row per symptom"
fields:
  - name: "Total is 2× or 3×"
    type: "fan-out"
    role: "measure"
    note: "Uma medida dos pais duplicada nas fileiras das crianças. Caminhe com as juntas, a contagem salta para o nó ofensivo."
  - name: "Total is slightly high"
    type: "partial fan-out"
    role: "measure"
    note: "Só alguns pais têm vários filhos. Mais difícil de identificar porque não é um múltiplo limpo, o padrão do mundo real."
  - name: "Rows missing for everyone"
    type: "inner join or upstream filter"
    role: "key"
    note: "Uma união interior é um filtro usando roupas de união. Também verifique um nó de filtro cuja condição exclui nulos sem querer: 'Stage ! = Fechado Perdido' também remove todas as linhas onde Stage é nulo."
  - name: "Rows missing for SOME users"
    type: "row-level security"
    role: "key"
    note: "Não é problema de receita. A herança predicada ou compartilhada, pela seção de preparação de dados. O sinal é que é bom para você e errado para eles."
  - name: "A column is entirely null"
    type: "sync or permissions"
    role: "dimension"
    note: "O campo não foi selecionado em sincronia, ou o usuário de integração não pode vê-lo. Está ausente em vez de vazio - verifique a lista de colunas do nó de entrada antes de reconstruir qualquer coisa."
  - name: "Numbers change every run"
    type: "a non-deterministic recipe"
    role: "date"
    note: "Normalmente, um filtro de data relativo - 'últimos 30 dias' se move - ou uma junção em uma chave não-única escolhendo uma combinação arbitrária. O segundo é mais desagradável: é estável até que os dados mudem."
  - name: "Everything is one day old"
    type: "schedule dependency"
    role: "date"
    note: "A receita corre antes da sincronização terminar. Verde em todo lugar, consistentemente velho. Compare os dois horários e a duração da corrida."
---
::

::tip{icon="i-lucide-undo"}
**Quando uma receita quebra depois de uma mudança que você fez, desfaça a mudança antes de investigar.** É tentador depurar para frente de um estado quebrado, é mais rápido voltar para um que funcione e reaplicar a mudança em pedaços menores. Esta é uma disciplina de engenharia comum, e é incomummente fácil abandonar em uma ferramenta visual onde cada edição parece pequena.
::
