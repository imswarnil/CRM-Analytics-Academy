# Carregar a CSV Apropriadamente

Carregar leva dez segundos. Checar leva dois minutos. Esta lição é sobre os dois minutos, porque cada um dos três cheques abaixo previne uma reconstrução em vez de um incômodo.

## Os três cheques, por ordem de despesas.

::field-table
---
dataset: "what to verify at upload"
grain: "one row per check"
fields:
  - name: "Dates typed as dates"
    type: "most common"
    role: "date"
    note: "Uma data de texto é perfeita em uma tabela, então sobrevive a cada revisão casual. Ele não pode ser filtrado por alcance, agrupado por mês, ou tendência - e você descobre que no momento exato você precisa de uma tendência. Consertá-lo significa editar os atributos e recarregar o arquivo."
  - name: "IDs typed as dimensions"
    type: "common"
    role: "key"
    note: "Sumário da Conta A identidade não tem sentido e está disponível. Forçar cada identificador a uma dimensão em carga. Isso importa mais nas chaves que você vai juntar, que no caso da Academia é Contabilidade, Oportunidade e Campanha."
  - name: "Currency scale"
    type: "expensive when wrong"
    role: "measure"
    note: "Cada figura a jusante está sempre errada, então nada parece anormal. Compare uma única fileira com o arquivo cru por olho antes de seguir em frente."
  - name: "Row count"
    type: "always"
    role: "measure"
    note: "O conjunto de dados README indica a verdadeira contagem para cada arquivo da Academia. Off por um é um problema de cabeçalho. Zero é uma carga falhada, e Monitor detém a razão."
---
::

## Por que a resposta chave importa tanto

A Academia `README.md` afirma os verdadeiros totais: linhas por arquivo, receita fechada, ARR por mês, contagens de chumbo. Cada construção neste curso pode, portanto, ser verificada contra algo que é independentemente verdadeiro.

::tip{icon="i-lucide-check-check"}
**Verifique cada carga, mesmo quando você está confiante.** O valor não é pegar o erro que você esperava, é construir o reflexo, de modo que quando você está trabalhando em dados sem README você ainda instintivamente procurar algo para se reconciliar - uma figura financeira, uma contagem publicada anteriormente, um relatório que alguém já confia. Analisadores que fazem isso são confiáveis, analistas que não são surpreendidos em público.
::

## Quando... CSV é a resposta certa, e quando não é

::compare-cols
---
items:
  - title: "CSV Está certo."
    subtitle: "Fixed extracts, learning, one-offs"
    icon: "i-lucide-file-check"
    pros:
      - "No infrastructure, no connection, no schedule"
      - "Reproducible: the same file gives the same dataset"
      - "Perfect for this entire course"
    cons:
      - "Never updates itself"
      - "Somebody has to remember to re-upload"
    verdict: "Fine when the data genuinely does not change."
  - title: "CSV Está errado."
    subtitle: "Anything anyone expects to be current"
    icon: "i-lucide-file-x"
    pros:
      - "Fast to set up, which is the trap"
    cons:
      - "It will silently age, and it looks identical to a live dataset"
      - "The re-upload becomes one person's undocumented monthly chore"
    verdict: "Use a connection and a schedule instead."
---
::

::warning{icon="i-lucide-calendar-x"}
**A armadilha manual na produção.** A CSV Carregado uma vez se torna 'o painel' e silenciosamente envelhece. Não há nada na tela para distingui-lo de um conjunto de dados programado, e a única pessoa que sabe é quem o enviou. Se você deve enviar um, coloque a data de extração no nome do conjunto de dados - `the Academy Accounts 2026-09` - então o vazio é visível para todos ao invés de ser lembrado por uma pessoa.
::
