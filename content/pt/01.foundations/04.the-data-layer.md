# Tradução: & Datasets

Tudo impressionante em CRM Analytics - Painéis rápidos, filtragem instantânea, predições de aprendizado de máquina. **Camada de dados**. Esta camada faz dois trabalhos: **Lojas** seus dados eficientemente e **Prepare-se.** esses dados em uma forma de análise pronta. Fique confortável aqui e o resto da plataforma faz sentido. Esta lição é uma lição de membros porque é onde "usar CRM Analytics"se transforma em "compreensão" CRM Analytics. "

## Sincronia:

Antes de transformar dados, você tem que trazê-los. Esse é o trabalho de **Sincronia de dados**, às vezes chamado **Conectar**. Pense nisso como uma área de encenação: ela alcança suas fontes e puxa seus dados para CRM Analytics como pequenos conjuntos de dados individuais, um por objeto ou tabela que você sincroniza.

Pelo... **local Salesforce conexão**, Data Sincronia é especialmente inteligente:

- **Refresco incremental** - em vez de recarregar cada registro em cada corrida, ele só busca o que mudou desde a última vez. Sincronia mais rápida, carga mais leve.
- **Filtros** - Você pode sincronizar apenas as linhas que você realmente precisa (por exemplo, apenas oportunidades dos últimos dois anos), mantendo seus dados encenados magros.

::tip{icon="i-lucide-database"}
Sincronize primeiro, transforme depois. Dados O trabalho do Sync é apenas para *Terra* Cópias limpas rapidamente. A formação acontece no próximo passo.
::

## Preparando dados: Dataflow Vs. Receitas

Uma vez que os dados são encenados, você moldá-lo - juntar tabelas, campos de computação, agregado, filtro, balde. CRM Analytics Dá duas ferramentas para isso, e saber que a diferença é um tópico clássico de entrevista.

**O Dataflow editor** é o original, **legado** Motor de transformação. É genuinamente poderoso e pode expressar lógica complexa, mas é **Menos fácil de usar** Uma experiência baseada em nós que leva tempo para se acostumar.

**Data Prep / Receitas** é o **Moderno**, **arrastar e soltar** Experiência. Você constrói uma tubulação visual de nós de transformação, pré-visualização dos resultados, e geralmente se move mais rápido com menos atrito. Salesforce tem investido muito aqui, e **As receitas estão se movendo para a paridade de características.** com o fluxo de dados. Para novos trabalhos, receitas são o caminho recomendado, você ainda encontrará fluxos de dados em orgs mais velhos.

::note{icon="i-lucide-workflow"}
Mesmo objetivo, duas ferramentas: ambos produzem conjuntos de dados. O fluxo de dados é a poderosa velha guarda, receitas são o futuro amigável e rápido.
::

## Datasets: o molho secreto

A saída de toda esta preparação é o **Conjunto de dados** - e datasets são o verdadeiro "molho secreto" de CRM Analytics.

Um conjunto de dados é **Armazenamento colunar otimizado**. Ao contrário de um banco de dados tradicional baseado em linhas transacionais (ótimo para salvar um registro de cada vez), o armazenamento colunar é construído para análise: lendo algumas colunas através de milhões de linhas, filtrando, e agregando-se em velocidade relâmpago. É exatamente por isso. CRM Analytics pode filtrar um painel multi-milionário assim que você clicar, algo que um relatório padrão luta para combinar.

Coisas-chave para lembrar sobre conjuntos de dados:

- Eles cuidam **Alto volume.** graciosamente.
- Eles entregam. **Consulta rápida** Performance por causa do projeto colunar.
- Eles são a unidade que painéis, lentes e histórias lêem.

## Mantendo-o funcionando: monitorando trabalhos de dados

Uma camada de dados não é "configurada e esquecida". Sincronia, fluxo de dados, e receitas todas funcionam como **Trabalhos de dados**E parte de possuir a camada de dados é **Monitoramento** Esses trabalhos, verificando se eles correram, quanto tempo demoraram, e se algum falhou. CRM Analytics fornece uma visão do monitor para exatamente isso, assim você pode pegar uma sincronização quebrada antes que um stakeholder note um painel velho.
