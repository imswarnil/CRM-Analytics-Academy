# Anatomia de um painel

Quatro partes, e uma vez que você sabe qual é qual, um arquivo de painel desconhecido deixa de ser intimidante.

## As quatro partes

::field-table
---
dataset: "top-level structure"
grain: "one row per part"
fields:
  - name: "state"
    type: "the container"
    role: "key"
    note: "Enrola tudo abaixo, as configurações do painel e as três coleções. Quando a documentação diz 'o painel' JSONÉ isso que significa."
  - name: "steps"
    type: "where data comes from"
    role: "key"
    note: "Definições de perguntas, cada um com um nome. Um passo nomeia seu conjunto de dados, seus agrupamentos e medidas, quaisquer filtros, e muitas vezes o SAQL Ele mesmo. Widgets referenciam passos pelo nome, e é por isso que nomeá-los corretamente importa."
  - name: "widgets"
    type: "what is drawn"
    role: "dimension"
    note: "Uma entrada por elemento visível: tipo (grama, tabela, número, texto, filtro), que passo alimenta-lo, e seus parâmetros de exibição - título, formatação, cores, comportamento facetante."
  - name: "layouts"
    type: "where things sit"
    role: "dimension"
    note: "Posição e tamanho, separados dos próprios widgets. Normalmente vários layouts para diferentes larguras de tela, por isso uma mudança que parece certa no construtor pode estar errada em um telefone."
---
::

## Como eles se referem

Um widget não contém sua consulta; ele **Dê um passo.**. Vários widgets podem nomear o mesmo passo, que é exatamente como um número de título, um gráfico de barras e uma tabela podem compartilhar uma consulta em vez de emitir três.

::tip{icon="i-lucide-merge"}
**Lendo o JSON É a maneira mais rápida de auditar o desempenho do painel.** Conte os passos e os widgets. Doze widgets contra onze passos significa que quase nada é compartilhado e a tela está fazendo onze viagens redondas; doze widgets contra quatro passos é um painel que alguém pensou. Esta auditoria leva trinta segundos em um editor de texto e é estranho para executar no construtor em tudo.
::

::note{icon="i-lucide-search"}
**Esse último ponto é a melhor razão para abrir o arquivo em um painel que você herdou.** A seção anterior dizia que as ligações são invisíveis na interface. JSON Eles são respeitáveis. Dez segundos de busca dá-lhe o mapa de dependência que de outra forma levaria uma tarde de clique - e esse mapa é o que você deve escrever na descrição do painel.
::

## Nomes são a camada legível.

Nomes de passos se propagam por toda parte: widgets os referenciam, ligações os referenciam, e eles são o que você lê quando rastreia qualquer coisa.

`step_7` Não te diz nada. `closed_won_by_segment` Diz à próxima pessoa o que é a pergunta antes de lerem uma linha dela. E como vinculam passos de referência pelo nome, bons nomes são a diferença entre um arranjo legível e um quebra-cabeça.
