# A Paisagem de Dados: Conectar, Sincronizar e Onde os Datasets se encaixam

Antes de construir qualquer coisa, você precisa de um mapa mental de como os dados passam CRM Analytics. Faça a imagem certa e cada ferramenta na plataforma de repente tem um lugar óbvio. Se errar, vai passar horas imaginando por que um conjunto de dados está ruim ou uma sincronização falhou.

## Conectar e Sincronizar

A maioria dos seus dados começa em seu **local Salesforce org**E a plataforma tem uma conexão nativa com ela. Você traz objetos através **Conectar** (também chamado **Sincronização**Cada aterrissagem como seu próprio objeto sincronizado.

Pense nisso como um **Área de preparação livre**. Você não está construindo conjuntos de dados acabados aqui, você está puxando objetos crus para uma zona de detenção. Mais tarde, um fluxo de dados ou receita *Lê de* Esta camada de encenação para montar os conjuntos de dados que você vai usar em painéis, lentes e histórias.

O superpoder da camada de sincronização é **Atualização incremental** - após a primeira carga completa, ele só puxa linhas mudadas. Isso é o que permite programar uma sincronização a cada 15 minutos, a cada hora, ou todos os dias sem martelar suas orgs. Vamos fundo nisso no Data Manager Material.
::

## De onde os dados podem vir

Salesforce é a fonte comum, mas está longe da única. A camada Connect/Sync pode ingerir de:

- **Seu local Salesforce org** - nativo, o caminho mais comum.
- **Outro Salesforce Nuvens ou orgs conectados** - Puxe dados através de ambientes.
- **Fontes externas como Snowflake** - incluindo um **Conector ao vivo** que lê na hora da consulta.
- **CSV Arquivos** - um simples upload manual, que faremos na próxima lição.
- **Seu próprio. ETL ferramenta ou API** - Qualquer ETL Que tem um conector para CRM Analytics pode empurrar dados, ou você pode chamar a ingestão API diretamente (documentado sob o link de ajuda).

## Os dados podem fluir. *Fora.*, também

Em recentes lançamentos, a plataforma tem ampliado seu **Conectores de saída**. Uma vez que você construiu um conjunto de dados - trouxe-lo de Salesforce, combinado, enriquecido - você pode empurrá-lo de volta para **Floco de neve**, **Amazon S3**, ou um **Tabuleiro** Arquivo hiper para construir painéis lá. Analytics não é mais uma rua de mão única.

## Uma característica para saber: Dados do Relatório de Tendência

Se você tem o CRM Analytics Mais licença, mais o **Relatório de tendências de dados em análise** Permissão, cada relatório operacional recebe um pequeno **"Trend in Analytics"** Botão. Clique nele e você pode agendar esse relatório, diário, semanal ou mensal, para armazenar seus resultados diretamente em um conjunto de dados.

É útil se você for pesado Salesforce Informar usuário que só quer fotos históricas de contagens, atividades ou casos. Esteja ciente, porém, que é **limitado**Vai direto para um conjunto de dados com pouco controle sobre a transformação. Na prática, você mais frequentemente fotografa dados através de um aplicativo ou uma receita.

A visão chave que leva as pessoas: **Ordem**. Sincronize refresca os objetos básicos primeiro, *Então...* Um fluxo de dados ou receita é executado para atualizar os conjuntos de dados acabados. Se seu painel mostra números obsoletos, o culpado é quase sempre algo fora de ordem nessa corrente - uma sincronização que não foi executada, ou uma receita programada antes de sua fonte terminar.

Ao longo desta seção você vai me ouvir distinguir **Datasets de base** (os blocos de construção crus) de **Datasets finais resultantes** (que painéis consomem). Segure-se nessa distinção. É a diferença entre um aplicativo de análise sustentável e um emaranhado que ninguém pode depurar. Em seguida, a maneira mais simples de fazer um conjunto de dados: **CSV upload**.
