# Desenhando um conjunto de dados

Comece pelas perguntas, não pelas mesas. As mesas dizem o que é possível, as perguntas dizem o que construir.

## O projeto de quatro perguntas.

::lesson-steps
---
items:
  - title: "Escreva as perguntas que ele deve responder."
    description: "Cinco ou seis, em linguagem simples. Que segmentos mantêm nossa ARR. Que acordos foram presos há mais tempo. Se você não pode listá-los, você está construindo uma cópia de uma tabela fonte em vez de um conjunto de dados."
  - title: "Derive o grão da melhor pergunta"
    description: "Se alguma pergunta é sobre negócios individuais, o grão é uma fileira por negócio. Se eles são todos sobre totais mensais por segmento, pode ser uma fileira por segmento por mês - e será muito mais rápido."
  - title: "Liste as colunas que cada pergunta precisa"
    description: "Dimensões para agrupar, medidas para agregar, datas para tendência. Qualquer coisa que não sirva uma pergunta listada é um candidato a deixar de fora: cada coluna extra custa tempo de execução e torna a lista de campo mais difícil para a próxima pessoa ler."
  - title: "Decida o que está permanentemente excluído."
    description: "Registros de testes, contas internas, uma linha de produtos que ninguém relata. Se uma linha nunca aparecer em qualquer resposta que este conjunto de dados dê, filtrar aqui em vez de pedir a cada painel para lembrar."
---
::

## Filtrar no conjunto de dados ou no painel?

::field-table
---
dataset: "where a filter belongs"
grain: "one row per case"
fields:
  - name: "In the dataset"
    type: "structural exclusion"
    role: "key"
    note: "Contas de teste, registros apagados, um segmento que não faz parte do propósito deste conjunto de dados. Ninguém deve ser capaz de desexcluí-los limpando um controle, e todo consumidor herda a exclusão sem saber perguntar."
  - name: "In the widget's query"
    type: "this widget always"
    role: "measure"
    note: "\"Oleoduto aberto\" nunca deve mostrar acordos perdidos porque alguém redefiniu um filtro. Estrutural para o widget, não para o conjunto de dados, porque outro widget no mesmo conjunto de dados legitimamente quer essas linhas."
  - name: "On the dashboard"
    type: "exploratory"
    role: "dimension"
    note: "Período, região, segmento, coisas que os espectadores podem mudar. Se um filtro é um controle, é aqui."
---
::

::warning{icon="i-lucide-filter-x"}
**Um filtro no conjunto de dados é invisível para todos.** Esse é seu valor e seu risco: um analista reconciliando seu conjunto de dados contra a fonte vai encontrar uma diferença e não tem como ver o porquê. Coloque cada filtro de nível de dataset na descrição do conjunto de dados - 'exclui contas de teste e o sandbox interno org' - ou você será perguntado sobre a discrepância repetidamente.
::

## Um conjunto de dados ou dois?

A tentação é sempre ampliar o existente. Dois sinais que você deveria dividir.

::compare-cols
---
items:
  - title: "Separar"
    subtitle: "Different grain, or different purpose"
    icon: "i-lucide-split"
    pros:
      - "Each is simple enough to reason about"
      - "The daily dashboard gets a fast pre-aggregated dataset while exploration keeps the detail"
      - "One recipe can produce both outputs, so the logic is still defined once"
    cons:
      - "Two things to schedule and monitor"
    verdict: "Usually right when the grains genuinely differ."
  - title: "Alargamento"
    subtitle: "Add columns to the existing one"
    icon: "i-lucide-move-horizontal"
    pros:
      - "One thing to maintain"
      - "Fine when the new questions live at the same grain"
    cons:
      - "A dataset serving everybody eventually serves nobody well"
      - "Sixty columns of which fifteen matter is hostile to self-service"
    verdict: "Right only while the grain and purpose still match."
---
::

::tip{icon="i-lucide-git-branch"}
**Duas saídas de uma receita é a opção subutilizada.** As juntas, a limpeza e as definições acontecem uma vez, a receita então escreve um conjunto de dados detalhados e um agregado. Você tem velocidade onde importa e detalhes onde é necessário, sem duas cópias da lógica se distanciando.
::

## Escreva o grão na descrição.

Cada conjunto de dados, uma frase: *Uma fileira por oportunidade por produto.*. São cinco segundos de trabalho e a única coisa mais útil que qualquer um lê a jusante, a diferença entre um colega somando a coluna direita e somando uma duplicada sem nunca saber.
