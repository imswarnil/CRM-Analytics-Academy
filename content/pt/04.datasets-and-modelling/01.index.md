# Um conjunto de dados é uma decisão

A seção anterior tem dados sobre CRM Analytics. Este é sobre a forma que toma uma vez que está lá - e ao contrário de um armazém, onde uma consulta inteligente pode resgatar uma mesa pobre, a forma de um conjunto de dados é uma decisão que você vive com.

::note{icon="i-lucide-ruler"}
**Porque um conjunto de dados é construído em vez de examinado, alguém escolhe seus grãos, suas juntas, seus filtros e seus campos.** Essas escolhas decidem quais perguntas são responsáveis e quais não são. Um conjunto de dados agregado aos totais mensais é rápido e nunca pode lhe dizer qual segmento dirigiu o mês; um conjunto de dados no melhor grão possível responde a tudo e entrega o problema dos fãs a cada pessoa que toca nele.
::

## Muito bom, muito grosseiro, quase certo.

::compare-cols
---
items:
  - title: "Muito bem."
    subtitle: "Every row preserved"
    icon: "i-lucide-microscope"
    pros:
      - "Any question is answerable"
      - "One dataset serves many dashboards"
    cons:
      - "Every widget aggregates a lot of rows on every load, for every viewer"
      - "Fan-out risk handed to everyone who builds on it"
      - "Counting anything needs a distinct count, and somebody will forget"
    verdict: "Right for exploration, expensive for a daily dashboard."
  - title: "Muito grosseiro."
    subtitle: "Pre-aggregated"
    icon: "i-lucide-box"
    pros:
      - "Fast, and the definition is settled upstream"
    cons:
      - "'Which segment drove that?' is no longer answerable"
      - "Every new question needs a new dataset"
    verdict: "Right for a screen many people open daily."
---
::

::tip{icon="i-lucide-layers"}
**A resposta da produção geralmente é ambas.** Um conjunto de dados fino para exploração, e um pré-agregado atrás do painel que todos abrem. O depósito da seção de engenharia GTM é construído desta forma deliberadamente. As tabelas que você explora nem sempre são as tabelas que o conselho executivo lê, e fingir que um conjunto de dados pode servir a ambos é como os painéis acabam lentos e analistas acabam bloqueados.
::

## O que esta seção cobre

Grain, junta-se e o fan-out que quase triplica a receita, como projetar um conjunto de dados das perguntas que deve responder, os padrões de modelagem que valem a pena copiar, datas, histórico e instantâneos, e os metadados de campo que decidem se alguém pode usar o que você construiu.
