# Padrões de modelagem

CRM Analytics Não é um armazém e seus conjuntos de dados não são um esquema de estrelas, mas as mesmas formas se repetem - e reconhecê-los salva você de redescobrir cada um.

## Fato e referência

::field-table
---
dataset: "the two roles"
grain: "one row per role"
fields:
  - name: "Fact tables"
    type: "things that happened"
    role: "measure"
    note: "Oportunidades, pistas, casos, uso, sessões. Muitas filas, carregando medidas, datas e chaves. Isso é o que você soma."
  - name: "Reference tables"
    type: "things that are"
    role: "dimension"
    note: "Contas, produtos, representantes, campanhas. Algumas filas, carregando atributos. Você se junta a eles para obter etiquetas e agrupamentos - somando qualquer coisa em um é quase sempre um erro, e uma coluna ARR em uma tabela de conta é a armadilha de pé porque é tanto um atributo e uma medida."
---
::

::warning{icon="i-lucide-alert-triangle"}
**Juntar uma tabela de referência em uma tabela de fatos é seguro, o inverso multiplica.** Trazer o segmento de uma conta para cada oportunidade mantém a oportunidade. Trazer todas as oportunidades para cada linha de conta não faz - e se você então somar a ARR da conta, você multiplicou pela contagem de negócio dessa conta. Este é o leque da lição anterior, chegando da outra direção.
::

## Ampla contra longa

Duas maneiras de manter várias métricas por entidade:

::compare-cols
---
items:
  - title: "Ampla"
    subtitle: "One column per metric"
    icon: "i-lucide-table-columns"
    pros:
      - "Natural for charts — pick the column you want"
      - "Obvious to read in a table preview"
      - "Fine when the metric list is short and stable"
    cons:
      - "A new metric means a schema change and a rebuild"
      - "Charting many metrics together needs one widget per column"
    verdict: "Default for a small, settled set."
  - title: "Longo."
    subtitle: "One row per entity per metric"
    icon: "i-lucide-rows-3"
    pros:
      - "New metrics are new rows, not schema changes"
      - "One widget can chart any metric, chosen by a filter"
      - "Natural fit for a metric-toggle binding"
    cons:
      - "Every query must filter to a metric, and forgetting sums unrelated things together"
      - "Harder to read raw"
    verdict: "Right when metrics are added often."
---
::

::note{icon="i-lucide-alert-circle"}
**O fracasso do formato longo é espetacular e silencioso: somando métricas.** Uma consulta que esquece de filtrar para uma métrica adiciona receita para a contagem de acordo à taxa de conversão e retorna um número. Nada de erros. Se você modelar longo, faça o filtro métrico parte da consulta base de cada widget em vez de confiar em cada construtor para lembrar.
::

## Camadas derivadas

Uma receita pode ler o resultado de outra receita. É assim que se consegue um conjunto de dados de base limpa alimentando vários feitos de propósito, o padrão que a seção de engenharia GTM usa.

::lesson-steps
---
items:
  - title: "Mantenha a corrente rasa."
    description: "Base, então derivada. Três ou quatro ligações profundas e uma falha no início é invisível no final, e ninguém pode dizer qual camada introduziu um número errado."
  - title: "Peça os horários com a sala da frente."
    description: "A armadilha de dependência de novo: uma receita derivada que começa antes de sua fonte terminar funciona com sucesso em dados de ontem, todas as noites, e relata verde."
  - title: "Diga as camadas."
    description: "Um prefixo que diz para que serve um conjunto de dados - base, relatório, executivo - diz à próxima pessoa onde na cadeia eles estão procurando, que nenhuma outra propriedade irá."
  - title: "Coloque as definições na base"
    description: "Métricas calculadas na camada de base são herdadas por tudo a jusante pela construção. Uma definição adicionada a um conjunto de dados derivado se aplica a um ramo e discretamente diverge de seus irmãos."
---
::

## Mesas de ponte

Quando duas coisas têm uma relação de muitos a muitos - oportunidades e produtos, campanhas e leads - a mesa de reunião *É* O grão que você deve respeitar.

`opportunity_products.csv` É de Namilio: 1.378 fileiras, com 677 oportunidades e 6 produtos. Qualquer pergunta contra ele está na linha de grãos, então a contagem precisa de uma contagem distinta e as medidas dos pais não devem ser resumidas. Reconhecendo uma mesa de ponte à vista, uma mesa que é principalmente chave, diz tudo isso antes de escrever qualquer coisa.
