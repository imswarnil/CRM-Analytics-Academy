# Construir o mesmo conjunto de dados com uma receita

Vamos construir o **Exatamente igual.** Oportunidade + Conta + Usuário, mas com **receita** Desta vez. Receitas são o moderno motor de preparação de dados: arrastar e soltar, visual e muito mais flexível do que um fluxo de dados. A troca é que *Você.* É o dono dos relacionamentos. Dataset Builder Descobri o próximo objeto e as chaves de junção para você, em uma receita você decide o que se junta ao quê, e como.

## Comece uma nova receita.

De Analytics Studio, **Criar → Dataset** e escolher de seus conjuntos de dados ou sincronizar objetos - isso abre um **receita** na Data Manager (Dados Fluxos & Receitas → **Receitas** → nova receita).

Na receita, **Selecionar Dados** mostra tudo disponível para você: conjuntos de dados que você criou, fontes externas, e os objetos conectados/sincronia de Salesforce. Pegue os mesmos três... **Oportunidade**, **Conta.**, **Usuário**.

::tip{icon="i-lucide-list-checks"}
Primeira diferença real de Dataset BuilderVocê pode. **Selecionar tudo** campos por objeto em vez de clicar neles um por um, um enorme tempo-salvar em objetos largos. Mas não faça isso. Se um objeto tem mais de 150 campos você não precisa de todos eles, um conjunto de dados muito amplo é miserável para rolar e mais lento para pesquisar. Traga apenas o que o painel precisa.
::

Clique **Próxima** E você pousa na tela da receita - seus três objetos sentados lá, **Não conectado.**. Essa é a diferença principal: em uma receita, conectá-los é o seu trabalho.

## Junte-se aos objetos.

As regras do grão ainda se aplicam: **Oportunidade é o nível mais baixo**Então tudo se junta a ele.

::lesson-steps
---
items:
  - title: "Junte-se a Conta na Oportunidade"
    description: "Arraste do nó de oportunidade para a conta. Torna-se um nó de união. A receita corretamente pega o ID da conta = ID da conta - verifique-o, em seguida, aplicar."
  - title: "Junte-se ao Usuário Oportunidade, cuidado com a chave."
    description: "Adicionar usuário à oportunidade (não à conta - o proprietário pertence à oportunidade). Aqui a receita acha errado: combina com o ID de oportunidade para ID de usuário. Você quer ID do proprietário → ID do usuário. Conserte a chave à mão."
  - title: "Aplique cada passo"
    description: "Receitas não salvam como você vai como você pode esperar - clique em Aplicar na parte inferior para commit cada nó antes de seguir em frente."
---
::

::tip{icon="i-lucide-triangle-alert"}
Este é o imposto de receita, e vale a pena internalizar: **Ele escolhe uma chave de junção, e pode escolher a errada.** Para o dono que você precisa `OwnerId → User.Id`, não `Opportunity.Id → User.Id`. Você tem que... *Conheça seus objetos.* O suficiente para pegá-lo. Dataset Builder Nunca deixaria você cometer esse erro. Essa é a segurança que troca por controle.
::

## Controle suas colunas.

As receitas lhe dão controle real sobre as colunas de saída:

- **Junte-se ao tipo.** - Expandir o nó de união para escolher um **Procure.** Contra uma adesão completa. (Cobrimos por que isso importa na lição de grãos; mantenha estes como buscas aqui.)
- **Prefixos** - Os campos da Conta vêm como `Account.Name`, `Account.Industry`E assim por diante. Você pode renomear esses prefixos para que as colunas finais leiam como quiser.
- **Mantenha ou solte** - Previsão das colunas e **Esconda-se.** Os que você não precisa para que eles nunca atinjam a saída. Aparar `User.` campos até apenas o nome do proprietário e foto, por exemplo.

## Adicione o nó de saída

Aqui está o passo que as pessoas esquecem: **nada existe como um conjunto de dados utilizáveis até que você adicione um nó de saída (registro).** Só as juntas não produzem nada que você possa colocar em um painel.

::lesson-steps

  - title: "Aplicar, então salvar e correr"
    description: "Aplique o nó de saída, então salve e execute a receita. Ele executa e constrói seu conjunto de dados."
---
::

## Mesmo resultado, motor diferente.

Quando termina, você tem as mesmas oportunidades de dataset - construído por um **receita** leitura dos mesmos objetos sincronizados, em vez de por um fluxo de dados. Dois motores, um resultado.
