interview:
  - q: "O que é um conjunto de dados CRM AnalyticsE por que a plataforma usa seu próprio formato de armazenamento?"
    a: "Um conjunto de dados é dados combinados de um ou mais objetos relacionados, armazenados em um formato comprimido e otimizado construído especificamente para análise. Ele usa uma loja achatada, de índice invertido, de valor chave, que permite manter grandes volumes de dados e ainda retornar consultas no painel em sub-segundo tempo. Essa combinação de big data e consulta interativa rápida é por isso que não apenas consulta Salesforce diretamente."
  - q: "O que é grão, e por que é a primeira coisa que você decide quando constrói um conjunto de dados?"
    a: "Grão é o que uma única linha do conjunto de dados representa: uma oportunidade, um caso, uma conta. Você decide primeiro porque determina qual objeto você começa e como você traz dados relacionados. Pegue o grão errado e suas medidas se multiplicam ou seu conjunto de dados responde à pergunta errada. Uma boa verificação de sanidade é terminar a frase uma linha deste conjunto de dados é uma. '"
  - q: "Por que você começa? Dataset Builder Do seu objeto de menor grão?"
    a: "Porque... Dataset Builder Só deixa você olhar a árvore do relacionamento. Comece com Oportunidade e você pode alcançar sua Conta e seu próprio Usuário. Comece com Conta e não há nada acima dela para alcançar, então você está preso com uma linha por conta. O objeto com o qual você começa é uma decisão de projeto deliberada impulsionada pelo conjunto de dados."
  - q: "Qual é a diferença entre uma busca e uma união, e por que isso importa?"
    a: "Uma busca fixa campos de pais em cada fileira de crianças sem mudar o grão - uma oportunidade permanece uma fileira, agora carregando campos de contas. Uma união completa pode combinar muitas vezes e multiplicar filas, o que infla somas se você não pretendia. Quando um total parece muito grande, verifique o grão primeiro, é geralmente um olhar que se comportava como uma junta de fãs."
  - q: "Compare Dataset Builder e receitas para construir um conjunto de dados de base."
    a: "Dataset Builder É guiado: ele anda o Salesforce Relacionamentos, auto-detecção juntam-se às chaves, e escrevem um fluxo de dados. Apenas procura, difícil de errar, ótimo para iniciantes. As receitas são drag-and-drop e muito mais flexíveis, mas você escolhe os objetos, os tipos de junção, e chaves você mesmo, então você possui tanto o poder e os erros - por exemplo, ele pode adivinhar a chave de junção errada e combinar identificação de oportunidade para ID do usuário em vez de identificação do proprietário."
  - q: "O que é a camada Connect/Sync e a camada de conjunto de dados, e como eles se relacionam?"
    a: "Connect (Sync) é uma área de montagem que puxa cru Salesforce e objetos externos na área, com atualização programada e incremental. Fluxos de dados e receitas então ler a partir dessa camada de encenação para construir os conjuntos de dados acabados que seus painéis consomem. Dataset Builder e receitas lidas de sincronia, não de Salesforce Por isso um objeto deve ser sincronizado antes que você possa usá-lo."
  - q: "Um fluxo de dados falha na primeira vez em uma nova org. Qual é o seu primeiro cheque?"
    a: "Que os objetos de origem estão na camada de sincronização. O fluxo de dados lê de Connect, não de SalesforceEntão, se Conta, Oportunidade e Usuário ainda não foram sincronizados, não tem nada para ler e errar. A correção é executar o Connect manualmente uma vez para encenar os dados, e então repetir o fluxo de dados. Quando tudo está programado corretamente, isso acontece automaticamente."
  - q: "Ao combinar dois conjuntos de dados em uma receita, o que você não deve esquecer, e como você mantém os dados frescos?"
    a: "Você deve adicionar um nó de saída (registro) - as juntas não produzem nada utilizável até que você produza o resultado. Para o frescor, respeite a ordem de operações: a sincronização atualiza os objetos base, o fluxo de dados ou receita de base reconstrói os conjuntos de dados de origem, então a receita combinada reconstrui o conjunto de dados final. Registre-os nessa sequência ou o conjunto de dados final serve para dados obsoletos."
