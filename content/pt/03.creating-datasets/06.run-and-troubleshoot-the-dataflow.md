# Corra e resolva os problemas. Dataflow

Você clicou em Criar Dataset, que **executa o fluxo de dados**. Agora vamos vê-lo correr, entender o que ele está realmente fazendo, e corrigir o erro que pega quase todos na primeira vez.

## O que "correr o fluxo de dados" realmente faz

Quando Dataset Builder escreve para o **fluxo de dados padrão**, não só constrói *Seu* Dataset - ele funciona **Tudo.** nesse fluxo de dados. Em uma orgia de treinamento que não está vazia, vem pré-embalado com outros conjuntos de dados e instruções. Então, executar o fluxo de dados padrão executa tudo, não apenas as oportunidades que você acabou de projetar.

::tip{icon="i-lucide-git-branch"}
É exatamente por isso que construtores experientes eventualmente criam seus **Mesmo.** fluxo de dados. Um único fluxo de dados padrão compartilhado significa que cada construção executa tudo de novo. À medida que você cresce, você vai dividir o trabalho em fluxos de dados nomeados (ou receitas) para que cada um refresque um conjunto conhecido de conjuntos de dados em sua própria programação.
::

Vá para lá. **Data Manager → Monitor** e verá seu fluxo de dados padrão rodando.

## O clássico erro de primeira corrida

Em uma nova org, ou a primeira vez que você executar isso, o fluxo de dados pode **Falhe com um erro.**. Não entre em pânico. A causa é quase sempre simples: o fluxo de dados está pedindo objetos que **Ainda não foram puxados para a camada de sincronização.**.

Lembre-se da corrente: **Conectar/Sync**, não de Salesforce diretamente. Se Connect não tiver preenchido Conta, Oportunidade e Usuário, o fluxo de dados não tem nada para ler e ele errou.

## A correção: executar Conectar manualmente

::lesson-steps

::

::tip{icon="i-lucide-workflow"}
Quando tudo é **agendado** corretamente, isso é automático: o fluxo de dados pergunta a camada de sincronização "os dados estão aqui?" e, se não, Connect começa e traz-os antes que o fluxo de dados progrida. Você só faz isso à mão quando um ambiente está fora de sincronia, normalmente uma nova org de treinamento no primeiro dia.
::

## Esqueceu um campo? Edite o nó de digestão.

Porque você não pode reabrir o Dataset Builder Seletor de campo, editar campos mais tarde acontece no **O fluxo de dados digeriu os nós.**.

- Abra o fluxo de dados, clique no nó de digestão relevante. **Conta.**), e readd o campo via **Selecione Campos**.
- Salvar, e quando solicitado, escolher **propagar** O campo todo até o nó final do registro. Caso contrário, ele pára em partway e nunca atinge seu conjunto de dados.
- Atualizar e **Execute o fluxo de dados novamente** Então o novo campo é materializado.

Nós cobrimos nós digeridos, atributos de campo, e edição de fluxo de dados corretamente no Data Manager lições — isso é o suficiente para desamarrar você.

## Você construiu seu primeiro conjunto de dados.

Quando o fluxo de dados terminar verde, volte para Analytics Studio E aí está, seu conjunto de dados de oportunidades, sentado em seu aplicativo privado, pronto para explorar. No diagrama da paisagem, ele agora vive no **Camada do conjunto de dados**, construído por um fluxo de dados que lê de sincronização.

::tip{icon="i-lucide-check-check"}
Verificação mental quando um fluxo de dados falha: **(1)** Os objetos de origem estão sincronizados? **(2)** Connect realmente terminou antes do fluxo de dados correr? **(3)** Todos os campos que você precisa propagam para o nó registrador? Nove em cada dez falhas na primeira corrida são respondidas por essas três perguntas.
::

Dataset Builder é amigável, mas te tranca em buscas e um fluxo de dados. Em seguida, vamos construir o **Exatamente o mesmo conjunto de dados.** com um **receita** Mais cliques na frente, muito mais controle, e a direção que a plataforma está indo.
