# Por quê? SAQL Existe.

Cada lente, cada widget e cada consulta de painel é SAQL Por baixo. Clicar gera, você só escreve quando a interface de clique acaba.

::note{icon="i-lucide-waves"}
**SAQL é uma transformação de fluxo, não uma consulta declarativa.** Cada declaração pega o resultado da declaração anterior e o transforma, reatribuindo a mesma variável de fluxo. Não há nenhum otimizador reordenando seu trabalho, então **A ordem em que você escreve declarações é o plano que executa** - Filtrar depois de agrupar realmente soma linhas que você estava prestes a descartar. Esta é a única diferença estrutural que pega pessoas que sabem SQL Bem.
::

## A forma

```
q = load "Namilio_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Carregar, estreitar, agrupar, computar, ordenar, limitar. Seis declarações, cada mudança. `q`Cada um consumindo o que o último produziu.

::warning{icon="i-lucide-eye-off"}
**O quê? SAQL NÃO deve ser usado para: definir uma métrica de negócios.** Uma definição escrita em uma consulta de widget é invisível para qualquer um lendo o conjunto de dados, a receita ou a documentação. Será redescoberto meses depois por alguém tentando entender por que dois painéis discordam e nenhum deles estará errado. Consultas de forma em SAQL; definir métricas na receita.
::
