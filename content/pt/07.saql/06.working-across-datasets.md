# Trabalhando em conjunto de dados

SAQL pode carregar mais de um fluxo em uma consulta e combiná-los. A mecânica é simples, o julgamento não é.

## O julgamento primeiro.

::warning{icon="i-lucide-git-branch"}
**Se dois conjuntos de dados precisam combinar para mais de um widget, a receita deve fazê-lo.** Uma junção escrita em uma consulta de widget é calculada em cada carga, para cada espectador, e é invisível para qualquer um lendo o conjunto de dados ou sua documentação. Dois painéis eventualmente irão implementá-lo ligeiramente diferente, ambos serão defensáveis, e o desacordo surgirá em uma reunião ao invés de em uma revisão. Combinação de tempo de consulta é para *Comparações*, Não para *Modelos*.
::

## A armadilha de grãos te segue até aqui.

Tudo que a seção de dados e modelagem diz sobre grãos se aplica dentro de uma consulta. Combinando um córrego em uma linha por oportunidade com um em uma linha por linha multiplica filas exatamente como uma receita iria juntar, e somando a medida dos pais depois de duas contas exatamente da mesma forma.

::note{icon="i-lucide-ruler"}
**Declare ambos os grãos antes de combinar, no editor de consultas tanto quanto em uma receita.** O editor de consultas se sente mais leve do que uma receita - é apenas texto, nada está sendo reconstruído - e que leveza é precisamente por isso que as pessoas pulam o cheque aqui. A aritmética não importa onde você escreveu.
::

## Forma prática

O padrão é: carregar e moldar cada fluxo separadamente, então combinar em uma chave compartilhada, e depois computar.

```
-- actuals by segment
act = load "Namilio_Opportunities";
act = filter act by 'StageName' == "Closed Won";
act = group act by 'Segment';
act = foreach act generate 'Segment' as 'Segment', sum('Amount') as 'Actual';

-- targets by segment (a small, separate dataset)
tgt = load "Namilio_Targets";
tgt = group tgt by 'Segment';
tgt = foreach tgt generate 'Segment' as 'Segment', sum('Target') as 'Target';
```

Ambos os fluxos já estão em uma fileira por segmento, então combiná-los não pode multiplicar nada - que é a propriedade para organizar deliberadamente em vez de descobrir depois.

::tip{icon="i-lucide-check"}
**Agregar cada córrego ao grão compartilhado antes de combinar.** Se ambos os lados são uma linha por chave, a combinação é segura por construção. Esta é a versão de "agregar os muitos lados antes da união", e é a mesma solução pela mesma razão.
::

## Uma nota em fósforos desaparecidos.

Um segmento presente em reais, mas ausente de alvos, ou ao contrário, produzirá nulos de um lado. Decida o que isso significa: um segmento sem alvo é provavelmente uma lacuna de dados que vale a pena aparecer, enquanto um alvo sem reais é um segmento que não vendeu nada - que é uma descoberta, não uma lacuna. Preencher ambos com zero silenciosamente é a opção fácil e esconde a diferença.
