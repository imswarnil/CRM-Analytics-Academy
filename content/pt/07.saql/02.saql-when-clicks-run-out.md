# SAQL Quando os cliques se esgotam

SAQL Não é. SQL Com palavras-chave diferentes. É um... **Tradução:**Cada declaração pega o resultado da declaração anterior e a transforma. Isso faz o *Ordem* de declarações o plano de consulta, que é a única diferença estrutural que as capturas experimentaram SQL Pessoas.

## A forma de uma consulta

Leia um gerado e o padrão é imediatamente visível:

```
q = load "Namilio_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Seis declarações, cada mudança. `q`. Carregar, estreitar, agrupar, computar, ordenar, limitar.

::note{icon="i-lucide-arrow-down"}
**A ordem importa de uma forma que não importa. SQL.** A SQL O motor reordena sua consulta para você. Aqui você está descrevendo um oleoduto literalmente: filtrar após agrupar significa agregar linhas que você iria descartar. Filtrar cedo, sempre - é tanto mais rápido e mais perto do que você quis dizer.
::

## Três padrões que valem a pena memorizar

### 1. Contagem distinta

Num grão fino, contar filas conta a coisa errada:

```
q = foreach q generate 'Segment' as 'Segment',
      unique('OpportunityId') as 'Deals',
      sum('LineAmount') as 'Revenue';
```

O grão de linha-item de Namilio torna isso essencial: 1.378 linhas, 677 acordos.

### 2. Parte do total

Cada grupo comparado com o todo - estranho clicando, direto aqui. Agrupar por `all` Para obter o total, então compare cada grupo com ele. Este é o padrão por trás de cada "percentagem de receita" widget, e é a razão mais comum para abrir SAQL De jeito nenhum.

### 3. Comparação do período

Dois riachos filtrados, cada um agregado, então se uniram no agrupamento - este quarto ao lado do último trimestre, com o delta calculado entre eles. A velocidade da Seção 9 usa exatamente essa forma.

::tip{icon="i-lucide-lightbulb"}
**Não memorize sintaxe que você pode gerar.** Construir o mais próximo que puder clicando, mudar para SAQL, e editar de lá. Você tem referências corretas de campo, citações corretas e um esqueleto de trabalho de graça. SAQL Normalmente dá errado: citações simples para nomes de campos, citações duplas para valores de cordas, exatamente como em um predicado de segurança.
::

## Quando chegar até ele, e quando não

      - "Harder for the next person to maintain"
      - "Easy to embed a business definition where nobody will find it"

  - title: "Não tente SAQL"
    subtitle: "When the recipe is the right place"
    icon: "i-lucide-database"
    pros:
      - "A company-wide metric computed once agrees everywhere"
    cons:
      - "A definition written into a widget query is invisible to everyone else"
      - "Two dashboards with the same metric in SAQL will drift, and neither will be wrong"
    verdict: "If ten dashboards need it, it belongs in the recipe."
---
::

::warning{icon="i-lucide-eye-off"}
**A armadilha de manutenção.** Uma métrica definida na escrita à mão SAQL dentro de um widget é invisível para qualquer um olhando para o conjunto de dados, a receita ou a documentação. Será redescoberta, meses depois, por alguém tentando descobrir por que dois painéis discordam. Use SAQL Para moldar uma consulta, use a receita para definir uma métrica.
::
