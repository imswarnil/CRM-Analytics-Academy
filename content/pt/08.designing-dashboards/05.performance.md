# Performance

Um painel que leva 12 segundos é um painel que as pessoas param de abrir. As causas são poucas e as correções são mais estruturais do que inteligentes.

## Conte as consultas, não os widgets.

Cada widget é alimentado por uma consulta. Vários widgets podem compartilhar um - e quando não, uma tela com doze widgets emite doze consultas.

::tip{icon="i-lucide-merge"}
**Esta é a maior alavanca disponível, e geralmente é grátis.** Um número de manchete, um gráfico de barras e uma tabela mostrando a mesma medida fatiado três maneiras freqüentemente *Pode* compartilhar uma única pergunta. Consolidar é frequentemente a diferença entre doze segundos e dois, e não muda nada sobre como o painel parece ou se comporta.
::

## O comércio de grãos

Seção 3 disse que um conjunto de dados é uma decisão. Aqui é onde você paga.

::compare-cols
---
items:
  - title: "Grão fino."
    subtitle: "Every row preserved"
    icon: "i-lucide-microscope"
    pros:
      - "Any question is answerable from it"
      - "One dataset serves many dashboards"
    cons:
      - "Every widget aggregates a lot of rows, on every load, for every viewer"
      - "Fan-out risk is handed to every designer who touches it"
    verdict: "Right for exploration, expensive for an exec board."
  - title: "Pré-agregado"
    subtitle: "Summarised in the recipe"
    icon: "i-lucide-box"
    pros:
      - "Fast — the aggregation happened once, overnight"
      - "The definition is settled upstream, so nobody can compute it differently"
    cons:
      - "Questions below the chosen grain are no longer answerable"
      - "Another dataset to schedule and maintain"
    verdict: "Right for a dashboard many people open daily."
---
::

::note{icon="i-lucide-layers"}
**A resposta normal da produção é ambas.** Um conjunto de dados fino para exploração, e um pré-agregado atrás do painel que todos abrem. O armazém da Seção 7 é construído desta forma deliberadamente: as mesas que você explora nem sempre são as mesas que o conselho executivo lê.
::

## As outras causas, em ordem difícil

::field-table
---
dataset: "what makes dashboards slow"
grain: "one row per cause"
fields:
  - name: "Too many distinct queries"
    type: "most common"
    role: "measure"
    note: "Doze widgets cada um deles. Consolide o que pode compartilhar, e a mudança é invisível para os usuários, exceto que a página aparece."
  - name: "Aggregating fine grain at query time"
    type: "common"
    role: "measure"
    note: "Milhões de linhas somadas por widget por carga. Pré-agregar na receita se o painel é aberto diariamente por muitas pessoas."
  - name: "Very wide tables"
    type: "common"
    role: "dimension"
    note: "Uma tabela de valores com 20 colunas e centenas de linhas é lenta para consultar e ilegível de qualquer maneira. Cortar para cinco colunas e dez fileiras resolve os dois problemas ao mesmo tempo."
  - name: "Complex bindings"
    type: "occasional"
    role: "dimension"
    note: "Ligas acorrentadas podem forçar seqüências em vez de consultas paralelas: widget C espera por B, que espera por A. Vale a pena verificar quando um painel é lento de uma forma que não corresponde à sua contagem de widgets."
  - name: "Row-level security evaluation"
    type: "structural"
    role: "key"
    note: "Predica e especialmente compartilhar herança custa algo por consulta por espectador. Este é um custo correto, não um defeito - mas é uma razão para um painel é mais lento para um espectador com acesso complexo do que para você."
---
::

## Como realmente medi-lo

::lesson-steps
---
items:
  - title: "Carregue como um usuário normal, não como você mesmo."
    description: "Sua conta pode pular a avaliação de segurança que um espectador de verdade paga em cada consulta. Teste de desempenho como administrador pode subestimar substancialmente."
  - title: "Veja quais widgets chegam por último."
    description: "Eles rendem como suas perguntas retornam, então os lentos se anunciam. Normalmente é a mesa mais larga e o melhor gráfico."
  - title: "Conte as perguntas distintas."
    description: "A lista de consultas do painel mostra. Se há mais perguntas do que há perguntas genuinamente distintas na tela, há uma consolidação a fazer."
  - title: "Conserte a estrutura antes da esperteza."
    description: "Consolidar consultas, cortar colunas de mesa, pré-agregar se necessário. Só então considere algo exótico. E se a resposta requer inteligência, o painel provavelmente está fazendo muito."
---
::

::warning{icon="i-lucide-hourglass"}
**Painéis lentos falham silenciosamente.** Ninguém registra uma multa dizendo "isso leva onze segundos". Eles abrem menos, então eles pedem o número em vez disso, então eles mantêm sua própria planilha - e a planilha discorda com o painel, que é como uma org termina com duas verdades. Quando alguém se queixa, o painel já perdeu.
::
