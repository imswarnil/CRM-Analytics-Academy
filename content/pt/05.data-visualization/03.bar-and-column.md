# Gráficos de barras e colunas

O mesmo gráfico, duas orientações, e mais painéis são decididos por sua ordem do que por qualquer outra coisa nesta seção.

## Horizontal ou vertical

::compare-cols
---
items:
  - title: "Barras horizontais"
    subtitle: "Categories that are words"
    icon: "i-lucide-align-left"
    pros:
      - "Labels read naturally, at any length"
      - "Ranking reads top to bottom, matching how people scan"
      - "Handles many categories without rotating text"
    cons:
      - "Feels unfamiliar to people expecting columns"
    verdict: "The default for segments, products, reps, sources."
  - title: "Colunas verticais"
    subtitle: "Categories that are periods"
    icon: "i-lucide-align-end-horizontal"
    pros:
      - "Time reads left to right, which readers expect"
      - "Good for a small number of short labels"
      - "Pairs naturally with a line on the same axis"
    cons:
      - "Long labels rotate, and rotated labels slow reading"
    verdict: "Months, quarters, stages — anything with a natural order."
---
::

## Ordenar é o cenário que importa.

CRM Analytics Tipos pelo... **Agrupando** por padrão, o que significa alfabeticamente para categorias de texto. Quase nunca é para isso que serve uma tabela de barras.

::warning{icon="i-lucide-arrow-down-wide-narrow"}
**Leitores assumem que os bares são classificados.** Apresentado com uma tabela de barras, o olho toma o primeiro bar como o maior e não verifica mais. Quando a ordem é alfabética, essa suposição é silenciosamente errada e a leitura errada é invisível - o gráfico é correto, o leitor não é. Ordenar a descida pela medida para qualquer agrupamento categórico, e manter a própria ordem do agrupamento apenas para o tempo e para estágios genuinamente ordenados.
::

## A regra básica

Para bares, **O comprimento é a codificação.**. Um bar duas vezes maior significa o dobro do valor, e os leitores confiam nisso sem pensar.

::note{icon="i-lucide-ruler"}
**Então o eixo de um gráfico de barras deve começar em zero.** Truncando-o para 40 porque tudo fica entre 40 e 60 torna uma diferença de 20% em uma barra três vezes maior, e o gráfico está sobre a proporção enquanto cada rótulo permanece preciso. Se pequenas diferenças importam e zero as torna invisíveis, isso é um sinal para usar um gráfico de linhas, um gráfico de pontos ou um alvo delta-contra-alvo - para não mover a linha de base de uma barra.
::

## Configurações práticas que valem a pena mudar.

::lesson-steps
---
items:
  - title: "Ordenar descendo pela medida"
    description: "Para cada grupo categórico. Esta é a única mudança de maior valor no widget."
  - title: "Limite-se ao topo N, e diga isso no título"
    description: "Dez barras são legíveis, quarenta é uma textura. \"Top 10 contas por ARR\" em vez de \"Contas por ARR\" - caso contrário alguém soma as barras visíveis e relata o total como errado."
  - title: "Coloque o valor na barra."
    description: "As etiquetas removem o passo de leitura do eixo para um pequeno número de barras. Largue-os quando o gráfico estiver denso o suficiente para colidir."
  - title: "Use uma cor"
    description: "Uma cor separada por categoria não codifica nada. A categoria já é a etiqueta do eixo. Passe a cor no bar que precisa de atenção, e deixe o resto neutro."
---
::

::tip{icon="i-lucide-palette"}
**Uma cor, uma exceção.** Um gráfico onde cada bar é uma cor diferente parece projetado e não comunica nada extra. Uma tabela de barras em um único ponto neutro, com uma barra acima ou abaixo do limite no sotaque, comunica uma descoberta antes que o leitor tenha lido uma etiqueta.
::
