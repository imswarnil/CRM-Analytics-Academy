# Atribuindo Acesso

Hora de colocar os conceitos para funcionar. Esta lição é uma caminhada prática Salesforce **Configuração** - Verificando as configurações do Analytics, inspecionando como um usuário real é licenciado e autorizado, e então **Construindo um novo conjunto de permissão.** Do zero. Abra sua orgia de desenvolvedores e siga em frente.

## Passo 1 - Verifique as configurações do Analytics

Comecem. **Configuração → Pesquisa Rápida → Análise → Configurações**. Aqui é onde você confirma que a org está pronta. Duas coisas que vale a pena notar aqui:

- **Linhas usadas** - O quê? CRM Analytics tem um limite de linha de dados, e esta página mostra o quanto você consumiu. Fique de olho nisso enquanto seus dados crescem.
- **Começando.** - Links e alternâncias que confirmam análise são ativados e apontam para o estúdio.

Uma rápida olhada aqui diz que a plataforma está ligada antes de você começar a atribuir acesso.

## Passo 2 - Inspecione o acesso de um usuário

Agora vá para **Configuração → Usuários** e abrir um usuário que já tem análise. Em seu registro de usuário você verá as duas camadas mais cedo nesta seção, lado a lado:

::lesson-cards
---
columns: 2
items:
  - title: "Licenças definidas."
    icon: "i-lucide-key-round"
    description: "O CRM Analytics (Tableau CRM) Mais PSL que dá direito ao usuário e possivelmente uma licença de aplicativo como Sales Analytics ao lado."
  - title: "Permissão definida para tarefas."
    icon: "i-lucide-shield-check"
    description: "Os conjuntos de permissão concedem capacidades reais. O conjunto de administrador padrão tem a maioria das permissões do sistema de análise pré-selecionadas."
---
::

Abra o **Permissões do sistema** do conjunto de permissão padrão do administrador e você verá quase todas as permissões de análise — Gerenciar o Analytics incluído — já verificadas. É assim que um administrador completo se parece. A maioria de seus usuários não deveria se parecer com isso.

## Passo 3 - Construir um conjunto de permissão

Agora o exercício real: criar um **Novo conjunto de permissão.** para um construtor de painéis, alguém que deveria construir e ver análises, mas não deve tocar no encanamento de dados.

::lesson-steps
---
items:
  - title: "Crie o conjunto de permissão."
    description: "Em Configuração → Conjuntos de Permissão, clique em Novo, dê-lhe um nome claro como CRMA Dashboard Builder, e salve."
  - title: "Permissões do Sistema Aberto"
    description: "Dentro do novo conjunto, abra a seção Permissões do Sistema e clique em Editar para escolher recursos analíticos."
  - title: "Conceda as capacidades diárias."
    description: "Habilite \"Use Analytics\", a habilidade de baixar e usar painéis, e permissão para criar aplicativos e painéis."
  - title: "Retenha os arriscados."
    description: "Deixe de lado a habilidade de adicionar conexões de dados e editar fluxos de dados, que pertencem a administradores, não construtores."
  - title: "Salvar e atribuir"
    description: "Salve o conjunto de permissão, então use Gerenciar atribuições para atribuí-lo ao usuário alvo (que já deve segurar o PSL)."
---
::

O resultado é um usuário que pode criar aplicativos, construir e baixar painéis, e explorar dados - mas **Não pode** adicionar conexões ou alterar fluxos de dados. Esse é o menor privilégio em ação, e é exatamente o tipo de conjunto que você distribuirá mais frequentemente em uma real implantação.

::tip{icon="i-lucide-lightbulb"}
Nome definido permissão após o **Papel** Eles representam: "CRMA Dashboard Builder", "CRMA Viewer", "CRMA Data Engineer". Future-você (e todo administrador que herdar a org) agradecerá quando for óbvio para o que cada conjunto é.
::
