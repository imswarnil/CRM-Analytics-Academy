# O REST API

Salesforce expõe análise através de sua REST APIDatasets, consultas, painéis e os metadados por trás deles.

## Autenticação

Pedidos carregam um token de acesso OAuth, obtido através de um aplicativo conectado. Dois pontos práticos importam mais do que a mecânica:

::lesson-steps
---
items:
  - title: "Use um usuário de integração dedicado."
    description: "Não uma pessoa. Uma pessoa sai, sua conta é desativada, e todo trabalho que se autentica como eles pára em um dia que ninguém previu. Uma conta de integração com apenas as permissões que precisa também faz uma trilha de auditoria significativa."
  - title: "Mantenha credenciais em uma loja secreta."
    description: "Variáveis ambientais de uma loja gerenciada, um cofre, ou o armazenamento secreto do informante. Nunca no roteiro, nunca em um caderno, nunca no repositório, e um acordo público torna isso irreversível ao invés de embaraçoso."
  - title: "Lidar com a expiração do símbolo como operação normal"
    description: "Tokens expiram, esse é o projeto. Um trabalho que morre durante a noite em um token expirado é um trabalho que não implementou atualização. Assumir que uma corrida pode cobrir uma expiração."
  - title: "Dê ao usuário de integração apenas o que ele precisa."
    description: "Um carregador precisa escrever conjuntos de dados, não ler todos os objetos da org. Licenças restritas limitam o raio de explosão de uma credencial vazada, e tornam óbvio para que serve o trabalho."
---
::

## Versão

Endpoints carregam uma versão no caminho. Prenda.

::note{icon="i-lucide-pin"}
**Uma versão presa é um script que continua funcionando quando a plataforma atualiza, e uma versão não montada é um script que muda o comportamento em uma data que alguém escolheu.** Atualização deliberadamente: mudar a versão, correr contra uma caixa de areia, confirmar a forma de resposta é o que você espera, em seguida, nave. Este é um hábito de dois minutos que impede a classe de falha onde nada no seu repositório mudou e o trabalho quebrou de qualquer maneira.
::

## Limites para projetar ao redor

Cada plataforma tem eles e os números específicos se movem, então o conselho durável é sobre a forma ao invés de figuras:

::compare-cols
---
items:
  - title: "Formas que escalam"
    subtitle: "Work with the limits"
    icon: "i-lucide-check"
    pros:
      - "Batch — one call with many rows rather than many calls with one"
      - "Incremental — send what changed, not everything, every night"
      - "Back off and retry on a rate-limit response rather than hammering"
      - "Check the current limits for your edition before sizing anything"
    cons:
      - "More code than the naive version"
    verdict: "Write it this way from the start."
  - title: "Formas que falham em escala"
    subtitle: "Fine in a test, not in production"
    icon: "i-lucide-x"
    pros:
      - "Simple, and works beautifully against 100 rows"
    cons:
      - "A call per row exhausts the daily allowance and starves everything else in the org"
      - "A full reload every night when 2% of rows changed"
      - "No retry, so one transient error loses the whole run"
    verdict: "This is how an analytics job takes down an org's API budget."
---
::

::warning{icon="i-lucide-gauge"}
**API Os limites são grandes.** Um trabalho de análise gananciosa não só se atrasa, mas consome subsídios que integrações, clientes móveis e outras equipes também estão se aproveitando. Isso faz de um carregador mal moldado um problema operacional para pessoas que nunca ouviram falar do seu painel, e é a razão para fazer um lote antes que alguém peça.
::
