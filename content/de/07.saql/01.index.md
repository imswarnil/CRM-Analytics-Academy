# Warum SAQL vorhanden

Jedes Objektiv, jedes Widget und jede Dashboard-Abfrage ist SAQL darunter. Klicken erzeugt es; Sie schreiben es nur, wenn die Klickoberfläche abgelaufen ist.

::note{icon="i-lucide-waves"}
**SAQL ist eine Stream-Transformation, keine deklarative Abfrage.** Jede Anweisung nimmt das Ergebnis der vorherigen Anweisung und transformiert es, wobei die gleiche Stromvariable neu zugewiesen wird. Es gibt keinen Optimierer, der Ihre Arbeit neu ordnet, also **Die Reihenfolge, in der Sie Anweisungen schreiben, ist der Plan, der ausgeführt wird** — das Filtern nach dem Gruppieren aggregiert wirklich Zeilen, die Sie verwerfen wollten. Dies ist der einzige strukturelle Unterschied, der Menschen fängt, die wissen, SQL gut.
::

## Die Form

```
q = load "Academy_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Load, narrow, group, compute, order, limit. Sechs Aussagen, jede Neuzuweisung `q`Jeder verzehrt, was der letzte produziert hat.

::warning{icon="i-lucide-eye-off"}
**Was SAQL sollte NICHT verwendet werden für: Definieren einer Geschäftsmetrik.** Eine Definition, die in die Abfrage eines Widgets geschrieben wurde, ist für jeden, der den Datensatz, das Rezept oder die Dokumentation liest, unsichtbar. Es wird Monate später von jemandem wiederentdeckt, der herausarbeitet, warum zwei Dashboards nicht übereinstimmen - und beides wird nicht falsch sein. Formabfragen in SAQL; Metriken im Rezept definieren.
::
