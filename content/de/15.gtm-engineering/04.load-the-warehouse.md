## Upload Order zählt (ein wenig)

Nicht für Korrektheit – für Vernunft. Laden Sie zuerst die Dimensionen, so dass beim Erstellen eines Rezepts die Lookup-Ziele bereits vorhanden sind.

::lesson-steps
---
items:
  - title: "Dimensionen zuerst"
    description: "Konten, Kontakte, Produkte, Mitarbeiter, Kampagnen. Fünf kleine Dateien. Jeweils zwei Minuten, und jetzt kann jedes spätere Rezept gegen sie aufschauen."
  - title: "Dann die Pipeline Fakten"
    description: "leads, opportunities, opportunity_products, quotes. Auf diesen läuft Modul 9 ab."
  - title: "Dann nach dem Verkauf"
    description: "Verwendung*monatlich, arr*Snapshots, Cases, Csat*Umfragen, Plattform*health_daily."
  - title: "Nachfrage zuletzt"
    description: "Web*Sitzungen, seo*Keywords, llm*Sichtbarkeit, Marketing*Ausgaben. Sie verbinden sich mit nichts, so dass nichts auf sie wartet."
---
::

::tip{icon="i-lucide-upload"}
Verwendung **Erstellen → Dataset CSV Datei**, kein Rezept, für den rohen Upload. Ein Rezept ist für die Gestaltung. Hochladen durch einen bedeutet, dass Sie einen Job jedes Mal wieder ausführen, wenn Sie einen rohen Tisch zurückhaben möchten.
::

## Beheben Sie die Feldmetadaten jetzt, nicht später

Das ist der Schritt, den jeder überspringt und den jeder bereut. Wann CRM Analytics folgert aus einem Schema, dass es drei vorhersehbare Fehler in diesem Datensatz macht.

::lesson-cards
---
columns: 3
items:
  - title: "Booleans werden zum Text"
    icon: "i-lucide-toggle-left"
    description: "IsWon, SLABreached, DeflectedByAI kommen als Strings 'true'/'false' an. Filterbar, aber Sie können sie nicht summieren - und das Zählen von Gewinnen ist eine Summe."
  - title: "Zahlen werden zu Dimensionen"
    icon: "i-lucide-hash"
    description: "LeadScore, Position, Erwähnung Rank wird als Text gelesen, weil es sich um kleine Ganzzahlen handelt. Dann können Sie sie nicht mitteln."
  - title: "Währung hat kein Format"
    icon: "i-lucide-dollar-sign"
    description: "Betrag und ARR ergeben 120000. Legen Sie das Format einmal im Datensatz fest und jedes Diagramm erbt $ 120K."
---
::

Der Fix ist Dataset **Feldmetadaten**, abgedeckt in Modul 4 — Bearbeiten des Feldes, Typ festlegen, Format festlegen, speichern. Tun Sie es einmal pro Datensatz und jedes Objektiv, Dashboard und SAQL Abfrage erbt es.

::metric-spec
---
items:
  - name: "Counting won deals"
    formula: "count() filtered to IsWon = true"
    grain: "Per opportunity"
    watchout: "Do NOT sum IsWon as text. If it uploaded as a string, either convert the field or count with a filter — a text 'true' summed gives you zero and no error."
---
::

## Drei Rezepte, einmal gebaut

Anstatt in zwanzig Dashboards beizutreten, treten Sie einmal bei und registrieren Sie das Ergebnis. Drei verbundene Datensätze tragen alles in diesem Abschnitt.

### Rezept 1 — `opp_enriched`

Das Pipeline-Arbeitspferd. Chancen, plus den konto- und rep-kontext, den jedes chart filtert.

::lesson-steps
---
items:
  - title: "Input: Chancen"
    description: "677 Reihen. Dies ist das Korn der Ausgabe - eine Zeile pro Gelegenheit, und es muss so bleiben."
  - title: "Treten Sie Accounts auf AccountId bei"
    description: "Lookup, nicht Append. Bringt Segment, Industrie, Region, HealthScore, SupportTier. One-to-one, also kein Fan-out."
  - title: "Treten Sie Reps auf Owner bei Id"
    description: "Bringt Rolle, RampStatus, AnnualQuota, Manager. Achten Sie auf leere OwnerId bei Self-Serve-Deals - sie haben keine Wiederholung, und ein Standard-Join wird sie stillschweigend fallen lassen."
  - title: "Aggregate opportunity_products first, THEN join"
    description: "Gruppe von Opportunity Id, nehmen Sie die Anzahl der Produkte und eine Komma-verbundene Produktliste. Das Verbinden der rohen Linienelemente multipliziert stattdessen jede Gelegenheit mit ihrer Produktzahl."
  - title: "Join final quote only"
    description: "Filtern Sie Zitate nach IsFinalVersion = true, bevor Sie beitreten, oder eine Gelegenheit wird zu bis zu fünf Zeilen."
  - title: "Output: opp_enriched"
    description: "Immer noch 677 Reihen. Überprüfen Sie diese Zählung, bevor Sie sie verwenden - wenn sie gewachsen ist, haben Sie sich aufgefächert."
---
::

::tip{icon="i-lucide-shield-alert"}
**Die eine Behauptung, immer zu laufen.** Nach jedem Join überprüfen Sie die Zeilenzählung gegen die Eingabe. `opp_enriched` Es müssen 677 Reihen sein. Wenn es 1.378 ist, haben Sie Zeilenelemente roh beigetreten; wenn es 818 ist, haben Sie alle Zitatversionen beigetreten. Row Count ist der billigste Korrektheitstest in der Analytik.
::

### Rezept 2 — `lead_funnel`

Leads, mit der Kampagne und dem Ergebnis beigefügt.

::lesson-steps
---
items:
  - title: "Input: Leads"
    description: "2.800 Zeilen, und die Ausgabe bleibt 2.800. Disqualifizierte Leads bleiben in - sie fallen zu lassen, bläst jede Conversion-Rate auf."
  - title: "An Kampagnen teilnehmen Kampagne Id"
    description: "Bringt Channel, Type, Spend, Region. Führt mit einer leeren Kampagne Id sind real (self-serve-signups) - halten sie sie mit einem linken join."
  - title: "Berechnen Sie die Stage Flags"
    description: "IsMQL, IsSQL, IsConverted existieren bereits. Hinzufügen von DaysToMQL = MQLDate - CreatedDate und DaysToSQL, so dass Geschwindigkeit in jedem Diagramm ohne Datumsmathematik verfügbar ist."
  - title: "Nehmen Sie am Opportunity Outcome teil"
    description: "Über ConvertedOpportunity Id, bring back Stage, Amount, IsWon. Jetzt beantwortet ein Datensatz \"welcher Kanal produzierte Einnahmen\", nicht nur \"welcher produzierte Leads\"."
---
::

### Rezept 3 — `account_360`

Eine Zeile pro Konto, mit allem, was damit passiert ist.

::lesson-steps
---
items:
  - title: "Input: Konten"
    description: "140 Reihen. Der Output muss 140 sein."
  - title: "Aggregierte Nutzung_monatlich für das Konto"
    description: "Gruppe nach AccountId: Summe BilledRevenue, durchschnittliche Nutzung Pct, nehmen Sie die neueste CommitState. Niemals roh beitreten - 2.616 Reihen gegen 140 ist das Lehrbuch Fan-out."
  - title: "Aggregierte Fälle für das Konto"
    description: "Zählen Sie Fälle, zählen Sie SLA-Verstöße, durchschnittliche CSAT, max LinkedToChurnRisk. Der Support wird zu drei Spalten auf dem Konto."
  - title: "Nehmen Sie den neuesten ARR Snapshot"
    description: "Filtern Sie arr_snapshots zum letzten MonthEnd und treten Sie dann bei. Schließen Sie sich allen Monaten an und multiplizieren Sie mit achtzehn."
  - title: "Ausgabe: account_360"
    description: "140 Zeilen und der einzige nützlichste Datensatz in Modul 10."
---
::

::note{icon="i-lucide-repeat-2"}
**Planen Sie sie, dann vergessen Sie sie.** Stellen Sie jedes Rezept auf Nachtlauf ein. Jedes Downstream-Dashboard liest einen Datensatz, keinen Join, was bedeutet, dass ein Dashboard nicht falsch sein kann, wie es ein Rezept nicht ist - ein einzelner Ort zum Beheben und ein einzelner Ort zum Auditieren.
::

## Der Fehler, der es wert ist, genannt zu werden

Ein verlockendes viertes Rezept: Verbinden Sie alles zu einem breiten Datensatz und erstellen Sie jedes Dashboard darauf. Es fühlt sich effizient an. Es ist eine Falle.

::compare-cols
---
items:
  - title: "Drei zielgerichtete Datensätze"
    icon: "i-lucide-layers-3"
    pros:
      - "Each has one obvious grain"
      - "Row-count assertions are meaningful"
      - "A fan-out is caught at build time"
    verdict: "What this section uses."
  - title: "Ein breiter \"Alles\"-Datensatz"
    icon: "i-lucide-package"
    pros:
      - "Only one thing to schedule"
    cons:
      - "No single grain, so every sum is suspect"
      - "Slow, and re-runs for any change"
      - "Fan-out is invisible until a number is absurd"
    verdict: "Avoid. The convenience is real and it costs you correctness."
---
::
