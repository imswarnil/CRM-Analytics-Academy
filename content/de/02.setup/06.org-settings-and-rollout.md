# Org-Einstellungen und Rollout

Zwei Dinge blieben vor dem Hands-on: die Schalttafel, und immer diese vor den Menschen ohne eine schlechte erste Woche.

## Die Einstellungsseite

Setup → Analytics → Einstellungen sind wo CRM Analytics ist aktiviert und wo Feature-Toggles live sind. Das meiste davon werden Sie einmal einstellen und nie wieder besuchen, aber drei Gewohnheiten sind es wert:

::lesson-steps
---
items:
  - title: "Lesen Sie die Seite, bevor Sie sie brauchen"
    description: "Zehn Minuten bedeutet jetzt, dass, wenn jemand sagt \"Können wir X einschalten\", Sie wissen, ob X ein Schalter, eine Lizenz oder ein Redesign ist. Das im Meeting beantworten zu können, ist unverhältnismäßig wertvoll."
  - title: "Neue Features in einer Sandbox zuerst aktivieren"
    description: "Umschalter ändern das Verhalten, und Verhaltensänderungen können verändern, was ein Live-Dashboard zeigt. Ein Entwickler oder eine Sandbox-Org ist der Ort, an dem Sie das herausfinden. Dies ist die eine wirklich wichtige Regel auf dieser Seite."
  - title: "Notieren Sie, was Sie geändert haben und warum"
    description: "Ein Umschalter, der vor achtzehn Monaten ohne Notiz umgedreht wurde, ist von einem Standard nicht zu unterscheiden, und niemand wagt es, ihn wieder zu ändern. Zwei Zeilen in den Projektnotizen verhindern eine permanente No-Touch-Zone."
---
::

::note{icon="i-lucide-flask-conical"}
**Ihre kostenlose Developer Org ist die Sandbox für diesen Kurs.** Alles, was Sie dort ermöglichen, ist konsequenzfrei, und genau das macht es wert, zu experimentieren. Behandeln Sie eine Produktionsorganisation als irgendwo ändern Sie Dinge absichtlich, nachdem Sie bereits gesehen haben, was die Änderung woanders bewirkt.
::

## Rollout: Die Sequenz, die funktioniert

Die technische Arbeit wird lange vor der Adoptionsarbeit erledigt. Die folgende Reihenfolge ist keine Bürokratie - jeder Schritt existiert, weil das Überspringen einen bestimmten, vorhersehbaren Fehler verursacht:

::field-table
---
dataset: "rollout sequence"
grain: "one row per step"
fields:
  - name: "1 — Two or three real users"
    type: "before anything else"
    role: "key"
    note: "Die Leute, die tatsächlich die Entscheidung treffen, unterstützt das Dashboard. Kein Komitee, kein Demopublikum. Sie werden ihnen innerhalb von zehn minuten sagen, ob der bildschirm ihre frage beantwortet, und dieses feedback ist mehr wert als jede interne Überprüfung."
  - name: "2 — Verify as them, not as you"
    type: "the non-negotiable step"
    role: "key"
    note: "Melden Sie sich als eingeschränkter Benutzer an. Ein Administrator sieht alles, so dass jeder Sicherheitsfehler für denjenigen unsichtbar ist, der ihn erstellt hat. Wenn Sie dies überspringen, wird ein Dashboard leer - oder zeigt die Angebote einer anderen Region - vor seinem Publikum."
  - name: "3 — One team"
    type: "a week or two"
    role: "dimension"
    note: "Jetzt ändern sich die Fragen von \"ist das richtig\" zu \"wie benutze ich es?\" Hier erfahren Sie, welche Etiketten mehrdeutig sind und welches Widget jeder falsch liest."
  - name: "4 — Everyone who needs it"
    type: "with the definitions attached"
    role: "dimension"
    note: "Versenden Sie die metrischen Definitionen neben dem Dashboard. Eine Zahl ohne Definition wird zum Argument, wenn sie zum ersten Mal mit der Tabellenkalkulation von jemandem nicht einverstanden ist - und das wird sie auch."
  - name: "5 — A named owner"
    type: "permanent"
    role: "measure"
    note: "Jemand besitzt den Zeitplan, die Definitionen und die Anfragen. Ein unbesessenes Dashboard verschlechtert sich leise: Das Rezept driftet, ein Feld ändert die Bedeutung und das Vertrauen geht, bevor jemand ein Ticket einreicht."
---
::

## Die zwei Dinge, die Menschen tatsächlich fragen

::compare-cols
---
items:
  - title: "„ Warum ist diese Zahl anders? „"
    subtitle: "Asked within the first week, always"
    icon: "i-lucide-equal-not"
    pros:
      - "Almost always a definition difference, not an error"
      - "Answerable in seconds if the metric spec exists"
    cons:
      - "Without a written definition it becomes a multi-day investigation, and trust drops while it runs"
    verdict: "Publish the definitions with the dashboard. Every time."
  - title: "„ Ist das live? „"
    subtitle: "Asked the moment a number looks wrong"
    icon: "i-lucide-clock"
    pros:
      - "A visible 'last refreshed' timestamp answers it permanently"
      - "Costs one text widget"
    cons:
      - "Without it, every staleness question becomes a personal support request to you"
    verdict: "Put the refresh time on the dashboard."
---
::

::tip{icon="i-lucide-timer-reset"}
**Das einzige Widget mit dem höchsten Wert auf jedem Produktions-Dashboard** ist ein Textfeld, das angibt, wann die Daten zuletzt aktualisiert wurden. Es lenkt eine ganze Kategorie von Fragen ab, es macht die Materialisierung ehrlich und nicht versteckt, und es dauert zwei Minuten, um hinzuzufügen.
::

## Was weiter zu tragen

- Aktivieren Sie zuerst neue Dinge an einem sicheren Ort und notieren Sie, was Sie aktiviert haben.
- Überprüfen Sie als eingeschränkter Benutzer, bevor jemand anderes es sieht - das ist die Gewohnheit, auf die der Kollaborationsabschnitt immer wieder besteht.
- Schiffsdefinitionen und ein Aktualisierungs-Zeitstempel mit jedem Dashboard.
- Geben Sie jedem Dashboard einen Besitzer oder erwarten Sie, dass es verrottet.
