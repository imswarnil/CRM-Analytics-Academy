## Die Syntax, da es das gemeinsame Stolpern ist

```
'Region' == "$User.Sales_Region__c"
```

**Einzelnotierungen** Umhüllen der Datensatzspalte. **Doppelangebot** wrap das User Attribut. Die asymmetrie ist, wie die syntax eine spalte von einem wert unterscheidet, und das umkehren ist der fehler, den sie mindestens einmal machen werden.

Kombination von Einsatzbedingungen `||` für oder und `&&` für und:

```
'Region' == "$User.Sales_Region__c" || "$User.Sales_Region__c" == "ALL"
```

::warning{icon="i-lucide-spell-check"}
**Prädikate vergleichen Strings genau.** `EMEA`, `emea` und `EMEA ` mit einem Hinterraum sind drei verschiedene Regionen. Wenn ein Prädikat nichts zurückgibt und die Syntax stimmt, drucken Sie die eindeutigen Werte der Spalte und den Wert im Benutzerdatensatz aus und vergleichen Sie sie Zeichen für Zeichen. Dies ist die zweithäufigste Ursache nach einem leeren Feld und sieht mit einer gebrochenen Regel identisch aus.
::

## Warum ein User hier attributiert und eine Hierarchie in der Produktion

Diese Lektion verwendet ein Feld im Benutzerdatensatz, weil es den Mechanismus sichtbar macht: eine Spalte, einen Vergleich, einen Ort, an dem man schauen kann, wenn es sich schlecht benimmt.

Die meisten Produktionsorganisationen wollen schließlich stattdessen die Rollenhierarchie - ein Manager, der alles unter ihnen sieht, ohne dass jemand ein Regionsfeld für Hunderte von Benutzern pflegt. Dies erfordert einen flachen Knoten im Rezept, der das Material des Datenvorbereitungsabschnitts ist. Der Mechanismus ist identisch; nur die Spalte, die das Prädikat mit Änderungen vergleicht.
