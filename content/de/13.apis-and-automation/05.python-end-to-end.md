## Das Skelett

```python
import os, csv, json, math, requests

BASE   = os.environ["SF_INSTANCE_URL"]        # from the secret store
TOKEN  = get_access_token()                    # refreshable
HEAD   = {"Authorization": f"Bearer {TOKEN}"}
CHUNK  = 10_000                                # rows per part

def declare(dataset, operation, metadata):
    """Create the upload job. Nothing is sent yet."""
    body = {"Format": "Csv", "EdgemartAlias": dataset,
            "Operation": operation, "Action": "None",
            "MetadataJson": metadata}
    r = requests.post(f"{BASE}/services/data/v62.0/sobjects/InsightsExternalData",
                      headers=HEAD, json=body, timeout=60)
    r.raise_for_status()
    return r.json()["id"]

def upload_parts(job_id, rows, header):
    """Send the rows as numbered parts. Part numbers start at 1."""
    for i in range(0, len(rows), CHUNK):
        part = i // CHUNK + 1
        payload = encode_csv(header, rows[i:i + CHUNK])
        post_part(job_id, part, payload)

def complete(job_id):
    """The step that is forgotten. Until this runs, nothing is processed."""
    requests.patch(f"{BASE}/services/data/v62.0/sobjects/InsightsExternalData/{job_id}",
                   headers=HEAD, json={"Action": "Process"}, timeout=60).raise_for_status()
```

::note{icon="i-lucide-code"}
**Die Endpunktpfade und das genaue Metadatenschema wechseln zwischen den Releases** - Überprüfen Sie die aktuelle Dokumentation für Ihre API Version, anstatt einen Pfad von einem Blog-Post zu kopieren, einschließlich dieses. Was sich nicht ändert, ist die Sequenz: deklarieren, Teile, vervollständigen, verifizieren. Lernen Sie die Form und schauen Sie nach den Details.
::

## Verifizierung ist der Teil, der seinen Unterhalt verdient

```python
expected = len(rows)
actual   = dataset_row_count(dataset)          # read back from metadata
if actual != expected:
    raise SystemExit(f"load mismatch: sent {expected}, dataset holds {actual}")
```

::tip{icon="i-lucide-shield-check"}
**Fehlschlagen Sie lautstark bei einer Fehlanpassung, anstatt eine Warnung zu protokollieren.** Ein Job, der nach dem Laden von 80% der Zeilen Null verlässt, erzeugt ein Dashboard, das so lange falsch ist, wie es jemanden braucht, um es zu bemerken - was bei einer Zahl, für die niemand eine Vorbedingung hat, Monate sein kann. Ein Exit-Code wird vom Scheduler gelesen; eine Warnung in einem Protokoll wird von niemandem gelesen.
::

## Abfrage des Ergebnisses zurück

Die gleiche Sitzung kann laufen SAQL, die einen Abgleichschritt am Ende einer Ladung natürlich macht: Ziehen Sie die Summe, die der Datensatz jetzt meldet, und vergleichen Sie sie mit der eigenen Figur des Quellsystems. Das ist die Antwort-Schlüssel-Gewohnheit aus dem automatisierten APIs-Bereich - und es ist die wertvollste Sache, die ein Loader über das Laden hinaus tun kann.

## Es laufen lassen

Was auch immer es ausführt - Cron, ein CI-Zeitplan, ein Orchestrator - braucht drei Dinge: den Zeitplan, die Anmeldeinformationen aus einem Geheimladen und irgendwo ist der Fehler *gesehen*. Ein Job, der in einem Protokollverzeichnis fehlschlägt, das niemand öffnet, ist ein Job, der nicht läuft, und Sie finden es Wochen später heraus.
