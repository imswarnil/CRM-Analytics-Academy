# Leistung

Ein Armaturenbrett, das zwölf Sekunden dauert, ist ein Armaturenbrett, das Menschen nicht mehr öffnen. Die Ursachen sind gering und die Fixes sind meist strukturell und nicht clever.

## Zählen Sie die Abfragen, nicht die Widgets

Jedes Widget wird durch eine Abfrage gefüttert. Mehrere Widgets können sich eines teilen - und wenn nicht, gibt ein Bildschirm mit zwölf Widgets zwölf Abfragen aus.

::tip{icon="i-lucide-merge"}
**Dies ist der größte verfügbare Hebel, und er ist normalerweise kostenlos.** Eine Überschrift, ein Balkendiagramm und eine Tabelle, die das gleiche Maß zeigt, werden in drei Richtungen häufig geschnitten *kann* Teilen Sie eine einzelne Abfrage. Die Konsolidierung ist oft der Unterschied zwischen zwölf Sekunden und zwei, und es ändert nichts daran, wie das Dashboard aussieht oder sich verhält.
::

## Der Getreidehandel

Abschnitt 3 sagte, dass das Korn eines Datensatzes eine Entscheidung ist. Hier ist, wo Sie dafür bezahlen:

::compare-cols
---
items:
  - title: "Feinkorn"
    subtitle: "Every row preserved"
    icon: "i-lucide-microscope"
    pros:
      - "Any question is answerable from it"
      - "One dataset serves many dashboards"
    cons:
      - "Every widget aggregates a lot of rows, on every load, for every viewer"
      - "Fan-out risk is handed to every designer who touches it"
    verdict: "Right for exploration, expensive for an exec board."
  - title: "Voraggregiert"
    subtitle: "Summarised in the recipe"
    icon: "i-lucide-box"
    pros:
      - "Fast — the aggregation happened once, overnight"
      - "The definition is settled upstream, so nobody can compute it differently"
    cons:
      - "Questions below the chosen grain are no longer answerable"
      - "Another dataset to schedule and maintain"
    verdict: "Right for a dashboard many people open daily."
---
::

::note{icon="i-lucide-layers"}
**Die normale Produktionsantwort ist beides.** Ein feinkörniger Datensatz für die Erkundung und ein voraggregierter hinter dem Dashboard, den jeder öffnet. Das Lager von Section 7 ist absichtlich so gebaut: Die Tische, die Sie erkunden, sind nicht immer die Tische, die der Vorstand liest.
::

## Die anderen Ursachen, in grober Reihenfolge

::field-table
---
dataset: "what makes dashboards slow"
grain: "one row per cause"
fields:
  - name: "Too many distinct queries"
    type: "most common"
    role: "measure"
    note: "Zwölf Widgets laufen jeweils ihre eigenen. Konsolidieren Sie, was geteilt werden kann, und die Änderung ist für Benutzer unsichtbar, außer dass die Seite erscheint."
  - name: "Aggregating fine grain at query time"
    type: "common"
    role: "measure"
    note: "Millionen von Zeilen summiert pro Widget pro Last. Pre-Aggregate im Rezept, wenn das Dashboard täglich von vielen Personen geöffnet wird."
  - name: "Very wide tables"
    type: "common"
    role: "dimension"
    note: "Eine Wertetabelle mit zwanzig Spalten und Hunderten von Zeilen ist langsam abzufragen und sowieso unlesbar. Das Schneiden auf fünf Spalten und zehn Zeilen behebt beide Probleme auf einmal."
  - name: "Complex bindings"
    type: "occasional"
    role: "dimension"
    note: "Verkettete Bindungen können sequentielle statt parallele Abfragen erzwingen: Das Widget C wartet auf B, das auf A wartet. Es lohnt sich, zu überprüfen, wenn ein Dashboard langsam ist und nicht mit seiner Widgetzahl übereinstimmt."
  - name: "Row-level security evaluation"
    type: "structural"
    role: "key"
    note: "Vorhersagen und vor allem das Teilen von Vererbung kosten pro Abfrage und Zuschauer etwas. Dies ist ein korrekter Preis, kein Defekt - aber es ist ein Grund, warum ein Dashboard für einen Viewer mit komplexem Zugriff langsamer ist als für Sie."
---
::

## Wie man es tatsächlich misst

::lesson-steps
---
items:
  - title: "Laden Sie es als normalen Benutzer, nicht als Sie selbst"
    description: "Ihr Admin-Konto kann die Sicherheitsbewertung überspringen, für die ein echter Viewer bei jeder Abfrage bezahlt. Das Testen der Leistung als Administrator kann sie erheblich unterschätzen."
  - title: "Beobachten Sie, welche Widgets zuletzt ankommen"
    description: "Sie kehren zurück, wenn ihre Fragen zurückkehren, so dass die Langsamen sich selbst verkünden. Normalerweise ist es der breiteste Tisch und das feinste Korndiagramm."
  - title: "Zählen Sie die verschiedenen Abfragen"
    description: "Die Abfrageliste des Dashboards zeigt sie an. Wenn es mehr Anfragen gibt als wirklich unterschiedliche Fragen auf dem Bildschirm, gibt es eine Konsolidierung."
  - title: "Fixe Struktur vor Cleverness"
    description: "Konsolidieren Sie Abfragen, geschnittene Tabellenspalten, gegebenenfalls voraggregieren. Nur dann betrachten Sie etwas Exotisches - und wenn die Antwort Cleverness erfordert, tut das Dashboard wahrscheinlich zu viel."
---
::

::warning{icon="i-lucide-hourglass"}
**Langsame Dashboards versagen leise.** Niemand meldet ein Ticket mit der Aufschrift "Das dauert elf Sekunden". Sie öffnen es weniger, dann fragen sie dich stattdessen nach der Nummer, dann behalten sie ihre eigene Tabellenkalkulation — und die Tabellenkalkulation stimmt nicht mit dem Dashboard überein, so dass eine Organisation mit zwei Wahrheiten endet. Wenn sich jemand beschwert, hat das Dashboard bereits verloren.
::
