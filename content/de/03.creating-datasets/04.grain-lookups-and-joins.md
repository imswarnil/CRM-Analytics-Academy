# Grain, Lookups und Joins: Das mentale Modell

Diese Lektion hat kein Video absichtlich - es ist das Konzept zu verlangsamen und *Internalisieren* Bevor Sie etwas bauen. Jedes Datensatzproblem, das ich im Laufe der Jahre behoben habe, geht auf eines von zwei Dingen zurück: das falsche **Körner**oder a **Verbinden** Dass sich die Reihen ruhig vervielfachen. Machen Sie das richtig und die Werkzeuge in den nächsten Lektionen werden offensichtlich.

## Was ist Getreide?

**Getreide** ist die Frage: *Was bedeutet eine Zeile?*

Wenn Sie einen Datensatz "über Chancen" erstellen, ist das Korn eine Zeile pro **Gelegenheit**. Das ist dein **Kernobjekt** - Ihre niedrigste, detaillierteste Ebene. Alles andere, was Sie einbringen (das Konto, der Eigentümer) ist *Belegende Informationen* An diese Gelegenheitszeile angehängt. Das Korn ändert sich nie: eine Gelegenheit, eine Reihe.

::tip{icon="i-lucide-ruler"}
Sagen Sie es laut, bevor Sie bauen: **Eine Zeile dieses Datensatzes ist eine \_\_\_\_\_.** Gelegenheit. Fall. Konto. Tätigkeit. Wenn Sie diesen Satz nicht sauber beenden können, sind Sie noch nicht bereit, den Datensatz zu erstellen - Sie entscheiden immer noch, was es ist *über*.
::

## Beginnen Sie mit dem niedrigsten Objekt

Hier ist die Regel, die dich jedes Mal rettet: **Beginnen Sie mit Ihrem niedrigsten Kornobjekt und schauen Sie *bis* Hierarchie.**

In Salesforce, eine Chance **Blick nach oben** zu einem Account (über) `AccountId`) und an einen Benutzerbesitzer (über `OwnerId`. Ein Konto sitzt *höher* Ein Konto hat *viele* Chancen. Also:

Deshalb ist das Objekt, mit dem Sie beginnen, ein *Entwurfsentscheidung*Nicht ein nachträglicher Einfall. Wenn es in Ihrem Dashboard um Chancen geht, beginnen Sie mit Opportunity. Wenn Sie wirklich eine Zeile pro Konto benötigen, ist das ein **Unterschiedlicher Datensatz** mit einem anderen Korn - und das ist in Ordnung, seien Sie einfach bewusst.

## Lookups vs. Joins

Du wirst das Wort sehen **Verbinden** In den tools, aber für baseline-datensätze, was sie fast immer wollen, ist ein. **Lookup**.

- A **Lookup** verbindet Felder von einem übergeordneten "Eltern"-Objekt an jede Kinderzeile. Bringen Sie den Namen und die Branche des Kontos zu jeder Gelegenheit - **ohne Kornwechsel**. Eine Chance bleibt eine Reihe.
- A **Verbinden** (im volleren relationalen sinne) können reihen von vielen zu vielen und. **multipliziert** sie. Verbinden Sie Gelegenheiten mit ihren Zeilenelementen und plötzlich wird eine Gelegenheit zu fünf Zeilen - eine pro Zeilenelement. Manchmal ist es das, was du willst; oft ist es ein Bug, der deine Summen aufbläht.

::tip{icon="i-lucide-triangle-alert"}
Der klassische Fehler: Sie schließen sich einem Elternteil an ein Kind an, das eine Reihe erwartet, und bekommen viele, also jede `sum(Amount)` ist jetzt doppelt oder dreifach gezählt. Wenn eine Summe zu groß aussieht, **Überprüfen Sie zuerst Ihr Getreide.** Neun von zehn Mal wurde ein Lookup wie ein Fan-Out-Beitritt behandelt.
::
