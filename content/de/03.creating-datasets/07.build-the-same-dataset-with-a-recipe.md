# Erstellen Sie den gleichen Datensatz mit einem Rezept

Lasst uns die **exakt gleich** Chancendatensatz - Gelegenheit + Konto + Benutzer - aber mit einem **Rezeptur** Diesmal. Rezepte sind die moderne Data-Prep-Engine: Drag-and-Drop, visuell und weitaus flexibler als ein Datenfluss. Der Kompromiss ist, dass *Sie* Die Beziehungen besitzen. Dataset Builder haben das nächste Objekt und die Join-Tasten für Sie herausgefunden; In einem Rezept entscheiden Sie, was mit was und wie verbunden ist.

## Starten Sie ein neues Rezept

von Analytics Studio, **Erstellen von Dataset** und wählen Sie aus Ihren Datensätzen oder Synchronisierungsobjekten - dies öffnet eine **Rezeptur** im Data Manager (Datenflüsse) & Rezepte → **Rezepte** → neues Rezept.

Im Rezept, **Ausgewählte Daten** zeigt alles, was Ihnen zur Verfügung steht: von Ihnen erstellte Datensätze, externe Quellen und die verbundenen / synchronisierten Objekte aus Salesforce. Schnappen Sie sich die gleichen drei - **Gelegenheit**, **Konto**, **Nutzer**.

::tip{icon="i-lucide-list-checks"}
Erster wirklicher Unterschied von Dataset Builder: Sie können **Alle auswählen** Felder pro Objekt, anstatt sie einzeln anzuklicken - eine enorme Zeitersparnis für breite Objekte. Aber nicht. Wenn ein Objekt mehr als 150 Felder hat, benötigen Sie nicht alle; ein zu breiter Datensatz ist schlecht zu scrollen und langsamer abzufragen. Bringen Sie nur das mit, was das Dashboard braucht.
::

Klicken **Nächster Artikel** und Sie landen in der Rezeptleinwand — Ihre drei Objekte sitzen dort, **nicht verbunden**. Das ist der Hauptunterschied: In einem Rezept ist es Ihre Aufgabe, sie zu verbinden.

## Verbinden Sie die Objekte

Es gelten weiterhin Getreidevorschriften: **Opportunität ist das niedrigste Niveau**, so dass sich alles daran anschließt.

::lesson-steps
---
items:
  - title: "Account bei Opportunity"
    description: "Ziehen Sie das Plus des Opportunity-Knotens auf das Konto. Es wird ein Join Node. Das Rezept nimmt die Konto-ID = Konto-ID korrekt auf - überprüfen Sie sie und wenden Sie sie an."
  - title: "Fügen Sie dem Benutzer bei Opportunity - Beobachten Sie den Schlüssel"
    description: "Fügen Sie den Benutzer zu Opportunity hinzu (nicht zu Account - der Eigentümer gehört zu der Gelegenheit). Hier rät das Rezept falsch: Es passt Opportunity ID zu User ID. Sie wollen Owner ID → User ID. Befestigen Sie den Schlüssel von Hand."
  - title: "Jeden Schritt anwenden"
    description: "Rezepte speichern nicht so, wie Sie es erwarten - klicken Sie unten auf Anwenden, um jeden Knoten festzulegen, bevor Sie fortfahren."
---
::

::tip{icon="i-lucide-triangle-alert"}
Dies ist die Rezeptsteuer, und es lohnt sich zu internalisieren: **Es wählt automatisch einen join-schlüssel aus und kann den falschen auswählen.** Für den Besitzer, den Sie brauchen `OwnerId → User.Id`, nicht `Opportunity.Id → User.Id`. Sie müssen *Kennen Sie Ihre Objekte* Gut genug, um es zu fangen. Dataset Builder Hätte dich niemals diesen Fehler machen lassen - das ist die Sicherheit, die du für die Kontrolle eintauschst.
::

## Kontrollieren Sie Ihre Spalten

Rezepte geben Ihnen echte Kontrolle über die Ausgabespalten:

- **Verbundart** Erweitern Sie den Join Node, um einen **Lookup** Vs ein Full Join. (Wir haben besprochen, warum das in der Getreidelektion wichtig ist; Behalte diese als Lookups hier.)
- **Präfixe** - Felder von Account kommen als `Account.Name`, `Account.Industry`und so weiter. Sie können diese Präfixe umbenennen, damit die letzten Spalten so gelesen werden, wie Sie möchten.
- **Halten oder Fallen** Vorschau der eingehenden Spalten und **Häute** die Sie nicht brauchen, damit sie nie den Output erreichen. Trimm `User.` Felder nur auf den besitzernamen und das foto, zum beispiel.

## Hinzufügen des Ausgabeknotens

Hier ist der Schritt, den die Leute vergessen: **Nichts existiert als nutzbarer Datensatz, bis Sie einen Ausgabe- (Register-) Knoten hinzufügen.** Die Verknüpfungen allein produzieren nichts, was Sie auf ein Armaturenbrett setzen können.

::lesson-steps
---
items:
  - title: "Hinzufügen des Ausgabeknotens"
    description: "Klicken Sie nach Ihrem letzten Beitritt auf das Plus und fügen Sie einen Ausgabeknoten hinzu. Das ist es, was den Datensatz tatsächlich materialisiert."
  - title: "Nennen Sie es absichtlich"
    description: "Geben Sie ihm ein klares Etikett (z. B. 'Opp Owner Acc - aus dem Rezept'). Labels können Leerzeichen haben; die API Name kann nicht. Verwenden Sie eine saubere API Name können Sie später in Bindungen einfügen."
  - title: "Anwenden, dann speichern und ausführen"
    description: "Wenden Sie den Ausgabeknoten an und speichern und führen Sie das Rezept aus. Es führt und baut Ihren Datensatz."
---
::

## Gleiches Ergebnis, unterschiedlicher Motor

Wenn es fertig ist, haben sie die gleichen chancen datensatz — gebaut von einem. **Rezeptur** Lesen von den gleichen synchronisierten Objekten anstelle von einem Datenfluss. Zwei Motoren, ein Ergebnis.
