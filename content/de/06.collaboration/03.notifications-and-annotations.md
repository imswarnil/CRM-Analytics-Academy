# Benachrichtigungen und Anmerkungen

Sharing ist eine *Zug* Feature - jemand muss das dashboard öffnen. **Meldungen** sind a *Schub* Funktion: die plattform beobachtet eine nummer für sie und e-mails, wenn sie eine linie kreuzt, die sie gezeichnet haben. Für einen vielbeschäftigten Geschäftsanwender ist dieser Unterschied alles.

## Festlegung einer Mitteilung

Benachrichtigungen live im **Widget** Höhe. Öffnen Sie das Aktionsmenü des Widgets und wählen **Gruppenmitteilung**.

::lesson-steps
---
items:
  - title: "Filtern Sie das Dashboard nach dem, was Ihnen wichtig ist"
    description: "Dieser Schritt ist nicht optional und nicht kosmetisch - die Benachrichtigung erfasst den aktuellen Filterkontext. Holen Sie sich das Widget, das zuerst Ihren Datenabschnitt zeigt."
  - title: "Open Set Benachrichtigung auf dem Widget"
    description: "Verfügbar auf Widgets, die durch ein Measure unterstützt werden - Zahlenkacheln und Diagramme sind die üblichen Kandidaten."
  - title: "Definieren Sie die Bedingung"
    description: "Wählen Sie das Maß und einen Schwellenwert: größer als, kleiner als, gleich einem Wert. 'Offene Pipeline unter 2M', 'Fälle über 50'."
  - title: "Wählen Sie einen Zeitplan"
    description: "Wie oft bewertet die Plattform den Zustand - stündlich, täglich, wöchentlich, zu einem Zeitpunkt, den Sie auswählen. Der Scheck läuft auf dieser Kadenz; Die E-Mail kommt nur an, wenn die Bedingung wahr ist."
  - title: "Entscheidung über Wiederholungsverhalten"
    description: "Klicken Sie auf \"benachrichtigen Sie mich nur beim ersten Mal, wenn die Bedingungen erfüllt sind\", wenn Sie eine einzige Warnung pro Verstoß anstelle einer jeden Bewertung wünschen."

::

Das letzte Kontrollkästchen ist der Unterschied zwischen einer nützlichen Warnung und einem Posteingang, den Sie ignorieren. Wenn eine Metrik für drei Wochen unter dem Ziel liegt, möchten Sie 21 E-Mails oder eine? Für die meisten Schwellenalarme ist die Antwort eine.

## Warum die *Nutzer* Setzt dies ein, nicht der Designer

Dies ist der Teil, der die Leute stolpert, und es ist die wichtigste Idee in der Lektion.

Meldung **erbt den Filterzustand des Dashboards zum Zeitpunkt seiner Erstellung**. Es schaut nicht nur "das Widget" - es schaut *die Abfrage, die das Widget für Sie ausgeführt hat, wobei Ihre Auswahl angewendet wurde*.

Das bedeutet:

::lesson-cards

items:
  - title: "Gleiches Widget, unterschiedliche Warnungen"
    icon: "i-lucide-git-branch"
    description: "Ein West-Region-Manager filtert nach West und setzt eine Benachrichtigung. Ein Manager der Ostregion tut dasselbe im Osten. Identisches widget, zwei wirklich unterschiedliche warnungen - jede beobachtet ihre eigenen zahlen."
  - title: "Der Designer kann es nicht für sie tun"
    icon: "i-lucide-user-x"
    description: "Eine Benachrichtigung, die Sie erstellen, gehört Ihnen und überwacht Ihre Filter. Es ist ein persönliches Abonnement für eine Bedingung, keine Dashboard-Eigenschaft, die Sie einmal für alle konfigurieren."
---
::

Der Job des Designers hier ist *Kommunikation*Nicht Konfiguration. Wenn Sie ein Dashboard übergeben, zeigen Sie dem Publikum, wo **Gruppenmitteilung** lebt und macht den Punkt explizit: Filtern Sie zuerst Ihre Welt, dann setzen Sie die Warnung.

::tip{icon="i-lucide-alert-circle"}
Jeder Nutzer ist beschränkt auf **10 Meldungen**. Das ist eine Pro-User-Cap über CRM Analyticsnicht pro Dashboard. Es ist großzügig für den beabsichtigten Gebrauch - eine Handvoll Metriken, über die Sie wirklich informiert werden müssen - aber es bedeutet, dass Benutzer sie absichtlich ausgeben sollten, anstatt eine auf jede Kachel zu setzen, die ihnen gefällt.
::

Benachrichtigungen auch Feuer auf **mobil**. Wenn dein Publikum die CRM Analytics Eine mobile App, eine Benachrichtigung kommt als Push-Benachrichtigung auf ihrem Telefon an, die für ein feldbasiertes Team oft der einzige Analytics-Touchpoint ist, der zuverlässig landet.

## Anmerkungen

Die zweite Hälfte dieser Lektion ist **Annotat**, und es löst ein anderes Problem: nicht "Sag mir, wenn sich eine Zahl bewegt", sondern "lass uns über diese Zahl sprechen".

Annotate befindet sich im selben Widget-Aktionsmenü. Es öffnet einen Kommentar-Thread, der an dieses bestimmte Widget angehängt ist, und postet ihn auf **Geschwätz** - mit zwei Optionen, die es weitaus nützlicher machen als ein einfaches Kommentarfeld:

- **Fügen Sie einen Screenshot hinzu** des Widgets, wie es derzeit aussieht, so dass das Gespräch ein Bild von dem hat, was Sie gesehen haben.
- **@mention** Kollegen, die sie in den Thread ziehen und ihnen das normale Salesforce Weg.

Zwei sehr unterschiedliche Zielgruppen nutzen dies, und beide sind erwähnenswert, wenn Sie Benutzer trainieren:

::lesson-cards
---
columns: 2
items:
  - title: "Geschäftsgespräche"
    icon: "i-lucide-message-circle"
    description: "'@Priya, warum hat Central in Woche 4 30% fallen lassen?' - die Frage lebt auf dem Widget selbst, mit dem visuellen Anhang, anstatt in einem verlorenen E-Mail-Thread."
  - title: "Entwurfsprüfung"
    icon: "i-lucide-clipboard-check"
    description: "Während der UAT kommentieren die Stakeholder die Widgets, die sie ändern möchten. Sie erhalten Feedback an das genaue Widget und nicht an ein Dokument, in dem steht: \"Das Diagramm in der Mitte sieht falsch aus\"."
---
::

Diese zweite Verwendung ist einer der praktischsten Tricks in diesem Abschnitt. Durch das Ausführen der Dashboard-Anmeldung durch Anmerkungen erhalten Sie eine eindeutige, gefädelte, Screenshot-gestützte Liste von Änderungsanforderungen - und dies geschieht innerhalb des Tools anstelle davon.

Benachrichtigungen und Anmerkungen halten die Menschen mit dem Dashboard beschäftigt. Aber früher oder später will jemand die Zahlen *aus* davon - in eine Tabelle. Das ist die nächste Lektion: **Download von Daten**.
