# Die Designschicht: Lenses, Dashboards & Apps

In der letzten Lektion formten wir Rohdaten in schnelle, optimierte Datensätze. Aber ein Datensatz selbst ist für Geschäftsanwender unsichtbar - er braucht ein Gesicht. Das ist die Aufgabe der **Designschicht**, wo Datensätze zu Dingen werden, die Menschen tatsächlich betrachten und erforschen: **Linsen**, **Armaturenbretter**, und **Apps**. Diese drei Konzepte sind das alltägliche Vokabular von CRM AnalyticsAlso machen wir sie zur zweiten Natur.

## LensesSchnelle, Self-Service-Exploration

A **Objektiv** Der schnellste Weg ist *Blick* in einem Dataset. Öffnen Sie einen Datensatz, und Sie werden in ein Objektiv fallen gelassen: eine leichte Erkundungsfläche, auf der Sie nach einem Feld gruppieren, das Maß ändern, Diagrammtypen wechseln und filtern können - alles mit wenigen Klicks.

Stellen Sie sich ein Objektiv vor, als würde man einem einzelnen Datensatz eine schnelle Frage stellen:

- "Wie viele Möglichkeiten haben wir auf der Bühne?"
- "Was ist der Gesamtumsatz nach Region in diesem Quartal?"

Sie bauen nichts Poliertes; Sie erforschen. Lenses sind inhärent **Selbstbedienung** — ein neugieriger Benutzer kann seine eigene Frage beantworten, ohne auf einen Entwickler zu warten.

::tip{icon="i-lucide-search"}
Erreichen Sie eine Linse, wenn Sie eine *Schnelle Antwort aus einem Datensatz*. Es ist das analytische Äquivalent einer schnellen Skizze.
::

## Dashboards: Curated, Multi-Widget Analytics

Wenn eine Reihe von Fragen wichtig genug ist, um sie immer wieder zu beantworten - für ein Team, ein Meeting, eine Rolle - graduieren Sie von einer Linse zu einer **Armatur**.

Ein Dashboard ist eine **Kuratierte Sammlung von Widgets**: mehrere Diagramme, Tabellen, Filter, Umschalter, Zahlenkacheln und Text, die absichtlich auf einer Leinwand angeordnet sind. Im Gegensatz zu einem einzelnen Objektiv kann ein Dashboard:

- Abziehen von **Mehrere Datensätze** Sofort.
- Kombinieren Sie mehrere Visualisierungen zu einer kohärenten Geschichte.
- Angebot **Interaktivität** Filter und Auswahlen, die die gesamte Seite zusammen aktualisieren.

Ein Dashboard ist *konstruiert*. Jemand entscheidet, welche Fragen das Publikum interessiert, wählt die richtigen Charts aus und legt sie so aus, dass die Antwort auf einen Blick offensichtlich ist. (Gutes Dashboard-Design ist eine Fähigkeit für sich - wir decken es später im Kurs ab.)

## Apps: Gruppierung und, entscheidend, Teilen

Sie haben Linsen und Dashboards. Wo leben sie und wer darf sie sehen? Geben Sie die **App.**.

An **App.** ist im wesentlichen a **Ordner** Diese Gruppen bezogen sich CRM Analytics Vermögenswerte zusammen:

- Dashboards
- Lenses
- Datensätze
- Geschichten

Aber eine App ist mehr als ein ordentlicher Container. Es ist auch die Einheit von **Zugang und gemeinsame Nutzung**. Normalerweise teilen Sie nicht jedes Dashboard einzeln; Sie teilen die **App.**Alles im Inneren erbt diesen Zugang.

::note{icon="i-lucide-folder-lock"}
Die Sicherheit in der Designschicht wird am **App.** Höhe. Gewähren Sie einem Benutzer Zugriff auf die Sales-App, und er kann die Dashboards, Objektive und Datensätze sehen, die er enthält - nicht mehr, nicht weniger.
::

Aus diesem Grund erstellen Unternehmen zweckgerichtete Apps nach Funktionen:

- A **Verkaufs-App** für Pipeline- und Prognose-Dashboards, die mit dem Verkaufsteam geteilt werden.
- An **HR-App** für Headcount und Abnutzung, nur mit HR geteilt.
- A **Finanz-App App** für Einnahmen und Margen, beschränkt auf die Finanzierung.

Apps können sein **privat** - sichtbar nur für ihren Schöpfer, während ein Dashboard ein Work-in-Work ist - oder **geteilt** mit bestimmten Benutzern, Rollen oder Gruppen, sobald es fertig ist. Mit dieser Flexibilität können Sie privat sicher bauen und dann genau das richtige Publikum veröffentlichen.
