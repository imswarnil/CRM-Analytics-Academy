# Wie die Daten ankommen

Fünf Stufen, in der Reihenfolge. Zu wissen, in welchem Sie stehen, ist das meiste Debugging.

::lesson-steps
---
items:
  - title: "Anschluss"
    description: "Woher die Daten stammen: diese Salesforce Org, eine andere, Snowflake, S3, Redshift, eine Datenbank oder eine hochgeladene CSV. Eine Verbindung besteht aus Anmeldeinformationen plus einem erreichbaren Endpunkt, der einmal konfiguriert ist."
  - title: "Datensynchronisation"
    description: "Ein geplantes Ziehen ausgewählter Objekte und ausgewählter Felder in CRM Analytics' eigener Laden. Rezepte lesen dann diese lokale Kopie, anstatt bei jedem Lauf die Quelle zu treffen - schneller und sanfter im Aufzeichnungssystem."
  - title: "Rezeptur"
    description: "Die visuelle Transformation: Eingaben, dann Verknüpfungen, Filter, Formeln, Aggregate und einen Ausgabeknoten. Dies ist, wo Getreide entschieden wird und wo das meiste Denken passiert."
  - title: "Datensatz"
    description: "Das materialisierte, säulenförmige Ergebnis. Welche Objektive und Dashboards tatsächlich lesen. Rebuilt ganze auf jedem Lauf."

## Sync: Felder auswählen, keine Objekte

Der Instinkt ist, alles zu synchronisieren und später zu entscheiden. Widerstehen Sie ihm.

::tip{icon="i-lucide-filter"}
**Sync schmal.** Jedes zusätzliche Feld ist Zeit auf jedem Lauf und Platz im Laden, und ein Objekt synchronisiert Großhandel zieht entlang Dutzende von Feldern niemand wird jemals gruppieren. Beginnen Sie mit den Feldern, die Ihre Rezepte tatsächlich verwenden; Hinzufügen eines dauert später eine Minute, und Sie werden wissen, warum Sie es hinzugefügt haben.
::

Die einzige Ausnahme, die es wert ist, bewusst gemacht zu werden: Felder, die Sie benötigen **Geschichte** für. Da sich ein Snapshot-Datensatz nur daran erinnern kann, was zu der Zeit synchronisiert wurde, hat ein Feld, das Sie im März mit der Synchronisierung beginnen, keine Februar-Werte und wird es niemals tun. Wenn ein Feld wahrscheinlich für die Trendanalyse von Bedeutung ist, synchronisieren Sie es, bevor Sie es benötigen.

## Der Integrationsbenutzer ist der Silent Filter

Sync läuft als bestimmter Benutzer - der **Integrationsnutzer** - und es kann nur sehen, was dieser Benutzer sehen kann.

::warning{icon="i-lucide-eye-off"}
**Dieses Versagen ist unsichtbar.** Wenn der Integrationsbenutzer keinen Feldzugriff auf `Discount__c`Das Feld kommt nicht an. Das Rezept macht keinen Fehler. Der Datensatz baut sich sauber auf. Das Dashboard zeigt eine Zahl, die einfach ohne Rabatte berechnet wird, und es sieht völlig plausibel aus. Zeilen fehlen, anstatt dupliziert ist fast immer dies, oder das Sicherheitsprädikat. Abschnitt 2 deckt beide richtig ab - es ist das einzige administrative Thema mit dem höchsten Wert in diesem Kurs.
::

## Rezepte und das Wort Dataflow

A **Rezeptur** ist das aktuelle Tool: eine visuelle Pipeline, die Sie aus Knoten zusammenstellen - Input, Join, Filter, Formel, Aggregat, Transformation, Ausgabe - mit einer Vorschau bei jedem Schritt.

A **Datenfluss** ist der Vorgänger: die gleiche Idee definiert als JSON, bearbeitet in einem viel weniger verzeihenden Editor. Orgs, die vor Jahren gebaut wurden, sind voll davon und sie laufen immer noch.

      - "One malformed node fails the whole thing"

## Wo jede Stufe scheitert

::field-table
---
dataset: "failure modes by stage"
grain: "one row per stage"
fields:
  - name: "Connection"
    type: "credentials, network"
    role: "key"
    note: "Abgelaufene Anmeldeinformationen und gedrehte Schlüssel. Laut und offensichtlich - der Lauf scheitert geradezu, was dies zum freundlichsten Misserfolg in der Liste macht."
  - name: "Sync"
    type: "permissions, selection"
    role: "key"
    note: "Der Stille. Ein Feld, das der Integrationsbenutzer nicht sehen kann, kommt nie an und nichts Fehler. Zeilen fehlen, nicht dupliziert."
  - name: "Recipe"
    type: "grain, joins, nulls"
    role: "measure"
    note: "Fan-out-Verdoppelung einer Gesamtsumme; ein innerer Join, der leise Datensätze ohne Übereinstimmung fallen lässt; eine Formel, die durch eine Null geteilt wird, die nur in einem Monat erscheint."
  - name: "Dataset"
    type: "types, size"
    role: "measure"
    note: "Datumsangaben, die als Text eingegeben werden, IDs, die als Maßnahmen eingegeben werden, und Zeilenzählgrenzen für größere Organisationen."
  - name: "Schedule"
    type: "timing"
    role: "date"
    note: "Das subtile: ein Rezept, das vor der Synchronisierung geplant ist, hängt von den Enden ab. Es gelingt, mit den Daten von gestern, jede einzelne Nacht, und nichts jemals Fehler."
---
::

::note{icon="i-lucide-list-ordered"}
**Debug in Pipeline-Reihenfolge, nicht in Panik-Reihenfolge.** Monitor zuerst: lief es, wann, wie viele Zeilen? Dann die Node Previews des Rezepts, die ein Kornproblem in etwa einer Minute lokalisieren. Dann die Feldtypen des Datensatzes. Das Armaturenbrett ist das letzte, und es ist selten der Täter - es berichtet normalerweise nur treu, was es übergeben wurde.
::
