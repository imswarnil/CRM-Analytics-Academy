# Modifier les champs et les métadonnées des ensembles de données

Ouvrez un objectif sur un jeu de données nouvellement construit et il semble... rugueux. Les dimensions sont appelées `AccountId.Name` et `StageName`. Les montants correspondent à des nombres nus sans symbole de monnaie et à huit décimales. Chaque graphique de vos étapes choisit différentes couleurs que la dernière.

Tout cela est **métadonnées des ensembles de données**, et vous le fixez de l'intérieur d'un objectif — via le **Champs** Panneau.

::tip{icon="i-lucide-triangle-alert"}
Lisez attentivement ceci : le panneau Fields **pas** modifier l'objectif. Il modifie le **ensemble de données**. Chaque changement que vous enregistrez ici s'applique à cet ensemble de données **partout** — chaque objectif existant, chaque tableau de bord, chaque histoire, pour chaque utilisateur. C'est ce qui le rend puissant, et c'est aussi pourquoi vous devriez le traiter comme un acte délibéré plutôt qu'un tweak cosmétique.
::

Vous avez besoin du **Gérer l'analyse** ou **Modifier les flux de données** autorisation de faire ces modifications. Sans cela, le panneau Fields est en lecture seule.

## Ouverture du panneau Fields

À partir d'un objectif ouvert, recherchez le **Champs** option (habituellement dans le menu objectif ou à côté de la liste des champs). Il énumère chaque champ de l'ensemble de données, divisé en **Dimensions**, **Mesures**et **Dates**. Sélectionnez un champ et ses paramètres apparaissent à droite.

Quatre choses valent votre temps.

## 1. Champs par défaut pour la table des valeurs

Quand quelqu'un ouvre ce jeu de données et passe à un **Tableau des valeurs**, quelles colonnes devraient-ils voir en premier?

A gauche, vous obtenez n'importe quel ordre le jeu de données a été construit dans — souvent ID et champs système à l'avant. Dans le panneau Fields, vous pouvez définir le **champs par défaut**: choisir la poignée de colonnes qui racontent réellement l'histoire (nom du compte, étape, date de fermeture, montant, propriétaire) et régler leur commande.

C'est un petit changement avec un effet surdimensionné. Chaque collègue qui ouvre ce jeu de données commence maintenant par quelque chose de lisible au lieu d'un mur de dix-huit caractères ID.

## 2. Repositionnement des dimensions

Sélectionnez une dimension et modifiez sa **étiquette**. `AccountId.Name` devient **Nom du compte**. `StageName` devient **Étape**. `Owner.UserRole.Name` devient **Rôle des ventes**.

C'est l'effort le plus important et le plus faible de cette leçon. L'étiquette apparaît dans les sélectionneurs de champs, les axes de cartes, les légendes, les tooltips et les en-têtes de table — partout où un utilisateur d'entreprise lit. Personne ne devrait avoir à connaître votre modèle d'objet pour utiliser votre tableau de bord.

::tip{icon="i-lucide-info"}
Le réétiquetage modifie **étiquette seulement**. Les **API le nom est inchangé** — enSAQL mode que vous allez toujours écrire `'AccountId.Name'`Pas `'Account Name'`. Idem pour les reliures et les définitions des filtres. Si SAQL requête s'interrompt après un relabel, le relabel n'est pas la cause ; regardez ailleurs.
::

## 3. Édition des valeurs et attribution des couleurs

Élargir une dimension et vous pouvez voir sa **valeurs**, et contre chacun **couleur**.

Voilà comment vous obtenez **une couleur cohérente et significative sur chaque graphique de votre org**. Choisissez une couleur pour chaque étape une fois — Fermé Won vert, Fermé Lost rouge, tout entre les deux sur une rampe sensible — et à partir de là, *chaque* graphique groupé par étape, dans chaque tableau de bord, utilise ces couleurs automatiquement. Plus de re-picking couleurs par graphique, et plus "attendez, est vert gagné ou perdu sur celui-ci?"

Faites-le pour les dimensions qui apparaissent partout : étape, type, industrie, priorité, statut. Rouge/ambre/vert pour tout ce qui a un bon à mauvais ordre inhérent paie pour lui-même immédiatement.

Vous pouvez également modifier le **valeur affichée** C'est là qu'il faut être prudent.

::tip{icon="i-lucide-triangle-alert"}
**Modifier les étiquettes ici; modifier les valeurs réelles à la couche de données.** Renaming une valeur dans ce panneau ne modifie que ce qui est *affiché*. La valeur sous-jacente est intacte, donc SAQL les requêtes, les définitions des filtres, les liaisons et les exportations montrent toujours l'original. Quelqu'un qui voit "Entreprise" dans un graphique et qui écrit `filter q by 'Segment' == "Enterprise"` obtient zéro ligne si la valeur stockée est vraiment `ENT`. Si une valeur est vraiment fausse, fixez-la dans le **recette ou flux de données** avec un seau ou une transformation — ainsi la valeur stockée et la valeur affichée sont d'accord, et personne ne se confond dans six mois.
::

## 4. Mesurer les formats de nombre

Sélectionnez une mesure et vous pouvez définir comment ses chiffres rendent sur toute la plateforme :

    icon: "i-lucide-hash"
    description: "Les montants n'ont presque jamais besoin de plus de deux, et ont souvent besoin de zéro. Le tri des décimales facilite considérablement l'analyse des graphiques."
  - title: "Monnaie"

    description: "Choisissez le format de devise et collez dans le symbole dont vous avez besoin — $, €, £, -. Il apparaît alors sur les axes, les étiquettes, les tables et les tooltips."
  - title: "Format personnalisé"
    icon: "i-lucide-settings-2"
    description: "Construisez votre propre modèle pour les préfixes, les suffixes, les milliers de séparateurs ou d'unités — pourcentages, heures ou « unités K »."
---
::

L'étape de la monnaie attrape les gens: plutôt qu'une longue baisse des devises mondiales, vous choisissez généralement la monnaie ou l'option de format personnalisé et puis **coller le symbole** dans le champ format. Copiez le personnage que vous voulez, collez-le dans le préfixe, fait. Un symbole roupie ou euro se comporte exactement comme le dollar par défaut une fois qu'il est dedans.

## Sauver

Sauvez, et les changements sont en direct. Ne pas « vivre dans cette lentille » — vivre dans l'ensemble de données. Réouvrir tout tableau de bord existant construit sur lui et les étiquettes, les couleurs et les formats de devises sont déjà appliqués, sans rien reconstruire.
