# Pourquoi SAQL Existe

Chaque objectif, chaque widget et chaque requête de tableau de bord est SAQL En dessous. Le clic le génère ; vous ne l'écrivez que lorsque l'interface de clic s'épuise.

::note{icon="i-lucide-waves"}
**SAQL est une transformation de flux, pas une requête déclarative.** Chaque instruction prend le résultat de l'instruction précédente et la transforme en réassignant la même variable de flux. Il n'y a pas d'optimisation de la réorganisation de votre travail, donc **l'ordre dans lequel vous écrivez des déclarations est le plan qui fonctionne** — le filtrage après le regroupement fait vraiment des lignes agrégées que vous étiez sur le point de jeter. C'est la seule différence structurelle qui touche les personnes qui connaissent SQL Et bien.
::

## La forme

```
q = load "Academy_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Charge, étroit, groupe, calcul, commande, limite. Six déclarations, chacune réaffectant `q`, chacun consommant ce que la dernière produit.

::warning{icon="i-lucide-eye-off"}
**Quoi ? SAQL Il ne devrait PAS être utilisé pour : définir une mesure commerciale.** Une définition écrite dans la requête d'un widget est invisible pour quiconque lit l'ensemble de données, la recette ou la documentation. Il sera redécouvert des mois plus tard par quelqu'un qui travaillera sur les raisons pour lesquelles deux tableaux de bord ne sont pas d'accord — et ni l'un ni l'autre ne se tromperont. Configuration des requêtes SAQL; définir les paramètres de la recette.
::
