# Exécuter et résoudre le Dataflow

Vous avez cliqué sur Create Dataset, qui **exécute le flux de données**. Maintenant regardons-le courir, comprenons ce qu'il fait réellement, et corrigez l'erreur qui capture presque tout le monde la première fois.

## Ce que "exécuter le flux de données" fait vraiment

Quand Dataset Builder écrit au **flux de données par défaut**, ça ne se construit pas seulement *Votre* ensemble de données — il fonctionne **tout** dans ce flux de données. Dans un org qui n'est pas vide : il vient préemballé avec d'autres ensembles de données et instructions. Donc, exécuter le flux de données par défaut exécute tout cela, pas seulement l'ensemble de données d'opportunités que vous venez de concevoir.

::tip{icon="i-lucide-git-branch"}
C'est précisément pourquoi les constructeurs expérimentés finissent par créer leur **propres** flux de données. Un seul flux de données par défaut partagé signifie que chaque construction réexécute tout. À mesure que vous grandissez, vous diviserez le travail en flux de données nommés (ou recettes) afin que chacun rafraîchisse un ensemble connu de ensembles de données sur son propre emploi du temps.
::

Tête vers **Data Manager → Surveiller** et vous verrez votre flux de données par défaut fonctionner.

## L'erreur classique de première sortie

Sur un tout nouvel org — ou la première fois que vous exécutez ce — le flux de données peut **échouer avec une erreur**. Ne paniquez pas. La cause est presque toujours simple : le flux de données demande des objets qui **n'a pas encore été tiré dans le calque de synchronisation**.

Souvenez-vous de la chaîne : le flux de données se lit depuis **Connexion/Sync**, pas de Salesforce directement. Si Connect n'a pas rempli Account, Opportunity et User, le flux de données n'a rien à lire et il s'annule.

## La correction : lancez Se connecter manuellement

::

::tip{icon="i-lucide-workflow"}
Quand tout est **programmé** correctement, c'est automatique : le flux de données demande à la couche de synchronisation « est-ce que les données sont ici ? » et, dans le cas contraire, Connect démarre et l'amène avant que le flux de données ne commence. Vous ne le faites à la main que lorsqu'un environnement n'est pas synchronisé — généralement un nouvel entraînement le premier jour.
::

## Vous avez oublié un champ ? Modifier le noeud du digest

Parce que tu ne peux pas rouvrir Dataset Builder sélectionneur de champ, édition des champs plus tard se produit dans le **les nœuds digesteurs de dataflow**.

- Ouvrez le flux de données, cliquez sur le noeud digest approprié (disons, **Compte**) et rajouter le champ **Sélectionner les champs**.
- Enregistrer, et quand vous êtes invité, choisissez de **multiplication** le champ jusqu'au nœud final du registre, sinon il s'arrête par secteur et n'atteint jamais votre ensemble de données.
- Mise à jour et **exécutez à nouveau le flux de données** donc le nouveau champ est matérialisé.

Nous couvrons les nœuds de digest, les attributs de champ, et l'édition de flux de données correctement dans le Data Manager les leçons — c'est juste assez pour vous détacher.

## Vous avez construit votre premier ensemble de données

Une fois que le flux de données se termine en vert, remonte à Analytics Studio et il est là — vos opportunités dataset, assis dans votre application privée, prêt à explorer. Sur le diagramme du paysage il vit maintenant dans le **couche de données**, construit par un flux de données qui lit depuis la synchronisation.

::tip{icon="i-lucide-check-check"}
Liste de contrôle mentale lorsqu'un flux de données échoue : **(1)** Les objets source sont-ils synchronisés ? **(2)** Connect a-t-il réellement fini avant que le flux de données ne tourne? **(3)** Est-ce que chaque champ que vous avez besoin de propager au noeud du registre? Ces trois questions répondent à neuf échecs sur dix.
::

Dataset Builder est amical, mais il vous verrouille dans les recherches et un flux de données. Ensuite nous construisons le **exactement le même ensemble de données** avec **recette** — plus de clics vers l'avant, beaucoup plus de contrôle, et la direction de la plate-forme se dirige.
