# Quelle obligation!

Faceting se produit seul entre widgets sur le même ensemble de données. A **liant** est-ce que vous filez l'état d'un widget dans la requête, le titre ou la visibilité d'un autre widget — délibérément, et à un coût.

::note{icon="i-lucide-link"}
**Le modèle mental : une liaison lit quelque chose et l'écrit quelque part.** Il lit soit ce que le spectateur *sélectionné* dans un widget, ou quelle requête *retourné*, et l'écrit dans la requête d'un autre widget, son titre, ou si elle apparaît du tout. Tout dans cette section est une combinaison de ces deux moitiés.
::

  - title: "Obligatoire pour les résultats"
    subtitle: "Reads what a query returned"
    icon: "i-lucide-database"
    pros:
      - "One widget can use another's computed value — a total, a max, a top category"
      - "Enables comparisons the click interface cannot express"
    cons:
      - "The input is invisible; debugging means tracing a query you cannot see on screen"
      - "Creates an execution order between widgets"
    verdict: "Powerful, and the first thing to suspect when a dashboard is slow."

## Le coût, déclaré clairement

::warning{icon="i-lucide-network"}
**Une liaison est une logique stockée en configuration widget.** Il ne peut pas être lu d'un coup d'œil, il ne diff, et il vit nulle part que personne ne regardera. Un tableau de bord avec vingt d'entre eux fonctionne magnifiquement pour son auteur et devient intouchable pour tous les autres: la personne suivante peut voir que changer quelque chose casse quelque chose, mais pas quoi ou pourquoi, donc ils construisent un nouveau tableau de bord à côté de lui. C'est ainsi qu'une organisation se retrouve avec quatre tableaux de bord de pipelines et un argument sur lequel elle a raison.
::

La règle qui maintient cette gérable: **si une liaison n'est pas évidente en regardant l'écran, écrivez-la** — dans la description du tableau de bord, une ligne par liaison, ce qui alimente quoi et pourquoi.
