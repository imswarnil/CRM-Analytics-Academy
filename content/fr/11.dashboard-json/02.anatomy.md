# Anatomie d'un tableau de bord

Quatre parties, et une fois que vous savez qui est qui, un fichier de tableau de bord inconnu cesse d'être intimidant.

## Les quatre parties

::field-table
---
dataset: "top-level structure"
grain: "one row per part"
fields:
  - name: "state"
    type: "the container"
    role: "key"
    note: "Enveloppe tout ci-dessous — les propres paramètres du tableau de bord plus les trois collections. Quand la documentation dit 'le tableau de bord JSON', c'est d'habitude ce que ça signifie."
  - name: "steps"
    type: "where data comes from"
    role: "key"
    note: "Interroger les définitions, chacune avec un nom. Une étape désigne son ensemble de données, ses regroupements et mesures, tous les filtres, et souvent SAQL lui-même. Widgets référence étapes par nom, c'est pourquoi les nommer correctement importe."
  - name: "widgets"
    type: "what is drawn"
    role: "dimension"
    note: "Une entrée par élément visible : type (graphique, tableau, nombre, texte, filtre), qui l'alimente, et ses paramètres d'affichage -- titre, formatage, couleurs, comportement de visage."
  - name: "layouts"
    type: "where things sit"
    role: "dimension"
    note: "Position et taille, séparément des widgets eux-mêmes. Habituellement plusieurs mises en page pour différentes largeurs d'écran, c'est pourquoi un changement qui semble droit dans le constructeur peut être mal sur un téléphone."
---
::

## Comment ils se référencent

Un widget ne contient pas sa requête ; il **désigne une étape**. Plusieurs widgets peuvent nommer la même étape, qui est exactement comment un numéro de titre, un diagramme à barres et une table peuvent partager une requête plutôt que d'émettre trois.

::tip{icon="i-lucide-merge"}
**Lire la JSON est le moyen le plus rapide pour vérifier la performance du tableau de bord.** Comptez les marches et les widgets. Douze widgets contre onze marches signifie presque rien n'est partagé et l'écran fait onze voyages ronds; douze widgets contre quatre marches est un tableau de bord que quelqu'un a pensé. Cet audit prend trente secondes dans un éditeur de texte et est maladroit à effectuer dans le constructeur du tout.
::

## Trouver votre chemin

::lesson-steps
---
items:
  - title: "Commencez par le widget que vous pouvez voir"
    description: "Trouvez son texte de titre dans le fichier, notez quelle étape il nomme, puis trouvez cette étape. Deux recherches et vous regardez la requête derrière la chose à l'écran."
  - title: "Suivez l'étape vers son ensemble de données"
    description: "L'étape désigne l'ensemble de données et soit sa structure de regroupement et de mesure, soit brute SAQL. C'est là que vous découvrez ce qu'un widget demande réellement — y compris les filtres que le constructeur a appliqués que vous n'avez pas."
  - title: "Vérifiez la dernière mise en page"
    description: "Si quelque chose est positionné bizarrement, le widget est bien et une mise en page est erronée. La recherche dans le widget d'un problème de positionnement est la façon la plus courante de gaspiller dix minutes ici."
  - title: "Rechercher les liaisons par leur syntaxe"
    description: "Les liens apparaissent en ligne comme des expressions de chaîne dans les propriétés étape ou widget. La recherche de la syntaxe liante énumère tous les éléments du tableau de bord, qui est le seul moyen de les voir tous en même temps, et beaucoup plus rapidement que l'ouverture de trente panneaux."
---
::

::note{icon="i-lucide-search"}
**Ce dernier point est la meilleure raison d'ouvrir le fichier sur un tableau de bord que vous avez hérité.** La section précédente dit que les liaisons sont invisibles dans l'interface; dans le JSON Ils sont greffables. Dix secondes de recherche vous donne la carte de dépendance qui autrement prendrait un après-midi de cliquer — et cette carte est ce que vous devriez alors écrire dans la description du tableau de bord.
::

## Les noms sont le calque lisible

Les noms d'étape se propagent partout : les widgets les référent, les reliures les référent, et ils sont ce que vous lisez en traçant n'importe quoi.

`step_7` ne vous dit rien. `closed_won_by_segment` indique à la personne suivante à quoi sert la requête avant qu'elle ne lise une ligne de celle-ci — et puisque les étapes de référence de liaison par nom, les bons noms sont la différence entre un arrangement lisible et un puzzle.
