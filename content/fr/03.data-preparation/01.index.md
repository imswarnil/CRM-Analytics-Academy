# De la source à l'ensemble des données

Tout ce qui est visible CRM Analytics est construit sur un ensemble de données, et un ensemble de données est construit par quelqu'un faisant des choix. Cette section vise à les faire délibérément.

## Quatre itinéraires

::field-table
---
dataset: "how data becomes a dataset"
grain: "one row per route"
fields:
  - name: "CSV upload"
    type: "manual, one-off"
    role: "key"
    note: "Faites glisser un fichier, vérifiez les types inférés. Parfait pour les données d'échantillon de ce cours et pour un véritable unique. Il ne se mettra jamais à jour, ce qui est une fonctionnalité lorsque le fichier est un extrait fixe et une responsabilité quand quelqu'un s'attend à ce qu'il soit à jour."
  - name: "Salesforce sync → recipe"
    type: "the normal path"
    role: "key"
    note: "Les objets et les champs sélectionnés sont synchronisés sur un horaire, puis une recette les rejoint et les forme. C'est ce qu'une organisation de production exécute, et ce que la section de préparation des données suppose."
  - name: "External connection → recipe"
    type: "warehouse, S3, database"
    role: "dimension"
    note: "Même forme, origine différente. Les sessions Web de Namilio, les dépenses et l'utilisation arrivent de cette façon dans un org réel; ici ils sont CSVs donc le cours fonctionne sans infrastructure externe."
  - name: "Recipe on existing datasets"
    type: "derived"
    role: "measure"
    note: "Une recette peut lire des ensembles de données d'autres recettes produites. Utile pour une base partagée et nettoyée sur laquelle plusieurs ensembles de données en aval s'appuient — et dangereuse si la chaîne devient longue, parce qu'un problème de calendrier trois liens retour est invisible à la fin."
---
::

## La question qui régit toute cette section

::note{icon="i-lucide-ruler"}
**Que représente exactement une ligne de la sortie ?** Vous l'avez rencontré dans la section des fondations. Ici, vous allez le construire mal sur le but, voir les revenus de Namilio double, et ensuite le corriger — parce que l'abstraction devient seulement un réflexe après que vous avez regardé il produit un chiffre plausible faux avec vos propres données.
::

## La seule habitude de passer par la section

Compter les rangées dans chaque noeud.

::tip{icon="i-lucide-hash"}
**Avant une jointure et après.** Si le nombre de rangs a augmenté, le grain a changé, et vous devez pouvoir dire pourquoi. Parfois, il devrait — l'intégration des comptes aux opportunités garde 677 lignes; l'intégration des lignes de produits aux opportunités produit légitimement 1378. L'échec n'est pas l'augmentation. L'échec, c'est la somme d'un parent. `Amount` après l'augmentation, que rien dans le produit vous avertira parce que rien dans le produit ne sait ce que vous voulez dire.
