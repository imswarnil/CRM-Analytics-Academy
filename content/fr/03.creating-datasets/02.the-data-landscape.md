# Le paysage des données : Connecter, synchroniser et placer les ensembles de données

Avant de construire quoi que ce soit, vous avez besoin d'une carte mentale de la façon dont les données passent CRM Analytics. Réalisez cette image et chaque outil de la plate-forme a soudainement un endroit évident. Vous vous tromperez et vous passerez des heures à vous demander pourquoi un jeu de données est bloqué ou une synchronisation a échoué.

## Le calque de mise en scène : Connectez et Sync

La plupart de vos données commencent dans votre **locaux Salesforce org**, et la plate-forme a une connexion native à elle. Vous apportez des objets **Connexion** (également appelé **Synchronisation**) exactement comme ils sont — Compte, Opportunité, Utilisateur — chaque atterrissage comme son propre objet synchronisé.

Pensez à ceci comme un **aire de rassemblement gratuite**. Vous ne construisez pas des ensembles de données finis ici; vous tirez des objets bruts dans une zone de rétention. Plus tard, un flux de données ou une recette *lit à partir* cette couche de mise en scène pour assembler les ensembles de données que vous utiliserez dans les tableaux de bord, les lentilles et les histoires.

La superpuissance de la couche de synchronisation est **rafraîchissement progressif** — après la première pleine charge, il tire seulement les lignes changées. C'est ce qui vous permet de programmer une synchronisation toutes les 15 minutes, toutes les heures, ou tous les jours sans frapper votre org. Nous allons au fond de cela dans le Data Manager matériel.
::

## D'où les données peuvent venir

Salesforce est la source commune, mais elle est loin d'être la seule. La couche Connect/Sync peut ingérer à partir de :

- **Votre local Salesforce org** — natif, le chemin le plus commun.
- **Autres Salesforce nuages ou orgues connectés** — d'extraire des données entre les environnements.
- **Sources externes comme le flocon de neige** — y compris **Connecteur en direct** qui lit au moment de la requête.
- **CSV fichiers** — un simple téléchargement manuel, ce que nous ferons dans la prochaine leçon.
- **Votre propre ETL outil ou API** — toute ETL qui a un connecteur à CRM Analytics peut pousser les données dans, ou vous pouvez appeler l'ingestion API directement (documenté sous le lien Aide).

## Les données peuvent circuler *dehors*, aussi

Récemment, la plate-forme a étendu ses **connecteurs de sortie**. Une fois que vous avez construit un ensemble de données — apportez-le de Salesforce, combiné, enrichi — vous pouvez le repousser **Flocon de neige**, **Amazone S3**ou une **Tableau** fichier hyper pour y construire des tableaux de bord. L'analytique n'est plus une rue à sens unique.

## Une caractéristique à connaître : Données du rapport de tendance

Si vous avez CRM Analytics Plus licence plus la **Trend Report Data in Analytics** chaque rapport opérationnel obtient un petit **"Tendance de l'analytique"** bouton. Cliquez dessus et vous pouvez programmer ce rapport — quotidien, hebdomadaire ou mensuel — pour stocker ses résultats directement dans un ensemble de données.

C'est pratique si tu es lourd. Salesforce signaler l'utilisateur qui veut juste des instantanés historiques de nombres, d'activités ou de cas. Soyez conscient que c'est **limitée**: il va directement à un ensemble de données avec peu de contrôle sur la transformation. En pratique, vous allez plus souvent photographier les données à travers une application ou une recette.

Le point de vue clé qui attire les gens vers le haut: ces **ordre**. Sync rafraîchit d'abord les objets de base, *puis* un flux de données ou une recette passe pour mettre à jour les ensembles de données finis. Si votre tableau de bord affiche des nombres inexistants, le coupable est presque toujours hors de l'ordre dans cette chaîne — une synchronisation qui n'a pas fonctionné, ou une recette prévue avant que sa source ne soit terminée.

Tout au long de cette section, vous m'entendez distinguer **ensembles de données de référence** (les blocs de construction bruts) **ensembles de données finals** (ce que les tableaux de bord consomment). Maintenez cette distinction — c'est la différence entre une application analytique durable et un enchevêtrement que personne ne peut déboguer. Ensuite, la façon la plus simple de faire un ensemble de données: a **CSV Téléchargement**.
