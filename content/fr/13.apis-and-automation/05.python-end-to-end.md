## Le squelette

```python
import os, csv, json, math, requests

BASE   = os.environ["SF_INSTANCE_URL"]        # from the secret store
TOKEN  = get_access_token()                    # refreshable
HEAD   = {"Authorization": f"Bearer {TOKEN}"}
CHUNK  = 10_000                                # rows per part

def declare(dataset, operation, metadata):
    """Create the upload job. Nothing is sent yet."""
    body = {"Format": "Csv", "EdgemartAlias": dataset,
            "Operation": operation, "Action": "None",
            "MetadataJson": metadata}
    r = requests.post(f"{BASE}/services/data/v62.0/sobjects/InsightsExternalData",
                      headers=HEAD, json=body, timeout=60)
    r.raise_for_status()
    return r.json()["id"]

def upload_parts(job_id, rows, header):
    """Send the rows as numbered parts. Part numbers start at 1."""
    for i in range(0, len(rows), CHUNK):
        part = i // CHUNK + 1
        payload = encode_csv(header, rows[i:i + CHUNK])
        post_part(job_id, part, payload)

def complete(job_id):
    """The step that is forgotten. Until this runs, nothing is processed."""
    requests.patch(f"{BASE}/services/data/v62.0/sobjects/InsightsExternalData/{job_id}",
                   headers=HEAD, json={"Action": "Process"}, timeout=60).raise_for_status()
```

::note{icon="i-lucide-code"}
**Les chemins des paramètres et le schéma exact des métadonnées changent entre les versions** — vérifier la documentation actuelle pour votre API version plutôt que de copier un chemin depuis n'importe quel blog, y compris celui-ci. Ce qui ne change pas est la séquence: déclarer, pièces, compléter, vérifier. Apprenez la forme et regardez les détails.
::

## La vérification est la partie qui gagne sa conservation

```python
expected = len(rows)
actual   = dataset_row_count(dataset)          # read back from metadata
if actual != expected:
    raise SystemExit(f"load mismatch: sent {expected}, dataset holds {actual}")
```

::tip{icon="i-lucide-shield-check"}
**Échec fort sur une erreur plutôt que d'enregistrer un avertissement.** Un travail qui sort de zéro après avoir chargé 80% des lignes produit un tableau de bord qui est discrètement mal pour autant qu'il faut quelqu'un à remarquer — qui, sur un nombre personne n'a un précédent pour, peut être des mois. Un code de sortie est lu par le planificateur; un avertissement dans un journal est lu par personne.
::

## Répondez au résultat

La même session peut fonctionner SAQL, ce qui rend une étape de rapprochement naturelle à la fin d'une charge: tirer le total de l'ensemble de données rapporte maintenant et le comparer à la figure propre du système source. C'est l'habitude de la clé de réponse de la section API automatisée — et c'est la chose la plus précieuse qu'un chargeur puisse faire au-delà du chargement.

## Je m'en occupe

Quoi qu'il en soit — cron, un calendrier d'IC, un orchestre — a besoin de trois choses: le calendrier, les références d'un magasin secret, et quelque part l'échec est *vu*. Un travail qui échoue dans un répertoire de journaux que personne n'ouvre est un travail qui ne fonctionne pas, et vous découvrez des semaines plus tard.
