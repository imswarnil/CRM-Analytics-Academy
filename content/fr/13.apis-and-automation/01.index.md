## Ce que cette section couvrira

Tout dans CRM Analytics est accessible sur une API — ce que cela permet, les quatre emplois qui méritent d'être automatisés et ceux qui doivent rester manuels.

## Enseignements prévus

- **Pourquoi automatiser** — Tout dans CRM Analytics est accessible sur une API — ce que cela permet, les quatre emplois qui méritent d'être automatisés et ceux qui doivent rester manuels.
- **Les REST API** — Authentification, les familles de paramètres qui comptent pour l'analyse, la version et les limites qui méritent d'être conçues avant d'écrire quoi que ce soit.
- **SAQL du code** — Envoi d'une requête API et de lire ce qui revient — plus les quatre raisons légitimes un nombre d'un script diffère du même nombre sur le tableau de bord.
- **Chargement des données** — Les données externes API: déclarer, télécharger en parties, compléter le signal — le modèle en trois étapes, le fichier de métadonnées qui décide de vos types de champs, et l'échec tout le monde frappe une fois.
- **Python fin à fin** — Un chemin travaillé en Python: authentifier, déclarer une charge, pousser les données de l'Académie dans les parties, compléter le signal, vérifier le nombre de lignes, et demander le résultat.
- **Automatisation & déploiement** — Calendrier, identificateurs, traitement des défaillances et utilisation de l'exportation de métadonnées pour donner aux tableaux de bord l'historique de changement que le produit ne fournit pas.
- **Questions d'entretien** — Les API et les questions d'automatisation, avec des réponses modèles — et le jugement opérationnel qu'ils recherchent vraiment.
- **Quiz classé** — Huit questions sur l'authentification, la requête et les API de données externes, les opérations de chargement, la programmation et l'historique des changements.
