# Courir SAQL du code

Vous envoyez une requête, vous récupérez les lignes. Les mécaniciens prennent un après-midi, les écarts prennent plus de temps.

## Lire la réponse

Les résultats reviennent comme JSON: un ensemble d'enregistrements, chacun une carte des noms de colonnes aux valeurs. Deux choses à gérer plutôt que de supposer :

- **Les noms de colonnes proviennent de la requête `generate` alias**, donc renommer un alias renomme une clé dans la réponse et casse tout ce qui la consomme. Épinglez les noms délibérément et gardez-les stables.
- **Les types sont ce que l'ensemble de données dit qu'ils sont.** Les dates arrivent dans la représentation de l'ensemble de données plutôt que comme objet de date de votre langue, et les chiffres peuvent arriver en tant que chaînes de caractères selon le client. Parse explicitement au lieu de faire confiance à la forme.

::tip{icon="i-lucide-copy"}
**Commencez à partir de la propre requête du tableau de bord plutôt que d'écrire une à partir de zéro.** Copier SAQL hors de l'étape, puis ajouter les filtres que la sélection a appliqué. Réconcilier deux requêtes écrites de façon indépendante est un problème beaucoup plus difficile que d'en adapter une, et la plupart du temps la divergence s'avère être un filtre dont personne ne s'est souvenu.
::

## Déterminisme pour la réconciliation

::warning{icon="i-lucide-calendar-clock"}
**Un travail de rapprochement doit épingler ses dates.** La comparaison d'une fenêtre roulante avec un système source produit une différence chaque fois que l'horloge bouge, et vous passerez un après-midi à étudier une divergence qui est entièrement un artefact de quand les deux requêtes ont couru. Début et fin absolus, calculés une fois en haut du travail et utilisés pour les deux côtés.
::

## Conserver la requête dans le dépôt

Une requête qui fonctionne sur un calendrier est un code. Gardez-le dans le dépôt avec le travail, non collé dans la boîte de texte d'un planificateur où il ne peut pas être examiné, diffusé ou expliqué — et où personne ne le trouvera lorsque le nombre qu'il produit est remis en question.
