# SAQL Cuando los clics se ejecutan

SAQL no SQL con diferentes palabras clave. Es una **lenguaje de transformación**: cada declaración toma el resultado de la declaración anterior y lo transforma. Eso hace que *orden* del plan de consulta, que es la única diferencia estructural que capta SQL gente.

## La forma de una consulta

Lea una generada y el patrón es inmediatamente visible:

```
q = load "Namilio_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Seis declaraciones, cada una de ellas `q`. Carga, estrecha, grupo, computación, orden, límite.

::note{icon="i-lucide-arrow-down"}
**El orden importa de una manera que no en SQL.** A SQL el motor reordena su consulta para usted. Aquí usted está describiendo un oleoducto literalmente: filtrar después de agrupar significa agrupar filas que iba a descartar. Filtrar temprano, siempre — es más rápido y más cerca de lo que querías decir.
::

## Tres patrones vale la pena memorizar

### 1. Conteo distintivo

En un grano fino, contar filas cuenta lo equivocado:

```
q = foreach q generate 'Segment' as 'Segment',
      unique('OpportunityId') as 'Deals',
      sum('LineAmount') as 'Revenue';
```

El grano line-item de Namilio hace esto esencial: 1.378 hileras, 677 tratos.

### 2. Porcentaje del total

Cada grupo comparó con el todo — awkward haciendo clic, directo aquí. Group by `all` para conseguir el total, luego comparar cada grupo contra él. Este es el patrón detrás de cada widget "porcentaje de ingresos", y es la razón más común para abrir SAQL Para nada.

### 3. Comparación de períodos

Dos flujos filtrados, cada agregado, luego se unieron a la agrupación — este trimestre junto al último trimestre, con el delta computed entre ellos. La construcción de velocidad de la sección 9 utiliza exactamente esta forma.

::tip{icon="i-lucide-lightbulb"}
**No memorice la sintaxis que puede generar.** Construir lo más cercano que puedas haciendo clic, cambiar a SAQL, y editar desde allí. Usted obtiene referencias correctas de campo, cita correcta y un esqueleto de trabajo de forma gratuita - y la cita es donde escrito a mano SAQL generalmente va mal: citas individuales para nombres de campo, citas dobles para valores de cadena, exactamente como en un predicado de seguridad.
::

## Cuando llegar a ella, y cuando no

      - "A company-wide metric computed once agrees everywhere"
    cons:
      - "A definition written into a widget query is invisible to everyone else"
      - "Two dashboards with the same metric in SAQL will drift, and neither will be wrong"
    verdict: "If ten dashboards need it, it belongs in the recipe."
---
::

::warning{icon="i-lucide-eye-off"}
**La trampa de mantenimiento.** Una métrica definida en manuscritos manuales SAQL dentro de un widget es invisible para cualquiera que mire el conjunto de datos, la receta o la documentación. Será redescubierto, meses después, por alguien que trate de averiguar por qué dos dashboards discrepan. Uso SAQL para configurar una consulta; utilice la receta para definir una métrica.
::
