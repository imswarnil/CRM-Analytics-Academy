# ¿Por qué? SAQL Existidos

Cada lente, cada widget y cada consulta de tablero es SAQL debajo. Hacer clic lo genera; sólo lo escribe cuando la interfaz de clic se agota.

::note{icon="i-lucide-waves"}
**SAQL es una transformación de corriente, no una consulta declarativa.** Cada declaración toma el resultado de la declaración anterior y lo transforma, reasignando la misma variable de flujo. No hay optimista reordenando su trabajo, así que **el orden en que usted escribe declaraciones en es el plan que ejecuta** — filtrar después de agrupar realmente hace filas agregadas que estaba a punto de descartar. Esta es la única diferencia estructural que atrapa a las personas que saben SQL Bueno.
::

## La forma

```
q = load "Namilio_Opportunities";
q = filter q by 'StageName' == "Closed Won";
q = group q by 'Segment';
q = foreach q generate 'Segment' as 'Segment', sum('Amount') as 'Revenue';
q = order q by 'Revenue' desc;
q = limit q 10;
```

Carga, estrecha, grupo, computación, orden, límite. Seis declaraciones, cada una de ellas `q`, cada uno consumiendo lo último producido.

::warning{icon="i-lucide-eye-off"}
**¿Qué? SAQL NO debe utilizarse para: definir una métrica de negocio.** Una definición escrita en la consulta de un widget es invisible para cualquiera que lea el conjunto de datos, la receta o la documentación. Será redescubierto meses más tarde por alguien que se encargará de por qué dos dashboards discrepan — y tampoco se equivocarán. Consultas de formas en SAQL; definir métricas en la receta.
::
