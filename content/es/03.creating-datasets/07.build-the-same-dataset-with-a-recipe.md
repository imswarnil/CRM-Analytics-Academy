# Construir el mismo Dataset con una receta

Vamos a construir el **exactamente igual** dataset de oportunidades — Oportunidad + Cuenta + Usuario — pero con **receta** esta vez. Las recetas son el motor moderno de preparación de datos: arrastrar y soltar, visual y mucho más flexible que un flujo de datos. La compensación es que *Tú* posee las relaciones. Dataset Builder Descubrió el siguiente objeto y las teclas de unión para usted; en una receta usted decide qué se une a qué, y cómo.

## Iniciar una nueva receta

Desde Analytics Studio, **Crear → Dataset** y recoger de sus conjuntos de datos o objetos de sincronización — esto abre un **receta** en el Data Manager (Data Flows & Recetas → **Recetas** → nueva receta).

En la receta, **Seleccionar datos** muestra todo lo disponible para usted: conjuntos de datos que ha creado, fuentes externas, y los objetos conectados / sincronizados de Salesforce. Coge los mismos tres: **Oportunidad**, **Cuenta**, **Usuario**.

::tip{icon="i-lucide-list-checks"}
Primera diferencia real Dataset Builder: **Seleccione todos** campos por objeto en lugar de hacer clic en uno por uno — un enorme ahorro de tiempo en objetos anchos. Pero no lo hagas. Si un objeto tiene 150+ campos no necesita todos ellos; un conjunto de datos demasiado amplio es miserable para desplazarse y más lento para la consulta. Trae sólo lo que el tablero necesita.
::

Haga clic **Siguiente** y aterrizas en el lienzo de recetas, tus tres objetos sentados allí, **no conectado**. Esa es la diferencia principal: en una receta, conectarlos es tu trabajo.

## Únete a los objetos

Las reglas de grava siguen vigentes: **La oportunidad es el nivel más bajo**Así que todo se une a ella.

::lesson-steps

    description: "Arrastre desde el nodo de oportunidad más hacia la cuenta. Se convierte en un nodo Join. La receta correctamente recoge ID de cuenta = ID de cuenta — verifique, luego aplique."
  - title: "Únase a Usuario Oportunidad — ver la clave"
    description: "Añadir Usuario a Oportunidad (no a Cuenta – el propietario pertenece a la oportunidad). Aquí la receta adivina mal: coincide con el ID de oportunidad al ID de usuario. Usted desea ID de propietario → ID de usuario. Arregla la llave a mano."
  - title: "Aplicar cada paso"
    description: "Las recetas no guardan a medida que va por la forma que puede esperar — haga clic en Aplicar en la parte inferior para comprometer cada nodo antes de seguir adelante."
---
::

::tip{icon="i-lucide-triangle-alert"}
Este es el impuesto de recetas, y vale la pena internalizar: **auto-pica una tecla de unión, y puede elegir el equivocado.** Para el propietario necesita `OwnerId → User.Id`, no `Opportunity.Id → User.Id`. Tienes que *conocer sus objetos* lo suficiente para atraparlo. Dataset Builder nunca te habría permitido cometer este error — esa es la seguridad que te cambias por control.
::

## Controla tus columnas

Las recetas le dan control real sobre las columnas de salida:

- **Unirse a tipo** — expandir el nodo de la unión para elegir un **Lookup** vs una unión completa. (Cubrimos por qué eso importa en la lección de grano; mantén esto como lookups aquí.)
- **Prefijos** — los campos de Cuenta vienen como `Account.Name`, `Account.Industry`Y así. Puedes renombrar estos prefijos para que las columnas finales lean la forma que quieres.
- **Mantenga o suelte** — previsualizar las columnas entrantes y **escondido** los que no necesitas para que nunca lleguen a la salida. Trim `User.` campos hasta el nombre del propietario y la foto, por ejemplo.

## Añadir el nodo de salida

Aquí está el paso que la gente olvida: **nada existe como un conjunto de datos utilizable hasta que agregue un nodo de salida (inscripción).** Las uniones solo no producen nada que puedas poner en un tablero.

::lesson-steps
---
items:
  - title: "Añadir el nodo de salida"
    description: "Haga clic en el plus después de su última unión y agregue un nodo de salida. Esto es lo que realmente materializa el conjunto de datos."
  - title: "Dilo deliberadamente"
    description: "Dale una etiqueta clara (por ejemplo, 'Opp Owner Acc - de la receta'). Las etiquetas pueden tener espacios; API El nombre no puede. Use una limpieza API nombre que puedes pegar en las ligaduras más tarde."
  - title: "Aplicar, luego Guardar y Correr"
    description: "Aplica el nodo de salida, luego Guardar y ejecutar la receta. Se ejecuta y construye su conjunto de datos."
---
::

## Mismo resultado, motor diferente

Cuando termina, usted tiene el mismo conjunto de datos de oportunidades — construido por un **receta** lectura de los mismos objetos sincronizados, en lugar de por un flujo de datos. Dos motores, un resultado.
