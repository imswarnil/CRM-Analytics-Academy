# Correr y resolver problemas Dataflow

Ha hecho clic en Crear Dataset, que **ejecuta el flujo de datos**. Ahora vamos a ver cómo funciona, entender lo que realmente está haciendo, y corregir el error que atrapa a casi todos la primera vez.

## Lo que "corre el flujo de datos" realmente hace

Cuando Dataset Builder escribe a los **Desglose de datos por defecto**, no sólo construye *tu* dataset — se ejecuta **todo** en ese flujo de datos. En una org de entrenamiento que no está vacía: viene pre-empaquetado con otros conjuntos de datos e instrucciones. Así que ejecutar el flujo de datos predeterminado ejecuta todo, no sólo el conjunto de datos de oportunidades que acaba de diseñar.

::tip{icon="i-lucide-git-branch"}
Esto es exactamente por qué los constructores experimentados eventualmente crear sus **propia** flujos de datos. Un único flujo de datos por defecto compartido significa que cada compilación re-establece todo. A medida que crezca, dividirá el trabajo en flujos de datos llamados (o recetas) para que cada uno refresque un conjunto conocido de conjuntos de datos en su propio horario.
::

Head to **Data Manager → Monitor** y verá su flujo de datos predeterminado funcionando.

## El clásico error de primera ejecución

En una nueva org —o la primera vez que se ejecuta esto— el flujo de datos puede **fallar con un error**. No entres en pánico. La causa es casi siempre simple: el flujo de datos está pidiendo objetos que **no han sido arrastrados a la capa de sincronización todavía**.

Recuerde la cadena: el flujo de datos lee desde **Connect/Sync**, no de Salesforce directamente. Si Connect no ha poblado Cuenta, oportunidad y usuario, el flujo de datos no tiene nada que leer y se equivoca.

## La solución: ejecutar Connect manualmente

::lesson-steps
---
items:
  - title: "Vaya a Conectarse"
    description: "In Data Manager, cambiar a la pestaña Connect donde viven tus objetos sincronizados."
  - title: "Corre todo una vez."
    description: "Abra el desplegable y ejecute manualmente la sincronización. Esto saca los datos de Salesforce en la capa de puesta en escena — la capa púrpura en el diagrama del paisaje."
  - title: "Deje que el flujo de datos vuelva a funcionar"
    description: "Con los objetos ahora sincronizados, ejecute el flujo de datos predeterminado de nuevo. Lee los datos recién establecidos y construye su conjunto de datos con éxito."
---
::

::tip{icon="i-lucide-workflow"}
Cuando todo es **programa programado** correctamente, esto es automático: el flujo de datos pide a la capa de sincronización "es los datos aquí?" y, si no, Connect comienza y lo lleva antes de que el flujo de datos proceda. Sólo haces esto a mano cuando un ambiente está fuera de sincronización, típicamente una org de entrenamiento fresco en el primer día.
::

## ¿Olvidó un campo? Editar el nodo digestivo

Porque no puedes reabrir Dataset Builder campo picker, campos de edición más tarde sucede en el **nodos digestivos del flujo de datos**.

- Abra el flujo de datos, haga clic en el nodo digestivo pertinente (por ejemplo, **Cuenta**), y re-add el campo a través de **Seleccionar campos**.
- Guardar, y cuando se le solicite, elegir **propagar** el campo hasta el nodo final del registro - de lo contrario se detiene en parte y nunca llega a su conjunto de datos.
- Actualización y **ejecutar el flujo de datos de nuevo** así se materializa el nuevo campo.

Cubrimos los nodos digestivos, los atributos de campo y la edición de flujo de datos correctamente en el Data Manager lecciones — esto es suficiente para deshacerse de ti.

## Has construido tu primer conjunto de datos

Una vez que el flujo de datos termine verde, retroceda Analytics Studio y ahí está: su conjunto de datos de oportunidades, sentado en su aplicación privada, listo para explorar. En el diagrama del paisaje ahora vive en el **capa de dataset**, construido por un flujo de datos que lee de sincronización.

::tip{icon="i-lucide-check-check"}
Lista de comprobación mental cuando un flujo de datos falla: **1)** ¿Los objetos fuente son sincronizados? **2)** ¿Conectó realmente terminar antes de que el flujo de datos funcionara? **3)** ¿Cada campo necesita propagarse al nodo de registro? Esas tres preguntas responden a nueve de cada diez fallos de primera ejecución.
::

Dataset Builder es amistoso, pero lo bloquea en las búsquedas y un flujo de datos. Siguiente construimos el **exactamente el mismo dataset** con una **receta** — más clics en el frente, mucho más control, y la dirección que la plataforma se dirige.
